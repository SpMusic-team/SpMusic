# 播放列表封面完整加载与有界资源方案

## 摘要与状态

当前实现将能够申请和显示封面的歌曲集合硬截断为 40 首。大窗口的小封面网格可以同时展示更多歌曲，因此部分真实可见卡片没有加载资格；单纯扩大历史缓存不能消除这一设计冲突。

建议把真实可见集合、屏外预取、转场暂存和资源驻留分开管理：保证支持窗口尺寸与 DPR 范围内的可见项能够获得封面，使用字节预算、缩略图尺寸和有限并发约束资源成本。预算紧张时先减少屏外工作，再调整缩略图画质，避免通过固定张数任意隐藏屏内封面。

本文是基于 2026-09-28 源码只读调查形成的草案。**方案尚未实施，未运行时复现或测量，也未执行功能、性能或发布验收。** 用户截图与代码限制高度吻合，但不能据此认定每一张缺失封面的歌曲都具有有效图片。本文不改变需求、任务、版本或缺陷记录的批准状态。

## 范围与质量目标

覆盖播放列表网格的封面资格、可见区域调度、缩略图请求、前后端取消边界、资源释放、失败恢复及验证方式。首曲大图与播放栏是同一资源供应链的独立使用者，需要计入预算。

不包含在线封面搜索、音频标签写回、播放状态机重构、播放器拖动转场重写、媒体库数据库或新增网络服务。磁盘缩略图缓存和网格虚拟化仅列为后续备选，不作为此次修复前提。

| 质量属性 | 约束 |
| --- | --- |
| 完整性 | 稳定视口内具有有效封面的歌曲最终全部显示，不因超过 40 首永久停在占位状态。 |
| 内存 | 驻留资源、在途像素、转场保留和待释放资源均有预算，不随浏览歌曲数无限累积。 |
| 交互 | 小幅滚动、窗口缩放、DPR 和布局变化能更新优先级；正在播放的封面请求不被列表请求作废。 |
| 启动与吞吐 | 只处理当前需求与有限预取；不在列表打开时扫描并解码整份歌单。 |
| 可维护性 | 组件报告几何需求，资源层决定调度与释放，Rust 负责受限本地读取、解码和缩放。 |
| 权限 | 继续限制到应用封面缓存目录；不扩大任意文件、网络或桌面权限。 |
| 跨平台 | 逻辑不依赖 WebView2 专属回收机制；内存结果分别在目标平台实际测量。 |

### 40 项资格与缓存大小的区别

这里的 40 首首先是一道申请与渲染资格限制，间接约束资源数量。它不是“缓存最多存 40 张，未命中仍可正常读取”的独立缓存策略。仅扩大磁盘缓存、元数据缓存或播放器大封面缓存，都不会让集合外卡片进入图片分支；仅修改一处 40 上限也会留下另一处截断。

当前首曲和播放栏会额外进入目标集合，因此也不能把 40 直接当作全部封面资源数量。未来应由一个资源管理者统一预算，组件不再各自硬编码同一人数限制。

## 推断与尚未验证的假设

1. 用户截图中真实封面约为三段 `14 + 14 + 12 = 40`，与硬限制高度吻合。这是支持主因的现象，不是运行时请求计数。
2. 卡片在上下各一屏的扩展观察区域内部移动时，可能跨过真实视口边缘而没有触发新的观察阈值通知，使排序暂时停留在旧位置。该机制可以解释顶部占位等分布，但截图不足以确定具体发生时序。
3. 整个窗口代次频繁变化可能重复作废仍需要的解码，增加快速滚动后的恢复时间；影响程度需观测任务计数和耗时。
4. 个别占位仍可能来自音频无嵌入封面、缓存文件不可用、图片损坏或大小保护拒绝，必须与调度遗漏分别统计。
5. 当前尚无此次问题对应的 Release 内存、DPR、缩略图清晰度及加载延迟基线，不能先承诺某个固定预算或档位组合足够覆盖所有窗口。

## 建议模块边界

| 模块 | 建议职责 | 不承担的职责 |
| --- | --- | --- |
| 列表组件 | 报告真实可见卡片、屏外候选、实际封面尺寸、DPR、布局和转场使用关系。 | 不决定全局资源上限，不重复裁剪可见歌曲，不直接控制 Rust 解码并发。 |
| 前端列表封面资源层 | 区分资源与使用者，选择尺寸，排序和合并请求，管理预算、有限重试、Object URL 引用与释放。初期可在现有模块边界内提取局部逻辑，无需引入通用缓存框架。 | 不访问任意本地文件，不修改播放器转场状态机。 |
| Tauri 服务适配层 | 验证输入输出，保持 TS 与 Rust 档位及错误语义一致，传输二进制像素。 | 不把卡片坐标或 DOM 生命周期传入 Rust。 |
| Rust 列表封面服务 | 校验应用缓存目录路径、源文件和解码限额，有限并发读取与缩放，拒绝失效会话。 | 不决定哪些卡片可见，不与播放器前景封面共用 latest-wins 请求身份。 |
| 播放器资源与转场层 | 继续独立管理播放器大封面、背景和会话图层。 | 不因列表预算不足被提前清空，不接受列表迟到回调修改会话。 |

依赖方向保持为“列表需求 → 前端资源调度 → Tauri 服务适配 → Rust 受限封面读取”，像素结果反向返回资源层，由资源层向仍有效的使用者发布。

## 加载与驻留策略

### 1. 完整真实可见集合

真实视口集合不能先被固定 40 首裁剪。可采用真实视口与预取区域分别观察，或者由滚动、窗口尺寸、布局及 DPR 变化触发一次合并到动画帧的几何计算。两种方案都必须验证“小幅滚动没有跨过预取边界”时仍正确更新。

实现时应使用实际可滚动内容区域，避免把被固定播放栏完全遮挡的卡片错误算成最高优先级。使用现有布局信息或观测到的几何边界，不以截图分辨率推断 CSS 像素或 DPR。

更新顺序为：当前屏内缺失封面与实际显示的首曲/播放栏需求，仍被有效转场引用的资源，近距离屏外预取。转场资源已有引用必须安全保留；尚未开始的屏外加载不能压过可见项。

### 2. 字节预算与尺寸选择

预算至少区分驻留图片、在途像素与短时换图/转场余量。资源账本记录编码字节、`width × height × 4` 的解码像素估计、在途响应和引用状态；估计用于控制应用管理的资源，不能冒充精确的 Renderer / GPU 总内存。

按封面实际 CSS 边长乘以 DPR 选择有限尺寸档位；小卡片不默认占用与大封面相同的像素。第一轮测量应覆盖最密布局、大窗口和高 DPR，随后确定支持档位、画质下限、预算和临时换图余量。新增小档位需要同步 TS 与 Rust 白名单；本文不预先批准具体数值。

正方形像素量与边长平方成正比。例如 `160 × 128² = 40 × 256²`，说明降低单张尺寸可以在相同像素量下容纳更多封面。它不代表 128px 在所有屏幕都清晰，也不代表两种场景的整体 WebView 内存相同：对象数量、BMP 编码、原图解码、纹理和回收时机仍有差异。

预算紧张时依次取消未执行预取、释放无使用者屏外资源、停止升档，再将适合降档的可见缩略图降至已验证档位。替换图片应在新资源可显示后交接引用，并把短时双份资源计入预算。支持的窗口与 DPR 组合下，所有可见项的最低画质资源必须能放入预算；若测量不满足，应调整预算、最低档位或明确支持边界，不能悄悄恢复随机隐藏屏内项的策略。

### 3. 在途复用与失效边界

把频繁变化的需求排序与封面会话失效分开。滚动仅更新等待队列的差集和优先级；同一资源仍被需要时继续等待原有任务，不因其他卡片进入窗口就整体取消。

前端以内容标识、目标档位和变换版本标识资源；以播放列表 epoch、歌曲 ID 和源身份标识使用者。请求完成时分别检查资源身份和使用者仍有效：结果可服务现有使用者，但旧列表结果不能写入新列表的歌曲视图。普通视口移动只撤销对应使用者，列表替换、源变更或完整资源会话结束才使相关会话失效。

保持有限队列和有限执行数，不把“保留在途工作”变成任意数量后台工作。当前前端 2 个视觉任务、Rust 列表串行解码可作为初始对照；是否调整由测量决定，不先扩大并发。已经开始且无法中止的 Rust 解码可以完成，但无人使用的结果应丢弃并释放，不触发后续 BMP 和图片分配。

### 4. 生命周期与失败状态

资源状态建议区分未请求、排队、加载中、就绪、确认无封面、暂时失败、永久失败和已失效。临时占位仍可用于等待；已确认无封面使用既有后备视觉，不能被计为加载遗漏。

| 情况 | 建议处理 |
| --- | --- |
| 元数据确认无封面 | 按源身份记录无封面结果，源更新后失效，不反复解码。 |
| `STALE_REQUEST` 或使用者已取消 | 正常取消，不展示为文件错误；只有当前仍有需求时重新安排。 |
| 暂时读取或工作线程失败 | 按当前需求有限次退避重试；上限与时间参数由验证确定。窗口没有变化也能重试。 |
| 非法路径、损坏图片、超出安全限额 | 记录具体失败类别，避免无限重试；只有源身份变化或明确重新加载才重新评估。 |
| 分配失败或资源压力 | 暂停预取/升档并降低负载，避免立即重试放大压力。 |
| 图片元素加载失败 | 回传资源层，区分已释放 URL、解码失败与过期使用者，不只隐藏图片后遗忘。 |

现有 `recoverable` 字段不能单独决定是否立即自动重试；需要结合稳定错误码与当前源状态。日志默认不记录完整本地音乐路径。

Object URL 只由资源层创建和撤销。可见卡片、播放栏、首曲大图以及有效转场分别持有引用；全部使用者释放后才进入可淘汰状态。换图、卸载、列表关闭和迟到完成均必须有对应释放路径。不得撤销仍被其他卡片或转场使用的共享 URL。

## 数据与命令契约

### 当前已存在的契约

列表使用 `audio_begin_playlist_cover_window({ clientId })` 分配窗口代次，随后通过 `audio_load_playlist_cover_pixels({ clientId, filePath, maxEdge, windowGeneration })` 请求像素。前景播放器使用独立的 `audio_load_cover_pixels` 与 `requestId`。列表当前 `maxEdge` 是 `256 | 512`，响应包含尺寸、stride、flags、源尺寸和 RGBA 像素。

前端 `onVisibleTrackIdsChange(trackIds, keepPersistentArtwork?, showArtwork?)` 只传有序 ID，无法完整表达真实可见、屏外预取、尺寸和转场引用差别。

### 建议新增的前端内部契约

下表是拟议字段与语义，不是已经存在的 API；最终命名可由实现 Agent 在不改变语义的前提下统一。

| 数据 | 建议内容与不变量 |
| --- | --- |
| 视口需求 | `playlistEpoch`、`demandRevision`、真实可见需求列表、预取候选列表；每项携带 `trackId`、实际 CSS 封面尺寸和 DPR。`demandRevision` 只用于排序快照，不自动取消仍需要的资源。 |
| 独立使用者 | 首曲大图、播放栏、转场引用通过独立身份声明需求或保留引用；同歌曲不同显示尺寸可以选择同一足够大的资源或不同档位。 |
| 资源键 | 封面内容身份、目标 `maxEdge`、变换版本；初期可利用已有内容哈希文件名作为会话内身份，不强制增加持久化索引。 |
| 使用者键 | 播放列表 epoch、歌曲/展示位置身份、源身份；清理回调只能释放自身引用。 |
| 资源记录 | 状态、像素尺寸、编码字节、像素字节估计、URL、引用、在途任务、错误类别和重试信息。 |

### 建议调整的跨端契约

1. TS 与 Rust 同步扩展列表缩略图档位白名单，仍只接受有限合法档位和受限文件路径。不能只给前端加入一个后端会拒绝的尺寸。
2. 第一阶段可保留现有窗口代次保护，先验证可见集和预算；实现跨窗口在途复用时，需要将“普通需求移动”和“整个列表资源会话失效”区分。
3. 推荐保留现有命令入口，协调调整 `windowGeneration` 的使用周期：视口移动不再为仍有效的资源会话不断递增，列表资源会话失效时才分配新代次；前端通过使用者身份检查阻止错写。该语义变更需要前后端一起实现并测试，不能只删除前端 stale 检查。若现有调用者需要原窗口取消语义，应明确引入单独的会话字段/入口后逐步切换，不同时混用两种解释。
4. 不必让 Rust 持有 DOM 可见集合。前端只提交有限执行任务，Rust 保留会话有效性、路径安全和解码门；离开需求的未提交任务直接移出前端队列。
5. 错误仍使用可机器判断的结构，先复用已有错误码；只有确实无法表达新边界时才新增，并同步 TS/Rust 与验证案例。

## 历史约束与回归边界

[BUG-0016](../changes/bugs/BUG-0016.md) 已记录无界图像工作、Canvas 与像素传输叠加、DOM 和 WebView2 回收高水位问题。此次必须保留有限并发、过期结果释放和内存上限，不恢复整库原图预加载，不为每张列表卡片新增常驻 GPU Canvas，也不以开发模式单次任务管理器读数证明 Release 性能。

[BUG-0017](../changes/bugs/BUG-0017.md) 是播放器转场会话与图层生命周期问题，与此次列表资格不足不同。列表优化不能重置播放器 progress、取消当前动画、提前退休仍有效会话，或让旧列表清理影响当前播放器图层。资源共享若扩展到播放器，应另做边界评审；本方案初期只在列表资源内部共享。

## 备选方案与后续演进

| 方案 | 收益与代价 | 本次取舍 |
| --- | --- | --- |
| 把 40 改为更大常量 | 修改少，在部分窗口缓解；仍可能遇到更密布局，固定 256px 资源会同步增大。 | 不作为最终方案；不能将其称为保持原预算的修复。 |
| 完整可见集、字节预算、分档缩略图 | 从需求和像素成本两端解决问题，需要联动前端与 Rust 档位。 | 推荐主线。 |
| 按内容身份共享资源 | 同一封面被多首歌曲使用时可共享缩略图与在途任务，降低重复工作；需要引用计数，源变更必须失效。 | 可与资源层演进结合，但不能代替完整可见集合。 |
| 磁盘缩略图缓存 | 避免回滚时反复解码原图；可按内容哈希、档位、变换版本索引。增加持久化容量、清理、原子写入和损坏恢复责任。 | 待重复解码耗时证据充分后另行评审；不得无上限增长。 |
| 网格虚拟化 | 当前网格全量渲染，长列表可减少 DOM 与几何扫描成本；需兼容定位、选择、布局切换和动画。 | 后续独立优化。虚拟化不能解决同屏超过 40 张的资格限制。 |

仅改为浏览器懒加载图片也不能绕过现有资格截断，更不能直接证明原图解码内存有界。若未来改传输格式，应独立比较 CPU、峰值内存和图片就绪时间。

## 建议实施顺序

这些阶段是技术依赖顺序，不是已批准的 Sprint 或任务卡。

1. **建立观测与基线**：在现有实现记录可见数、入选数、图片状态、解码和内存；确认截图相似场景与小幅滚动问题。确定支持窗口、DPR、档位和预算的测量方法。
2. **完成最小正确性闭环**：移除前后两处按人数裁剪的职责，拆分真实可见与预取；增加滚动/尺寸更新；同步缩略图档位与资源预算。不能只去掉 40 上限后以全量 256px 资源交付。可暂时保留原 generation 取消策略以缩小一次变更面。
3. **完善调度和恢复**：引入使用者引用、在途复用与会话失效分离，取消无需求排队工作，分类错误并有限重试，覆盖 Object URL 的全部释放路径。
4. **独立验证与集成**：Frontend Agent 负责列表需求和资源层，Rust/Tauri Agent 负责档位和跨端取消契约，Test Agent 独立验证；共享 TS 类型、入口和 Rust 命令只分配一个写入者，跨端语义变更顺序集成。主代理完成仓库级检查。
5. **依据证据选择后续优化**：仅当指标显示重复解码或 DOM 成为瓶颈，再分别讨论磁盘缩略图缓存或网格虚拟化。

## 验证矩阵

以下均为待执行的验证要求，不代表本次文档工作已取得测试结果。

| 场景 | 验证要点 |
| --- | --- |
| 稳定视口超过 40 张有效封面 | 最终有效封面显示率达到 100%，未请求项不会永久停留在占位；首曲和播放栏正确。 |
| 缓慢小幅滚动 | 即使没有跨过扩展预取区域边界，真实可见集合与优先级仍更新。 |
| 快速滚动、反向滚动并停下 | 最终视口完整；有效在途任务复用；过期结果不会回写，任务数量和内存有界。 |
| 窗口缩放、不同 DPR、移动显示器 | 档位变化合理，支持组合下预算容纳最低画质的完整可见集。 |
| 连续布局切换与文本视图往返 | 动画正在使用的资源不提前释放；文本视图不触发全量封面解码；返回图片视图正确恢复。 |
| 搜索、列表替换、关闭重开 | 旧 epoch 不污染新列表，未使用 URL 与任务引用释放，重新打开无长期遗漏。 |
| 同封面多曲、同曲多使用者 | 共享结果一致，一个使用者卸载不影响其他使用者；最后引用释放后才可淘汰。 |
| 无封面、坏图、路径缺失、临时失败 | 状态可区分；同窗口可有限恢复暂时失败；永久错误无无限重试。 |
| 高分辨率原图与内存压力 | 输入安全限制保留；峰值包括原图解码和在途响应，不能只统计最终缩略图。 |
| 长时间往返浏览长列表 | 驻留账本稳定；Renderer/GPU 内存形成合理平台或可解释高水位，不随浏览总数持续增长。 |
| 播放期间列表操作和高频拖动切歌 | 不回归 BUG-0016 的无界工作，不回归 BUG-0017 的旧图层重放、抽搐或白屏。 |

必要的自动化应覆盖预算决策、需求差集、引用释放、重试上限、跨 epoch 迟到结果和尺寸契约，而非仅断言实现常量。真实 WebView 中补充视口、DPR、图片清晰度、动画与内存验证。实现后由负责 Agent 运行适用的构建、lint、Rust 检查及相关测试；纯文档阶段不以这些测试替代运行时证据。

## 观测指标与参数决定方式

| 指标 | 用途 |
| --- | --- |
| 真实可见、实际申请、已就绪、确认无封面、失败数量 | 区分资格遗漏、加载等待与文件问题。显示率分母只包含应有有效封面的可见项。 |
| 可见需求到图片真正显示的延迟 | 记录中位数及尾部；按冷/热资源、DPR、布局分组，避免只量 Rust 返回时间。 |
| 排队、开始、复用、取消、过期完成与重复解码数量 | 验证优先级、在途复用和取消粒度。 |
| 编码字节、估计解码字节、在途字节、有效引用、Object URL 创建/撤销 | 验证应用资源账本与生命周期是否收敛。 |
| Rust 解码耗时、并发、输入与输出尺寸 | 判断档位、原图读取及重复解码成本。 |
| Renderer / GPU / Rust 进程内存、长任务与滚动流畅度 | 识别账本外分配和原生高水位，回归历史内存风险。 |

先在同一 Release 构建条件、同一素材集合和同一操作序列取得现状基线，再比较新方案。覆盖最大受支持视口、最密布局、高 DPR、共享封面和超大原图；根据显示清晰度及内存平台选择有限档位和预算，并为解码与替换保留余量。预算、重试次数、退避间隔与延迟目标须在实现验证阶段记录，本文不虚构已经测得的数值。

## 风险与回退条件

- **低档位模糊**：高 DPR 下需保留适当档位或调整预算。不能用未验收的模糊图片换取表面完整性。
- **预算估计偏低**：WebView 原生解码、GPU 纹理、原图峰值和回收延迟不完全进入 JS 账本，应结合进程数据修正余量。
- **共享释放错误**：若出现仍在显示的 URL 被撤销、引用不归零或跨 epoch 错图，先停止共享/复用策略，保留可见集合和受限缩略图路径，修正所有权后再启用。
- **取消语义回归**：如列表替换后旧工作污染新列表，可将前后端共同恢复为原窗口 generation 策略，并记录可能重复工作的代价；不能单边回退命令语义。
- **布局转场受损**：如图层闪现或退场图片提前消失，回退转场资源接入部分，保留历史会话隔离，按 BUG-0017 的时序检查。
- **明显内存或交互退化**：优先停预取与升档、调低并发或撤回引入退化的阶段。若只能整体回退，明确原有超过 40 张缺图问题重新存在，不能将回退状态视为修复完成。
