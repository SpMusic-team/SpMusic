# 插件系统（三十六）：lib 单值约束与下划线二次定位

## 0. 一句话结论

本篇闭合两个此前标注"未展开"的项：

| 问题 | 答案 |
| --- | --- |
| `lib` 是否可多次出现 | ❌ **不支持**。所有字段都是 `iput-object` 直接覆盖 |
| `v5==1` 分支里 `under` 二次查找的作用 | ✅ **它就是分隔位置**（`v0 = indexOf("_", v0+1)`） |

---

## 1. `lib` 只支持单个声明

### 1.1 证据：全字段直接覆盖

`router/A.y` 里 `<lib>` 相关的四处 `iput`：

| 行 | 字段 | 操作 |
| ---: | --- | --- |
| `:2667` | `х.B` | `iput-object`（name 字面量） |
| `:2751` | `х.P` | `iput-object`（lib 值） |
| `:2759` | `х.P` | `iput-object`（trim 后重写同一字段） |
| `:2867` | `х.р` | `iput-object`（libBasePath） |
| `:2875` | `х.р` | `iput-object`（trim 后重写） |

### 1.2 无计数、无列表

在 `:2600-3000` 区间检索 `lib` 与 `count`/`size`/`ArrayList` 的组合——**0 命中**。

| 观察 | 含义 |
| --- | --- |
| 全部是 `iput-object`（单值字段） | 无追加语义 |
| 无 `ArrayList` / 无计数变量 | 无集合结构 |
| 同一字段被 `iput` 两次（原值 + trim） | **明确是"覆盖式更新"** |

> **结论：`<lib>` 只能出现一次**。若 XML 里写多个，**后者静默覆盖前者**，无任何告警。

### 1.3 设计评价

| 视角 | 评价 |
| --- | --- |
| 合理性 | ✅ 大多数插件只需 1 个 `.so`，单值足够 |
| 风险 | ⚠️ 需多库的 pak（如拆分 DSP + 编解码）**无法表达** |
| 静默性 | ⚠️ 多写不报错，调试困难 |

---

## 2. ★ 下划线二次定位的真实作用

第十七篇说"`v5 == 1` 分支里 `under` 二次查找对 `v5` 无影响，疑为历史残留"。
**本轮订正：它不是残留，而是决定分隔位置。**

### 2.1 代码（`Н.h()`，`:135-158`）

```smali
// v4 = "_"
v0 = s.indexOf("_");                    // 第一次找

if (v0 == 0 && s.length() > 2) {        // ★ 仅当"_"在首位且长度>2
    v0 = s.indexOf("_", v0 + 1);        // ★ 找【第二个】下划线，结果写回 v0
}

v5 = 1;                                 // 分隔符长度 = 1
goto :goto_0

:cond_3
v5 = 3;                                 // 分隔符长度 = 3（" - "）

:goto_0
// 后续用 v0 作为切分位置
```

### 2.2 真实语义

| 输入 | `v0`（最终分隔位置） | 结果 |
| --- | ---: | --- |
| `A_B` | `1`（第一个 `_`） | name=`A`, author=`B` |
| **`_A_B`** | **`2`（第二个 `_`）** | 跳过首位的占位下划线，name=`A`, author=`B` |
| `_A` | `0`（长度 >2 不成立） | 保持 `0`，前半为空 |

> **作用是跳过"前导下划线"**——某些预设文件名以 `_` 开头（可能是排序前缀），
> 此时应把**第二个**下划线当作真实分隔符。

### 2.3 与第十七篇"去前导下划线"的关系

第十七篇记录过第五步的 `if (v2.startsWith("_")) v2 = v2.substring(1)`。
两处配合：

| 阶段 | 处理 | 场景 |
| --- | --- | --- |
| **`v0` 二次定位**（`:149`） | 跳过 `_` 找下一个 | `_A_B` → 分隔在位置 2 |
| **`v2` 去前导**（`:194`） | 去掉 `_` | `_A` 无分隔时 → author 从 `"_A"` 变 `"A"` |

> **两条互补路径**：有多个下划线时用二次定位；只有一个下划线时用去前导。

## 3. 验证

| 输入 | `v0` | 分隔符长 | name | author |
| --- | ---: | ---: | --- | --- |
| `A - B.milk` | `" - "` 位置 | 3 | `A` | `B` |
| `A_B.milk` | 1 | 1 | `A` | `B` |
| `_A_B.milk` | **2** | 1 | `A` | `B` |
| `_A.milk` | 0 | 1 | `""` | `A`（去前导后） |
| `A.milk` | -1 | — | `A` | `""` |

---

## 4. 可借鉴 / 不建议照抄

### 4.1 值得借鉴

| # | 做法 | 理由 |
| --- | --- | --- |
| A1 | **跳过前导下划线找真实分隔** | 兼容 `_` 排序前缀 |
| A2 | **`lib` 单值 + trim 重写** | 简洁，覆盖语义明确 |

### 4.2 不建议照抄

| # | 问题 | 后果 |
| --- | --- | --- |
| N1 | **多 `lib` 静默覆盖** | 无告警，调试困难 |
| N2 | `indexOf` 结果被覆写复用（`v0` 双重含义） | 代码可读性差，易误判为残留 |
| N3 | 无多库支持 | 复杂 pak 无法表达 |
