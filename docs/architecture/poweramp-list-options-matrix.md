# Poweramp 全分类「列表选项」组织方式横向对照

> **本文定位**：`poweramp-list-options.md` 讲**机制**（弹窗怎么组装），
> `poweramp-album-songs-list-options.md` 讲**一个分类的深挖**。
> 本文补第三块：**把所有分类放在一张表里横向比对**——谁有排序、谁有缩放、
> 谁的排序是继承的、谁其实是空的。
>
> 方法论：对 `rest/library` 下 **155 个类**做**接口传递闭包**计算（不是只看直接
> `.implements`），再沿 `.super` 链解析 `g()` / `х()` 的**真实声明处**。

## 0. 一句话结论

**「列表选项」不是一套选项服务所有页面，而是每个实体各带一份「可选能力清单」。**
全库 38 个可弹列表选项的实体里，排序表只有 **7 种不同内容**，缩放表只有 **4 种**——
但这 7 种排序表被分给 38 个实体，**同一个数字在不同表里含义完全不同**（`sortMode=1`
在专辑是"按年份"、在所有歌曲是"按标题"、在年份页是"按添加日期"）。

三个反直觉事实：

1. **11 个实体的排序是「零项」**——它们的"排序"分组里只剩一个 **Reverse 复选框**，或者干脆整组不显示；
2. **缩放全部继承同一个 10 档基表**，只有搜索、字体、媒体库根三处覆写；
3. **能力靠接口继承判定**（`instance-of` 会沿父类与父接口走），所以**直接读 `.implements` 会漏判一半**。

## 1. 判定口径

### 1.1 能力探测：6 个接口 + 4 个"实体类判等"

`ListOptsActivity` 对实体做 11 处 `instance-of`，**但它们不是同一种探测**——
`instance-of` 的右操作数既有**能力接口**，也有**具体实体类**：

| 探测目标 | 类型 | 分组 | 行 | 判据含义 |
| --- | --- | --- | --- | --- |
| `g1` | 实体类 | Home 分类 | `:185` | 是不是"媒体库根" |
| `v3` | 实体类 | 搜索分类 | `:375` | 是不是"搜索页" |
| **`m2`** | **接口** | 排序 | `:481` | 能否排序 |
| **`d2`** | **接口** | 最大条目数 | `:690` | 能否设上限 |
| `d3` | 实体类 | **最长时长** | `:760` | 是不是"长"页（不是接口！） |
| **`e2`** | **接口** | 列表记忆 | `:833` | 能否记忆位置 |
| **`r2`** | **接口** | 查看方式（缩放） | `:964` | 能否改缩放 |
| `y0` | 实体类 | 文件夹限定 | `:968` | 是不是文件族 |
| **`q2`** | **接口** | 布局-精简标题 | `:1127` | 能否改行样式 |
| **`s2`** | **接口** | 布局-紧凑页头 | `:1243` | 能否改页头 |
| `a3` | 实体类 | 分类页填充 | `:1511` | 首页分类表 |

> **⚠️ 关键区分**：`d3` 名字长得像接口（和 `d2`/`e2` 同族），实际是 `class d3 extends o0`，
> 就是「长」页那个**实体**。所以「最短时长」分组**不是能力探测**，
> 而是"你这个页面就是 d3 本身"的**身份判等**。
>
> **推论**：其余实体**不可能**显示最短时长组——哪怕它继承了什么也一样。

### 1.2 为什么必须算「传递闭包」

`instance-of` 在 Dalvik 里**沿父类链 + 父接口链递归**。而本库大量能力是通过**接口继承**下发的：

```
l2  [interface] implements m2      ⇒ 实现 l2 即可排序
q2  [interface] implements r2      ⇒ 实现 q2 即得缩放
s2  [interface] implements r2      ⇒ 同上
x2  [interface] implements h0
m1  [interface] implements l1, k2
s1  [interface] implements z1
```

> **只读 `.implements` 行会得出错误结论**：例如专辑 `j` 的直接 `.implements` 是
> `[o2, n1, x3, i3, t3]`，**一个能力接口都没有**，但它的父类 `l` 实现了 `m2/q2`，
> 所以它**有**排序与布局。本库 38 个实体里，靠继承拿到能力的超过一半。

### 1.3 三元组格式

`g()`（排序）与 `х()`（缩放）都返回 `int[]`，**每 3 个 int 一组**：

```
{ 标题资源 id, 枚举值, 附加标志 }
```

第 3 位非 0 时，弹窗会在该项下追加一行提示（如"以该排序方式播放时，播放次数不会更新"）。

### 3.7 「没有排序」的三种实现 —— 行为各不相同（2026-11-18 修订）

> **本轮推翻了自己上一版的结论。** 上一版说「null → 只剩 Reverse；空数组 → 整组隐藏」。
> 全量复算后发现：**`d()` 的返回值才是真正的总开关**，`g()` 只是次要信号。

#### ① `d()` 返回 `-1` → **整组完全隐藏**（含 Reverse）

```smali
; ListOptsActivity.smali:491-511
invoke-interface {v0}, m2->d()I
const/4 v14, -0x1
if-ne v3, v14, :cond_d
goto/16 :goto_a          ; ← 直接跳到组结束
```

**受影响的 10 个实体**：`a0` 书签、`b0`、`f3` 歌词、`k3` 播放列表歌曲、`l3`、`m3` 队列、
`n3`、`p3` 原始文件、`v3` 搜索、`x0` 文件夹层次结构。

> 即使它们继承或覆写了 `g()`（`x0` 给空数组、`m3`/`a0` 给 null、`k3` 继承 16 项），
> **都到不了渲染那一步**。

#### ② `g()` 返回共享空数组 `h1.В` → 组仍显示，但**没有任何单选**

```smali
; ListOptsActivity.smali:506-511
sget-object v5, h1->В:[I
if-ne v4, v5, :cond_e
:goto_6  goto/16 :goto_a      ; ← 引用相等 ⇒ 跳过圆圈列表
```

**但注意**：这条分支跳到的是 `:goto_a`，而 `d()==-1` 也跳这里。
⇒ **两者效果相同：整组隐藏**。区别只在于触发的条件不同。

#### ③ `g()` 返回 `null` → 同上，也隐藏

`if-eqz v4, :cond_11`（`:526`）跳过圆圈循环，随后仍会走到 Reverse 追加段（`:628-681`）。
**但若 `d()` 正常返回**，Reverse 会被追加，组是可见的。

#### 汇总对照表

| `d()` | `g()` | 排序组表现 | 实例 |
| --- | --- | --- | --- |
| `-1` | 任意 | **整组隐藏** | `m3` `a0` `v3` `x0` `k3` `p3` `b0` `l3` `n3` `f3` |
| 正常值 | 空数组/`null` | 显示 Reverse，无单选 | 无（当前无实体落在此格） |
| 正常值 | 16/5/4/… 项 | 完整单选 + Reverse | 其余 28 个 |
| 固定常量 | 表 | 显示，默认选中固定项 | `e3`(0x1) `e4`(0x5) |

> **结论**：真正决定「这个分类有没有排序」的是 **`d()` 是否返回 `-1`**，
> 而不是 `g()` 是否为空。上一版把 `x0`/`m3`/`a0` 记成「只剩 Reverse」是**错的**。

## 5. 布局与记忆：只在少数分类出现

### 5.1 布局（`q2` / `s2`）—— 两个位掩码

| 接口 | 键 | 语义 | 出现在 |
| --- | --- | --- | --- |

## 7. 一句话回答"它们都是如何组织和实现的"

**组织**：弹窗只做三件事——探测能力、按三元组渲染、写回偏好。**没有任何一个分类的 UI 是单独写的。**

**实现**：分四层

| 层 | 内容 | 规模 |
| --- | --- | --- |
| ① 实体层 | 每个分类一个类，覆写 `g()`/`х()` 给出自己的表，覆写 `d()`/`r0()` 读写自己的偏好键 | 38 个实体 |
| ② 能力层 | 7 个空接口标记能力，靠 `instance-of` 探测 | 7 个接口 |
| ③ 视图层 | 1 个 `ListOptsActivity` + 8 个分组布局 | 单入口 |
| ④ 存储层 | `FastStaticPrefs` 的每分类独立键 | 见主文档 §4 |

**关键设计取舍**：**用"数据表 + 接口探测"换掉了"每分类一份 UI 代码"**。
代价就是 §3 里那张"同一数字含义不同"的表——这是**必须付的代价**，因为
`sortMode` 是**该分类私有的枚举**，不是全局枚举。
