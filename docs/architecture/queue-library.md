# 媒体库队列页面与入队契约

## 摘要

本次采用前端独立队列模型，复用现有音频加载命令、切曲事务及本地存储惯例。媒体库队列与当前播放来源自动形成的 `queueTracks` 分离。无需新增 Rust 命令、权限、依赖或数据库。

## 范围与页面边界

用户已要求队列页面、各选择面板中的添加到队列，以及集合展开。页面复用所有歌曲布局与卡片，隐藏页面工具栏和播放控制器上方工具栏的搜索入口；标题右侧显示已播数/队列总数，空队列显示“空”，其垂直位置对齐下方更多图标。播放不减少右侧总数。未播队列歌曲仅在队列根页的列表行评分之后显示同尺寸队列图标；其他分类及卡片网格均不显示此图标。集合项入队展开真实歌曲，不向队列加入文件夹或专辑占位项。

本次不实现 Poweramp 全套偏好（入队自动清空、延迟启动、分类自动返回等），不修改原播放列表关系。默认添加只追加并反馈成功，不打断当前播放；显式点击队列行或播放/随机按钮才进入队列播放。

## 数据与职责

`libraryQueue` 模型负责纯函数、序列化验证和固定存储键；`useAudioPlayer` 负责提交、播放确认及公开回调；视图模型负责投影；页面与选择面板只消费快照和动作。

建议每条独立记录具有：`entryId`、规范化 `sourcePath`、`scope`、真实 `trackId`、必要的原始曲目描述符、`createdAt`、可空 `playedAt`。记录按数组顺序排列。`entryId` 每次实际加入时生成，不以真实曲目 ID 代替；跨操作重复加入同一曲目产生不同条目。同一次选择集合展开按规范化音源路径去重，避免重叠文件夹或同一实体的多入口产生偶然重复。

持久化沿用书签的 version 1 本地存储结构，使用独立键。读入严格检查版本、类型、条目 ID 唯一性、有限时间戳与必要描述符。缺失/损坏数据返回空，不阻止启动。写入失败必须向调用方报告，避免成功反馈与实际状态不一致。不得把完整封面字节或歌词复制进队列存储。原始描述符/路径可以保留待恢复引用，展示与播放前仍需检查可访问性。

`queueTracks` 与 `PlaybackQueueOrigin` 当前表示某个来源的即时播放快照，许多索引按真实 `trackId` 建 Map；它们不能直接作为独立队列表。需要增加明确的队列来源判别和 occurrence 游标，或者等价地在队列模式下以独立条目 ID 导航。

## 入队与集合展开

各页面复用现有加入播放列表/删除动作已使用的真实歌曲展开函数，将实体选中项展开成歌曲快照。文件夹包含该集合定义的全部子层级歌曲；专辑、艺术家、专辑艺术家、作曲家、流派、年份及播放列表均展开对应集合成员，而非只取封面歌曲、已渲染行或当前视口内容。

选择范围以用户选中的实体为准；不能将界面搜索、虚拟列表挂载或分页状态误当作实体完整成员。显式选择单首歌曲仍只加入该歌曲。提交在 hook 内重新校验来源、根选择权限、真实 trackId 与 available，不接受任意 UI 提供路径绕过既有根过滤。全部不可用时不改变队列并显示失败原因；部分不可用时明确反馈实际加入数量和跳过数量。异步准备完成后检查选择请求仍有效，防止过时结果加入另一次选择。

## 播放与已播状态

音频命令只接受真实路径，返回真实 `trackId`。禁止用 `entryId` 覆盖 `AudioFolderTrackRef.id`。队列内点选、上一首、下一首、自然结束和随机必须以 occurrence 游标定位，不得通过 `findIndex(trackId)` 或 `Map(trackId,index)` 猜测重复项的位置。继续调用现有加载事务与 generation/requestId 守卫，加载失败不得标记已播；快速换曲的过时响应不能移动游标或更新条目。

本次选择“首次确认开始播放”作为已播门槛：接受的真实 `phase=playing` 与当前曲目及代次匹配后，更新该路径当时已存在的未播队列项。不得在入队、点击播放、loading、error、仅恢复 paused 或预取时提前标记。此规则与 Poweramp 的曲目级播放时间晚于入队时间的方向一致；它不是声称已复现 Poweramp 的播放时间写入时机。已有最近播放/最常播放采用播放一半门槛，不可直接复用其统计结果代替队列状态。

同一音源已经存在的多个未播项一起更新，是曲目级时间语义的结果；稍后再次加入该音源的新条目重新未播。计数始终来自完整条目数组，满足 `已播数 + 未播数 = 队列总数`，标题展示 `已播数/队列总数`。队列页列表行使用各条目自己的状态显示未播图标；不再向其他分类或卡片网格提供全局待播图标。

用户最终澄清恢复原先的保留记录行为：首次确认 playing 更新已播状态，自然 ended 后记录仍保留在页面与持久存储。自然结束、停止、跳歌、循环和播放其他来源均不得自动删除条目。此前关于自然 ended 消费条目、捕获完成 entryId、按剩余条目过滤导航和消费后清理会话的临时契约全部撤回。已播条目仍可重新播放，全部已播时标题为 `总数/总数`，不显示“空”。

## 手动清空

队列根页面更多按钮提供可执行的“清空队列”。它清空独立条目及独立持久存储，不删除音频文件、不修改原播放列表或媒体库。先完成存储提交再发布空状态；写入失败保留原列表并报错。空队列时该动作禁用或隐藏。清空后标题显示“空”。

手动清空不打断当前正在播放的音频。若当前播放来自队列，则解除其后续旧队列导航和可恢复引用；自然结束不能从已清空快照继续下一条或恢复旧队列。使用现有 generation/requestId 守卫，清空前挂起的选择结果不能重新填回已清空记录。清空之后的新入队项是新的独立条目，不被旧响应改写。

播放其他来源退出队列播放上下文，保留独立条目。修改来源实体或评分只刷新展示，不重写已有队列顺序；真实文件删除按现有删除语义更新可用性/引用并保护当前加载事务。移除队列关系不得删除物理文件。

## 质量属性与取舍

选择前端模型能复用现有书签、本地存储与音频事务，保持权限和依赖不变。Rust 持久表方案会增加命令、迁移和同步边界，本次没有必要。仅把当前播放快照显示为队列的方案无法满足独立入队、重复条目和跨来源保留，因此不采用。

队列条目只持有轻量引用；卡片继续使用既有虚拟化、元数据与封面缓存通道。恢复不自动启动音频，不为每个条目读取完整详情。未来若独立队列迁移到后端，保留 entryId、真实音源身份、条目状态和 occurrence 导航四个边界。

## 分工与验收

Frontend Agent 独占 `src/**`，负责模型、hook、视图模型、页面、各集合选择接线和必要播放分支。Rust/Tauri 本轮无写入任务。Architecture Agent 仅拥有本文。Test Agent 独立验证，可在明确分配后写专用测试文件，不能与实现 Agent 同时改同一文件。

验收覆盖空/非空、两处无搜索、已播数/总数和图标布局；其他分类及卡片网格无队列图标；各类集合完整展开；跨操作重复入队、重叠集合单次去重；真实成功播放与失败/过时/暂停恢复的状态区别；playing、自然 ended、跳歌、停止后记录始终保留，播放与结束不减少右侧总数；已播状态持久恢复、重复音源和播放中追加项行为；更多按钮实际清空、空态、写失败、物理文件与来源关系不受影响；清空不打断当前音频但旧快照不继续导航或恢复；队列持久恢复与存储损坏；来源播放不被添加操作打断；已有播放列表、评分、文件夹排除和物理删除语义回归。最终执行前端 build/lint 和独立模型/浏览器测试；不需要为无 Rust 变更运行额外后端编译。
