# 播放列表封面加载及持续滚动慢于所有歌曲

## 现象与复现

在同一音乐库中打开“所有歌曲”，再打开当前播放列表或浏览其他播放列表，比较首屏封面、持续拖动滚动条以及停止后的封面补齐速度。原播放列表会出现大片封面尚未显示，拖动时差距更明显。

首轮减少卡片重复渲染后，用户仍反馈持续拖动明显偏慢。第二轮沿真实加载路径修复后，用户于 2026-10-24 确认“这次修改效果显著”。本记录据此标记已修复，不将浏览器计时等同于所有设备的实机性能承诺。

## 根因

1. 每张封面发布都会合成新的歌曲行及点击回调，使卡片的引用比较失效，并推动整个 Shell 重新派生列表数据。
2. 当前播放列表窗口变化会额外调用同步 `audio_hydrate_track`，读取音频详情、时长、原始封面及歌词；“所有歌曲”加载缩略图不需要这条完整详情路径。实际列表文字和时长已有独立摘要、时长通道。
3. 播放列表近邻缩略图预取逐张等待空闲回调，持续滚动时容易到进入视口后才开始读取。
4. 打开音源后队列保持逻辑打开，即使已经被音乐库页面覆盖，原封面发布仍依据 `queueOpen` 更新整个 Shell；因此仅增加卡片局部订阅还不足以消除当前播放列表的额外更新。

## 修复范围

- [PlayerShell](../../../src/features/player/components/PlayerShell.tsx) 与 [歌曲行结构共享](../../../src/features/player/model/playlistTrackRows.ts)：复用未变化的最终展示行，稳定歌曲选择回调；播放顺序仍取当前过滤结果。
- [PlaylistPanel](../../../src/features/player/components/PlaylistPanel.tsx)：稳定相同歌曲 ID 序列的激活回调，使符合验证条件的网格布局复用既有行索引；几何不符合条件时继续完整测量回退。
- [useAudioPlayer](../../../src/features/player/hooks/useAudioPlayer.ts)：移除列表滚动触发的完整详情队列，保留播放、恢复、预览所需的真实 hydration；有界近邻缩略图以低优先级直接准入，全播放源后台工作仍等待空闲。
- [封面订阅桥](../../../src/features/player/model/playlistArtworkStore.ts)、[PlaylistCard](../../../src/features/player/components/PlaylistCard.tsx) 与 [useLibraryArtwork](../../../src/features/player/hooks/useLibraryArtwork.ts)：按歌曲通知封面变化，普通卡片更新不再逐张推动 Shell。队列只有在播放器页面实际可见时才需要整队列更新；首曲大封面、当前歌曲和侧栏首曲继续更新。
- `PlayerSurface`、`PlaylistPanel` 和展示模型传递封面订阅来源。原 hook 保留缓存、预算和 URL 所有权；首次显示只读 fallback 时建立窗口内租约，离窗、替换和卸载时释放。发布、回收、错误回滚、重置及 StrictMode 清理均通知消费者，避免保留已回收的 URL。

本次没有新增依赖、权限或持久化结构，也没有修改 Rust 命令契约、全局单原生缩略图请求约束及原有首曲 512px 升级规则。

## 独立验证

### 持续滚动对照

Test Agent 使用真实生产前端和浏览器，比较 600 首相同曲目、相同布局及 `1600 × 1000` CSS px 视口。两页先等起始可见封面完成，再以 `800 CSS px/秒` 持续滚动 3 秒。采样通过 IntersectionObserver 维护可见集合，最多检查 40 个节点；测试采样自身的卡片几何测量次数为 0。

| 页面 | 滚动期间可见封面完成率 | 停止后补齐时间 |
| --- | ---: | ---: |
| 所有歌曲 | 99.97% | 22ms |
| 当前播放列表 | 99.01% | 63ms |
| 浏览其他播放列表 | 99.81% | 50ms |

当前播放列表的额外完整详情读取和逐封面 Shell 更新均降为 0；测试保留逻辑打开但实际隐藏的队列，以覆盖第四项根因。真实可见封面重复读取为 0；屏外可选预取允许有界缓存回收后重入，所测场景每个来源最多读取 2 次。

原生边界使用确定性替身：缩略图工作延迟为 15ms，同步 hydration 占用宿主分发 40ms；调度模型已按 Rust/Tauri 源码核对。表中数字用于同场景回归比较，未直接计时视频中的实际音乐库，不能推广为真实设备固定耗时。

### 功能及生命周期回归

- `npm run lint`、`npm run build`、`git diff --check`：通过。
- 封面订阅、歌曲行引用、readiness、grace、fallback、All Songs 窗口与共享调度：50 项单测通过。
- 预览元数据：5 项通过，保留标题、艺人、专辑、权威空标签及过期来源隔离检查。
- 封面预加载、错误重试、URL 生命周期和内存预算：12 个场景通过；摘要及独立时长通道仍提供真实字段。
- StrictMode 卸载：外部订阅收到空快照，原 canonical snapshot 清空，旧 URL 已释放。
- 底部播放器滑动、跨播放源及反向切换：通过，所测切换轨迹未出现封面空白。

## 附件与验收边界

来源视频为用户提供的 `播放列表相对加载缓慢现象.mp4`，本次不将大视频或临时性能轨迹加入仓库。用户已确认实际体验显著改善；自动化覆盖的是上述浏览器场景，不代表任意设备、音频格式、存储速度及无限快冷缓存拖动下封面均能即时出现。
