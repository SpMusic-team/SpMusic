# SpMusic 变更记录

本文件是 SpMusic 正式的问题/变更跟踪**索引**。每条 bug 一个独立文件（`docs/changes/bugs/BUG-xxxx.md`），本文件只维护索引、字段约定和状态流转；截图内嵌在各 bug 文件中。

## 字段约定

| 字段 | 说明 |
| --- | --- |
| 编号 | 唯一标识，格式 `BUG-xxxx`，只增不改 |
| 类型 | 缺陷 / UI 优化 / 功能缺失 / 样式适配 |
| 严重程度 | 高：功能不可用或明显错乱；中：体验明显受损；低：细节打磨 |
| 模块 | 歌词页 / 播放控制器 / 播放页（标题与滚动）等 |
| 问题描述 | 一句话说清问题，必要时补充上下文 |
| 提出日期 | 格式 `yyyy-mm-dd hh:mm` |
| 修复版本 | 计划或实际修复的版本，未修复为空 |
| 状态 | 待处理 / 处理中 / 待审核 / 已关闭（另：已拒绝、重复、暂缓） |
| 附件 | 截图等证据，存放于 `docs/changes/assets/`，内嵌于对应 bug 文件；入库前统一压缩到宽度 ≤1200px |

本项目由两人协作，记录不设提出人/处理人/审核人字段。

## 状态流转

```text
待处理 → 处理中 → 待审核 → 已关闭
   │         │         │
   └── 已拒绝 / 重复 / 暂缓
```

- 提出：新建条目，状态为“待处理”；
- 处理：开始修复时改为“处理中”，完成后填写修复版本并改为“待审核”；
- 审核：验收通过改为“已关闭”；不通过退回“处理中”，并在附件/备注中说明原因；
- 已关闭条目不再原地修改，后续问题新开编号。

## 维护约定

- 新增问题：在 `docs/changes/bugs/` 下新建 `BUG-xxxx.md`（编号递增），并在本索引表追加一行；
- 截图入库前统一压缩到宽度 ≤1200px，存放于 `docs/changes/assets/`，命名与编号对应；
- 状态、类型、严重程度、模块取值见“字段约定”，不要随意新增取值；
- 修改 bug 文件正文后同步更新其 frontmatter 中的 `updated`，并同步本索引表；
- 条目关闭或拒绝时，更新其状态并在对应 bug 文件正文中注明原因与版本。
