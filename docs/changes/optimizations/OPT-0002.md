# 读取路径重复解析且只读操作会改写用户文件

> 状态：已实现（2026-08-13）

## 问题描述

曲目引用加载流程对同一文件做多次解析，且带 sidecar 歌词的「只读」操作会把歌词写回并替换用户音频文件，产生副作用与额外耗时。

## 现状依据

- `src-tauri/src/audio/source.rs:203-224`：`load_track_ref_with_options` 依次执行 `open_source().total_duration()`、`decode_duration()`、`read_metadata_or_default()`，同一文件被打开解析 2-3 次。
- `src-tauri/src/audio/source.rs:950-966`：`read_metadata_or_default` 在无内嵌歌词且存在 sidecar `.lrc` 时调用 `embed_lyrics`。
- `src-tauri/src/audio/source.rs:1065-1107`：`embed_lyrics` → `safe_update_tag` 通过 `fs::copy` 复制整份音频到临时文件、改写标签后替换原文件。
- 该路径被 `hydrate_track_ref`（`source.rs:196-200`）和 `runtime.load_path`（`runtime.rs:158`）调用，即 `audio_load_file`、`audio_hydrate_track`、目录列表等只读流程都会触发。

## 影响

- 读取操作产生副作用：用户音频文件在加载/列表过程中被静默改写，无法回滚。
- 大文件每次加载都要复制整份文件并写盘，耗时且占用双倍磁盘空间；同一文件被多个只读调用重复改写。

## 优化方向

歌词优先存入应用侧缓存（内存或后续持久化存储），sidecar 歌词只读取、不写回音频文件；将「内嵌歌词」从默认读取流程中移除，或改为显式的用户操作。

## 备注

- 现有内嵌歌词测试（`source.rs:2285` 附近）需要随行为变更同步调整。
- 缓存目录与文件失效策略需要与数据层/架构方案一并评估。

## 实现记录

### 采用方案

按架构说明 `docs/architecture/lyrics-cache-and-embed-boundary.md` 与决策记录 `docs/decisions/2026-08-13-OPT-0002-lyrics-cache-and-embed-boundary.md` 实施：

1. **应用侧内存歌词缓存**：新增 `src-tauri/src/audio/lyrics_cache.rs`，有界 LRU（默认 512 条），键为 `track_id(path)`，只缓存 sidecar `.lrc` 解析结果（`None` 为负缓存）；失效采用「实际读取的 `.lrc` 路径的 mtime + 大小指纹」+「负缓存 TTL（30s）」；`Arc<LyricsCache>` 由 `AudioController` 持有并克隆给 parser worker，Mutex + 锁外磁盘 I/O + double-checked 回填；`read_metadata` 是唯一命中/回填入口。内嵌歌词始终随 tag 实时读取，不经过缓存。持久化（`cache_dir/lyrics`）本次不实现，仅在 `lyrics_cache.rs` 内部预留边界。
2. **sidecar 歌词只读**：`read_metadata` / `read_sidecar_lyrics` / `read_sidecar_lyrics_with_source` 均只读，不写回音频文件；新增依赖方向约束——只读模块（metadata/source/runtime/playlist/duration/cover_cache/symphonia_source/cue/chapters/device）不得引用 `tag_writer`，由 `mod.rs` 注释声明，Test Agent 以 grep 验证。
3. **内嵌歌词写回显式化**：新增唯一生产写入口 Tauri command `audio_embed_lyrics`（输入 `{ path, lyrics }`，空串=清除；输出重新水合的 `AudioTrackRef`），复用 `tag_writer::embed_lyrics` / `safe_update_tag`，成功后失效歌词缓存并重新水合；错误码映射 `INVALID_PATH` / `FILE_NOT_FOUND` / `UNREADABLE_FILE` / `UNSUPPORTED_FORMAT` / `INTERNAL_ERROR`（recoverable=false，回滚也失败时）。「内嵌歌词」读取保留（内嵌优先、sidecar 后备），移除的是默认读取流程中的写回动作。

### 关键改动

- `src-tauri/src/audio/lyrics_cache.rs`：新增（缓存结构、指纹、负缓存 TTL、LRU、锁中毒降级直读、8 项单元测试）。
- `src-tauri/src/audio/metadata.rs`：`read_metadata` 增加 `lyrics_cache: Option<&LyricsCache>`；新增 `read_sidecar_lyrics_with_source`。
- `src-tauri/src/audio/source.rs` / `runtime.rs`：`hydrate_track_ref` / `start_track_parser` 签名扩展。
- `src-tauri/src/audio/controller.rs`：持有 `Arc<LyricsCache>`；新增 `embed_lyrics` 方法与错误映射纯函数（5 项单测）。
- `src-tauri/src/audio/types.rs`：新增 `AudioEmbedLyricsInput`（ts-rs 导出测试）。
- `src-tauri/src/lib.rs`：注册 `audio_embed_lyrics` 命令。
- `src/features/player/services/audioCommands.ts`：新增 `AudioEmbedLyricsInput` 与 `embedAudioLyrics` 封装（无 UI 接入）。
- `docs/architecture/real-audio-playback.md`：sidecar 写回偏差由「必须修复」改为「已修复（OPT-0002）」并同步验收标准与风险条目。
