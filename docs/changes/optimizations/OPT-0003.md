# 命令返回状态与事件推送双通道对账

## 问题描述

每个控制命令都返回完整 `AudioPlaybackState`，同一操作后又广播 `audio_state_changed` 事件。前端需要同时消费两条通道，并依赖多套 ref 与回滚逻辑做去重、防竞态，复杂度持续膨胀。

## 现状依据

- `src-tauri/src/lib.rs:84-146`：`audio_play`、`audio_pause`、`audio_stop`、`audio_seek`、`audio_set_volume` 均返回 `Result<AudioPlaybackState>`。
- `src-tauri/src/audio/controller.rs:78,91,100,109,122,135,158,170`：上述每个操作完成后再次 `emit_state_changed`。
- `src/features/player/components/PlayerShell.tsx:664-673`：前端同时监听 `audio_state_changed` 事件。
- `src/features/player/components/PlayerShell.tsx:293-308`：前端用 `audioStateRequestGenerationRef`、`transportRollbackStateRef`、`latestAudioStateRef` 等多套 ref 处理双通道对账与竞态；该组件已 1195 行。

## 影响

- 双通道语义重叠，前端对账逻辑复杂，容易在快速操作、加载与设备切换场景出现竞态。
- 新增状态字段或操作时，命令返回值与事件负载两处契约都要同步维护。

## 优化方向

二选一并收敛为单一事实来源：

1. 命令只返回轻量结果（成功/错误 ack），状态变化全部由事件推送。
2. 命令返回值即唯一事实，事件只用于非命令触发的变化（设备切换、播放结束、解码失败等）。

## 备注

- 该决策影响所有控制命令的 TS 类型与 PlayerShell 状态机，需 Architecture Agent 输出契约方案后由前端与 Rust/Tauri Agent 分头实施。
- 与 OPT-0004（进度推送）存在耦合，建议一并评审。
