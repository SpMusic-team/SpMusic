# 封面图同时返回 dataUrl 与 filePath 导致负载膨胀

## 问题描述

封面已缓存到本地文件时，`AudioCoverArt` 仍同时返回 `file_path` 与整张封面的 base64 `data_url`，使每个曲目引用的 JSON 负载被数 MB 封面数据撑大。

## 现状依据

- `src-tauri/src/audio/source.rs:1227-1246`：`cover_art_from_picture` 在封面写入缓存后 `file_path` 为 `Some`，但仍设置 `data_url: Some(cover_art_data_url(...))`。
- `src/features/player/services/audioCommands.ts:34-39`：前端类型 `AudioCoverArt` 同时包含 `filePath` 与 `dataUrl` 两个字段。

## 影响

- 含封面的专辑按曲目逐个返回时，同一张封面在 JSON 中重复出现多次，解析与内存开销随曲目数线性放大。
- 列表加载、曲目切换的响应时间受封面 base64 传输影响。

## 优化方向

有 `file_path` 时 `data_url` 返回 `null`，前端统一通过 `convertFileSrc(filePath)` 加载缓存封面；仅当缓存不可用时回退到 `data_url`。

## 备注

- 需同步调整前端封面渲染逻辑与相关测试。
- 与 OPT-0006（契约生成）联动时一并更新类型契约。
