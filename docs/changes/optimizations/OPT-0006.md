# 前后端 TS 契约手抄维护、缺少生成与校验

## 问题描述

前端 `audioCommands.ts` 中的 `AudioPlaybackState`、`AudioTrackRef`、`AudioTrackMetadata` 等类型为手写维护，后端 ts-rs 只在单元测试中「自证」可导出，未生成并提交 `.ts` 产物，也没有 CI 校验两边是否同步。

## 现状依据

- `src/features/player/services/audioCommands.ts:9-60`：手写 `AudioPlaybackPhase`、`AudioErrorCode`、`AudioTrackRef`、`AudioTrackMetadata`、`AudioCoverArt`、`AudioCommandError` 等类型。
- `src-tauri/src/audio/types.rs:158-219`：ts-rs 的 `export_to_string` 仅在测试中断言导出字符串包含预期字段。
- 仓库中不存在由后端生成的 TS 类型文件，也没有校验生成产物新鲜度的 CI 步骤。

## 影响

- 新增字段、错误码或枚举值后，前后端类型容易漂移，问题通常在运行时（`invoke` 返回 `undefined`）才暴露。
- ts-rs 测试只能证明后端可以导出，不能证明前端已同步。

## 优化方向

增加 codegen 脚本生成 `*.gen.ts`（如 `src/features/player/services/audioCommands.gen.ts`）并提交到仓库，CI 校验产物新鲜度；手写类型改为重新导出生成类型，仅保留少量 UI 专属扩展。

## 备注

- 需要确定 codegen 的触发方式（手动脚本、pre-commit 或 CI 校验）。
- 与 OPT-0003、OPT-0004、OPT-0005 的契约变更联动实施收益最大。
