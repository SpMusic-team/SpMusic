# 命令路径输入缺少规范化与范围校验

## 问题描述

`input_path` 只拒绝空字符串，`audio_load_file`、`audio_hydrate_track`、`audio_list_folder_tracks` 等命令接受任意路径，且当前 WebView CSP 为 `null`，命令面缺少路径规范化与范围约束。

## 现状依据

- `src-tauri/src/audio/source.rs:175-183`：`input_path` 仅拒绝空白字符串，不做 canonicalize 或符号链接逃逸检查。
- `src-tauri/src/audio/controller.rs:295,307,319`：加载、hydrate、目录列表均直接使用 `input_path` 结果。
- `src-tauri/tauri.conf.json:25-26`：`security.csp` 为 `null`。

## 影响

- 一旦未来 WebView 引入插件或远程内容，命令面将等同于任意文件读取能力。
- 符号链接、UNC 路径、盘符外路径均未限制，边界语义不明确。

## 优化方向

对输入路径执行 canonicalize 并拒绝符号链接逃逸与预期范围之外的路径；至少补齐规范化与存在性校验。CSP 收紧策略应与安全边界一并评审。

## 备注

- 需要明确「允许读取的文件范围」定义（如用户显式选择的目录），建议由 Security Agent 或 Architecture Agent 评审。
- 相关文件选择功能使用原生对话框，本次主要解决命令面校验。
