# 播放队列位于前端，曲目切换存在间隔且无法预加载

## 问题描述

播放列表与队列当前由前端管理，`ended` 后由前端加载下一首，曲目间存在切换间隔，且无法预加载下一首。

## 现状依据

- `docs/decisions/2026-07-27-v0-1-local-m3u8-temporary-queue.md`：记录了临时将队列放在前端的决策。
- `src/features/player/components/PlayerShell.tsx:757-771`：播放结束后通过 `setTimeout` + `changeTrack(1, true)` 由前端加载下一首。

## 影响

- 曲目间有明显切换间隔：下一首在上一首结束后才开始打开与解析。
- 无法预加载下一首，快速连续切歌时竞态完全由前端管理。

## 优化方向

长期将队列收敛到后端：加载当前曲目时顺带解析并缓存下一首，减少切换间隔；前端只提交队列变更意图。

## 备注

- 属于跨模块契约变更，需 Architecture Agent 输出方案并由 PM Agent 排期。
- 该决策文档中的「临时」定位应随方案落地同步更新。
