# 目录播放列表重复扫描目录

## 问题描述

`load_folder_playlist` 对同一目录执行两次扫描：先遍历查找 m3u8，找不到后再遍历一次构建音频列表，大目录每次打开都是 O(n) 的两倍。

## 现状依据

- `src-tauri/src/audio/source.rs:244-259`：`load_folder_playlist` 先调用 `load_first_directory_m3u8_playlist`，无 m3u8 时再调用 `load_directory_audio_playlist`。
- `src-tauri/src/audio/source.rs:386` 与 `295`：两个函数各自执行一次 `fs::read_dir`。

## 影响

- 大目录每次打开都重复扫描，耗时翻倍。
- 列表接口未顺带返回时长/元数据摘要，后续渲染仍需逐个请求。

## 优化方向

单次 `read_dir` 同时识别 m3u8 与音频文件；列表接口顺带返回摘要信息，或将元数据改为按需懒加载。

## 备注

- 目录扫描与后续媒体库索引策略相关，可并入长期媒体库方案一并设计。
