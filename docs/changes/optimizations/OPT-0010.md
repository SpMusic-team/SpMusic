# 双解码栈与 vendored matroska 维护成本

## 问题描述

项目同时依赖 rodio 内置的 symphonia 与直接声明的 symphonia 各 feature，并 vendor 了 `matroska-demuxer`，解码依赖存在双栈与本地补丁维护成本。

## 现状依据

- `src-tauri/Cargo.toml:26-32`：`rodio = 0.19.0`（内部基于 symphonia）。
- `src-tauri/Cargo.toml:41-55`：直接依赖 `symphonia` 0.5.5 及 `symphonia-aac`、`symphonia-flac`、`symphonia-isomp4`、`symphonia-mp3`、`symphonia-vorbis`、`symphonia-wav`、`symphonia-adapter-libopus`。
- `src-tauri/Cargo.toml:56`：`matroska-demuxer = { path = "vendor/matroska-demuxer", version = "=0.8.0" }`（vendored）。

## 影响

- symphonia 升级需要同时验证 rodio 内嵌路径与直接依赖路径，回归面翻倍。
- vendored matroska 补丁的升级与回退条件未书面化，后续维护者难以判断何时可以还原。

## 优化方向

在架构文档中明确双栈边界、vendored 补丁的升级策略与回退条件；评估是否统一直接依赖与 rodio 内部的 symphonia 版本。

## 备注

- 涉及音频兼容性验证（Audio Compatibility Agent 负责格式矩阵与回归证据），变更前需与其协调。
