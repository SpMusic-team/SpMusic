# 日志在命令、控制器、运行时三层重复

## 问题描述

同一操作会在 Tauri 命令层、控制器、运行时线程各记录一条日志，load/play 路径日志噪音偏大，问题定位需要跨三层拼接。

## 现状依据

- `src-tauri/src/lib.rs`：命令层每个 `audio_*` 命令记录 `tracing::info!`（约 17 处）。
- `src-tauri/src/audio/controller.rs`：运行时线程对每个请求再记录一条（约 36 处）。
- `src-tauri/src/audio/runtime.rs`：内部操作继续记录（约 30 处）。
- 例如 `audio.load_file` 在命令、runtime 线程、`load_track_ref` 各记录一次（`lib.rs:71-78`、`controller.rs:67-79`、`source.rs:210-235`）。

## 影响

- 同一事件多次打印，日志可读性下降，问题定位成本增加。

## 优化方向

明确分层日志职责：命令层记录入参摘要（info），运行时记录状态变化（info），解析流程记录耗时明细（debug 或按需开启），并统一 operation 命名。

## 备注

- 属于工程规范调整，可结合代码评审流程一并落地，无需架构决策。
