# 播放信息按钮与输入到输出流程说明

> 状态：候选优化，尚未实现、审核或排期；本文档不代表需求已批准，也不承诺进入特定版本。

## 候选优化描述

在播放界面增加一个播放信息按钮，帮助用户用较小的界面占用查看当前播放上下文。候选交互为：

- 单击按钮时，在以下信息之间依次切换：输出方式、播放列表、播放方式、歌曲目录、曲名 - 作者、采样率。
- 长按按钮时，展示当前音频从输入到输出的完整流程。

上述名称和交互顺序来自原始工作簿，仍需 Requirements Agent 与 UI/UX Agent 明确定义后才能进入实现。

## 当前状态与实现缺口

当前代码具备部分可复用数据，但尚未形成该播放信息功能：

- `MoreActionsMenu.tsx` 中的“信息 / 标签”仍是禁用的 `UnavailableAction`，不能作为播放信息入口。
- `ControlDock.tsx` 当前没有播放信息按钮，也没有单击轮换信息的状态或交互。
- `PlayerShell.tsx` 已持有会话内临时队列、目录和播放模式状态；曲名与作者也已经用于当前歌曲展示。这些仅是候选功能的部分输入，不代表组合交互已完成。
- 前端 `AudioTrackRef` 与 Rust `AudioTrackRef` / `AudioTrackMetadata` 均未提供采样率字段。
- 输出设备签名目前仅供 Rust 音频运行时内部检测设备变化，未通过稳定 DTO 暴露给前端。
- 播放器组件中未发现针对该按钮的长按计时、取消规则、键盘等价操作或“输入到输出”流程面板。
- 当前没有覆盖此交互的前端测试。

## 待明确的产品与交互边界

进入实现前至少需要确认：

1. “输出方式”是指系统默认输出设备、音频后端 / 解码路径、声道布局，还是其他概念；是否需要新增后端查询契约。
2. “播放列表”在 v0.1 中应只表示会话内临时队列来源，不能让用户误解为已支持持久化或可编辑的产品级播放列表。
3. “播放方式”展示随机、顺序、单曲循环或列表循环中的哪些状态，以及文案与图标如何对应。
4. “歌曲目录”显示完整路径还是经过隐私处理的目录名；复制、展开和路径不可用时如何处理。
5. “采样率”展示输入文件采样率、解码后的 PCM 采样率还是实际输出设备采样率；三者不应混写。
6. 单击切换的固定顺序、初始项、自动复位、跨歌曲保持规则，以及没有数据时的后备文案。
7. 长按阈值、按下后移动 / 离开 / 取消的行为、触摸与鼠标一致性，以及键盘和辅助技术的等价入口。
8. “输入到输出的全部流程”需要展示哪些阶段，例如文件 / 临时队列来源、容器与 codec、解码、播放状态、混音 / 音量、输出设备；数据必须来自真实运行时，不能用静态说明冒充当前流程。

## 候选验收要点

以下仅供后续需求和 UI 规格细化，不是已批准验收标准：

- 单击按钮能按已批准顺序切换信息，每一项均显示真实数据或明确的不可用状态。
- 长按与键盘等价操作能打开流程说明，并可明确关闭；短按和长按不会同时触发。
- 临时队列不会被标记为持久播放列表，输入采样率与输出采样率不会混淆。
- 完整路径等本地信息遵循确认后的隐私展示规则。
- 加载中、无歌曲、元数据缺失、输出设备不可用和窄窗口下均有定义明确的状态。
- 新交互具备可访问名称、焦点行为和自动化测试证据。

## 依赖与建议分工

- Requirements Agent：澄清信息定义、范围和正式验收标准。
- UI/UX Agent：确定按钮位置、切换反馈、长按 / 键盘等价交互、流程面板和异常状态。
- Architecture Agent：若需暴露输入 / 输出音频参数或设备信息，定义前后端数据契约与安全边界。
- Frontend Agent：在需求、UI 与数据契约获批后实现界面交互。
- Rust/Tauri Agent：仅在批准的契约需要新增运行时音频信息时实现后端能力。
- Test Agent：验证短按 / 长按判定、数据准确性、可访问性和回归风险。
