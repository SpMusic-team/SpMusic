# 竖向半屏播放器布局适配

> 状态：候选优化，尚未完成、审核或排期；本文档不代表需求已批准，也不承诺进入特定版本。

## 候选优化描述

为播放器补充完整的竖向半屏布局适配。Figma 设计稿提供视觉思路，但受设计工具布局能力限制，歌词和封面的竖向适配不能直接作为最终实现尺寸；前端需要在保留设计意图的前提下，使用响应式代码完成布局。

候选布局意图为：

- 进入竖向半屏窗口时，封面保持比例，不因横向或纵向空间变化而被压扁或拉长。
- 在封面同时受可用宽度和可用高度约束时，以两项约束中较小的可用尺寸决定封面尺寸，即按 `min(可用宽度, 可用高度)` 的思路缩放。
- 歌词区域与下方播放控制使用封面之外的剩余空间，并能随窗口尺寸变化继续收缩或扩展。
- 前端可以根据设计稿的布局意图灵活实现，不要求逐项照搬 Figma 中无法表达的拉伸设置。

## 当前状态与实现差距

当前实现已经具备部分响应式基础，但尚未满足上述完整适配目标：

- `ResponsivePlayerLayout.tsx` 已定义 `full`、`horizontal`、`vertical` 和 `quarter` 四种布局，并根据视口宽高比、窗口状态与滞回阈值选择布局。
- `responsive.css` 已为 `vertical` 布局定义以 `1120 × 1440` 为参考的尺寸变量。`--vertical-cover-size` 使用多个宽高约束的 `min(...)` 结果，封面框同时设置 `aspect-ratio: 1`，具备“取较小约束并保持方形”的部分实现基础。
- `cover-panel.css` 中封面图片使用 `width: 100%`、`height: 100%` 与 `object-fit: cover`。该规则保持源图片比例，但可能裁切图片边缘；它是否符合本条“保持比例”的最终含义仍需确认。
- 当前 `vertical` 布局明确将 `.lyrics-panel` 设为 `display: none`，未实现歌词填充剩余区域。
- 当前竖向布局的控制区使用固定计算高度，网格中还包含固定间隔与空白行，尚未形成“歌词与控制共同分配封面之外剩余空间”的明确规则。
- 现有 `docs/ui/player-shell.md` 主要按宽屏、普通窗口和窄屏描述响应式行为，并规定窄屏隐藏歌词；尚未定义本条所述竖向半屏歌词可见布局。该规格应由 UI/UX Agent 在候选优化获批后更新，不能由本文档覆盖。

## 待澄清项

进入需求、UI 规格或实现前，需要明确以下歧义：

1. “竖向半屏”的目标窗口范围：是特定参考尺寸、操作系统贴靠后的半屏区域，还是满足某组宽高比与最小尺寸的所有窗口。
2. 当前 `vertical` 与 `quarter` 布局的边界是否符合目标；较窄竖屏应继续使用 `quarter`，还是也应采用本条布局。
3. “封面保持比例”是保持方形封面框，还是保持每张源图片的原始宽高比。若源图片不是方形，需要确认采用完整显示留白、居中裁切还是其他规则。
4. `min(可用宽度, 可用高度)` 中“可用高度”应扣除哪些固定区域，例如窗口栏、歌曲信息、歌词最小高度、控制条、内边距和安全间距。
5. 原始描述同时提到“竖向半屏”和“右侧的歌词”。竖向布局中的歌词究竟位于封面右侧、封面下方，还是根据宽度在两种结构之间切换，需要 UI/UX 规格给出明确网格。
6. “歌词和下方的按钮填充剩余部分”是指歌词弹性增长、控制条固定最小高度，还是两者按比例分配；两区各自的最小尺寸和溢出 / 滚动策略尚未定义。
7. 窗口高度不足、无歌词、长歌词、双语歌词、缺少封面和控制按钮精简状态下的降级顺序。
8. 布局切换时是否保留当前歌词位置、面板状态和焦点，以及是否需要遵循 `prefers-reduced-motion`。

## 候选验收要点

以下内容仅供 Requirements Agent、UI/UX Agent 与 Test Agent 后续细化，不是已批准验收标准：

- 在获批的竖向半屏尺寸范围内，封面不发生非等比拉伸，也不会覆盖歌曲信息、歌词或控制区。
- 封面尺寸由实际可用宽高约束中的较小值决定；窗口连续缩放时不出现明显跳动、溢出或反复切换布局。
- 歌词保持可见并使用剩余空间；内容不足和内容过长时均有稳定布局与滚动行为。
- 下方控制保持可操作，不与歌词或封面重叠；关键控件满足获批的最小点击尺寸。
- 无封面、无歌词、双语歌词、加载中和最小支持窗口均有明确降级状态。
- 使用目标平台半屏贴靠尺寸进行人工检查，并为布局选择和关键尺寸规则补充自动化测试。

## 依赖与建议分工

- Requirements Agent：定义竖向半屏的范围、内容优先级和正式验收标准。
- UI/UX Agent：补充竖向布局网格、最小尺寸、溢出策略、降级状态与参考图；说明哪些 Figma 设置仅表达意图。
- Frontend Agent：在规格获批后调整布局判定和 CSS / 组件结构，以代码实现宽高联合约束与剩余空间分配。
- Test Agent：验证目标窗口尺寸、连续缩放、歌词状态、封面比例、控件可用性和布局切换回归。
