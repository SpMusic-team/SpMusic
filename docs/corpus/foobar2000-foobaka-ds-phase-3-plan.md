## 直接交给 DS

> 本轮先拿真实运行证据。请在同一台 Windows 机器上，用官方 foobar2000 2.24.6 x86（A′）和 foobaka Mixture 1.7.12（B）完成三组必做实验：自动播放列表从建规则到改标签、更新和重启恢复；曲库改单首标签的进程级 I/O、根目录离线与恢复；长列表首次到达、同会话回访和同尺寸头图对照。PCM 预检可独立进行，通过后用已知波形分别测两文件续播和同文件 CUE 续播。把第二轮的表项、离线宽限、查询版本和统计键结论订正，再决定 SpMusic 的扫描诊断候选是否值得立项。设备或工具受阻时给出可以直接交接给 Windows 操作者的步骤，并完成其余用例。

第二轮已经交付二进制、SQLite 样本与配置证据，缺少完整的 Windows 行为链。本任务是 P2 研究，正式输出为勘误、行为证据和一张有条件的候选实施卡。继续逆向只针对可重现的运行差异，沿入口、相关状态到模块或调用点定位。全量 PE 或主题拆解、播放器整体移植及候选批量合并列为后续议题。

## 启动与执行顺序

| 顺序 | 执行内容 | 开始与停止条件 |

| 1 | 检索规则与实际改标签，约 45–75 分钟 | 先跑 A′ 的一条完整链，再跑 B 原生能力和主题入口差异。利用同次标签修改记录 I/O。 |
| 2 | 增量对照与离线恢复，约 60–90 分钟 | 先验证 trace 确实采到目标进程和测试路径。完成三组增量对照、一次根目录往返后收工。 |
| 3 | 同任务浏览、封面与头图，约 90–120 分钟 | 先跑一对验证录屏、目标图和计时口径，再完成三对。发现功能缺失或界面阻塞时保留各侧可测数据。 |
| 独立项 | PCM 预检约 30 分钟，抓样通过后做两个接缝 | 正对照和人工插空负对照均可定位才跑音频矩阵。抓样失败登记端点、尝试、错误与接手环境。 |
| 收尾 | 校正基线、写结果与扫描诊断候选，约 45 分钟 | 每项可查到输入、轮次、结果与状态。到时未完成的用例交接后转做独立项。 |

1. **Windows 操作者先做这一步。** 复制 `.rea-analysis/foobar2000-Aprime-2.24.6-x86/` 与 `.rea-analysis/foobaka-lab/` 到两个干净的实验目录，分别保留 profile 副本。用同一个专用测试根导入有明显编号的两首歌。启动 Windows 屏幕录制后，分别点选第二首、滚动一屏并停止录制，回放确认选中项和可见行变化。保存带帧率的短录像、关于页、启动时刻与两个进程 PID。留用既有 B 组件清单及运行前置条件，启动报错就登记具体文字、实际已加载组件和已验证的前置条件。
2. 固定 Windows 版本、缩放、窗口、设备、应用版本与组件 SHA。A′ 与 B 以相同版本和位数做主对照。已有 2.26.x 专用于验证明确的版本差异。优先复用首轮无损夹具和第二轮静态报告，第三轮跑新的 profile 与原始记录目录。会修改标签或挂载状态的用例从同一份冻结清单为两端分别制备测试副本，避免前一轮的改动成为后一轮的输入。
3. 仅凭静态截图无法判断桌面输入是否成功。前台不可用时把 Windows 操作卡交给能运行样本的人，卡中列出样本和准备命令、人工动作、录屏起止、要提交的文件及接受标准。A′ 可用就先做 A′。样本失配、界面能力缺失、工具受阻分别归档。

## 必做实验

### Q1 检索规则完整链

- 准备 12–20 条自制、可核对 ID 的曲目，至少含多值艺人、缺字段与诱饵曲。选一条如 `GENRE HAS Rock AND ARTIST HAS SpmQ3` 的规则，事先固化初始命中、改标签后命中及排序。保留一个同内容的静态快照作为对照。
- 从库检索确认命中后创建自动播放列表。保存显示的完整规则与逻辑曲目 ID。真实修改一条曲目的标签，让它进入或退出规则，查看多久生效、是否需要刷新。随后正常关闭并重开，重新核对同一规则、结果和排序。补一个永不命中的有效条件及一个语法错误条件，记录空结果、报错与是否保留旧规则。静态快照的成员应按其原有语义保持，记录是否出现意外联动。
- 在 A′ 原生入口做全链。B 记录主题快捷入口与可用原生入口，在同一份夹具上复现，分别注明组件。交一段操作录像及每阶段预期/实际 ID 表。验收看建规则、编辑前后结果和重启三环是否都有观察，行为与预期不符也保留实测证据。布尔一项有分歧时，再测试 `ALL`、`NONE` 或一对明确的运算符；保留帮助文档、分发表与行为三个层面的证据。
- 需要定位规则存放位置时，在克隆 profile 上分开做两次单变量干预。一次只改规则写法并保持结果集合相同，一次保持规则并修改标签使结果集合变化。分别在正常退出后比较属性记录和列表快照。仅随规则改变的记录与仅随结果改变的记录分别标注，无法区分时继续保留存储位置未知。

### L1 真实标签编辑与根目录离线恢复

- 用两个专用根和一份 300 条左右的测试清单。预检 Windows 文件活动记录工具，能按进程和运行时间筛出试读测试文件的记录。捕获完整测试窗口内的目标 PID、子进程、路径、操作、结果、读字节与时刻。采集时保留初次导入作为内容读取正对照。
- 从相同基线副本依次跑「不修改后重启」「只改一首 mtime」「只在一首内写入可见的新标签」三场景。写标签前后复读标签并记录 SHA、size 和 mtime，写入工具与播放器进程分开。记录首个可用条目、可搜索时间及最终条目 ID，按目录枚举、属性读取和实际内容读分别汇总，注明内存映射或缓存使哪些读无法确认。只有受控窗口中内容读可见且另一个根未被连带重读时，才就该轮声称改单首触发单文件重读。
- 从已导入状态移除测试挂载或临时断开专用共享，保留原登记的根目录；另一根保持在线。断开前、断开中、离线重启后、同路径重新挂载后分别记录条目、搜索可见性、播放报错、歌单引用及恢复后是否重复导入。以恢复同一路径后的实际 ID、可播放性与条目数闭合。短期往返只说明该时间窗的行为；改数据库时间戳的探索请另存实验副本，标为加速仿真。

### U1 同任务、长列表首达与真回访、头图

- 录制 A′/B 从同一库找到编号曲目并设为下一首的路径，记录交互次数、用时、实际队列与自然切换结果。然后导入带可辨封面编号和已知无图项的至少 300 条列表。固定排序、DPI、窗口、起跳/落点、统计时限、录制帧率与可见图面积。默认布局另存一组观测，计时对照只用可匹配面板。
- 首达跳到该会话未显示的区域，冻结目标屏的有图分母。等目标有图项全部正确后，离开并回到相同落点，方计为一次回访。对首达、回访各做 A′/B 三对交错运行。从松手帧记首个正确封面、90% 和全齐，附超时或错图。报中位数、范围、有效轮次与首末帧号。若无法确定磁盘或内存命中，只记录 profile 的准备状态。
- 用同一张带细线、小字的测试图获取头图原生截图和同区域 1:1 裁片，固定物理像素尺寸、源图和裁剪。至少跑一组嵌入图和目录图冲突，再移除当前优先来源复测。附屏幕位置、像素大小、可辨细节与所选图。没有等价面板时附入口核查，配对指标记为不适用。面板存在但输入或录制失败记为受阻。未确定源图、尺寸或录制置信度时只报告能观察到的现象。

## 独立项 A1 接缝抓样

用目标 Windows 播放端点播放一段带前后定位标记的已知 PCM，尝试环境可用的共享环回或数字回录。把整轨与人为插入固定静音的版本作为预检输入。只有录音能定位两侧标记、区分已知静音长度并确认端点，才运行主实验。记录端点、采样格式、抓样位置、系统混音及误差。共享混音与数字端、模拟端分别陈述测量边界。

复用 `.rea-analysis/p1-seam-fixture/` 的 `A.flac`、`B.flac`、`chirp.flac`、`chirp_dec.wav` 和 `seam.cue`。先核对整轨、分割文件与 CUE 的样本数和边界。A′、B 均先播整轨，再测独立 A/B 文件自然续播，以及同文件两个 CUE 分轨自然续播，每种三次。固定设备、顺序、音量和格式，关闭淡化、EQ、ReplayGain 等信号处理。用两侧定位标记对齐，交原始 PCM、定位脚本、接缝窗、丢样/重样/静音及测量误差。抓样受阻时交触发步骤、边界索引和预检记录，输出接缝状态保持待测。

## 第二轮勘误与实施候选

- **查询表按 12 字节复核。** 对 A′ 的 `0x27BD40` 起始区按 12 字节重列，包括 `ALL 0x27BE0C` 与 `NONE 0x27BE18`。原解读的 `+0x0C` 落到下一条起始项，删除据此推导的别名列。各字段只标注实际确认的含义，运行语法以 Q1 复验。候选清单中的「2.26 新增 ALL」改为「A′ 2.24.6 样本已有表项，2.26.2 补文档」，实际匹配行为另引测试。
- **保留期与恢复语义分开。** 某份 `metadb_indexes` 快照中四条 `retention` 值折算为 28 天，另有相关 SQL 字符串。收窄「28 天内完全无损」「第 29 天自动清理」及路径恢复的绝对表述。用 L1 的实测时间窗说明产品行为，生产环境的清理时机与适用条件保留待验证。
- **统计按各自键核查。** SpMusic 的评分键是 `trackId`，最常播放和最近播放按规范化 `sourcePath`。在当前 SHA 复核代码，路径相同的 CUE 分轨以及重复列表项都作为边界用例。foobar2000 样本中统计字段和索引键的存在，只能先用于定位测试，查询可见性与移动后是否跟随另行验证。
- **本轮只出一张 SpMusic 候选实施卡。** 以现有 `src-tauri/src/audio/playlist.rs` 扫描遇不可读目录时跳过并记录警告的路径为起点。若可稳定复现「扫描完成但只得到部分结果」，先保留已成功条目并为该次扫描汇总失败目录数、可核实的原因类别及脱敏示例，沿当前扫描入口验证。全成功无告警，单子目录被拒时其余目录仍得到相同结果，根级失败维持当前错误语义，日志也应同一批次可核对。首选以已有日志或独立原型验证；若需新增 Tauri 契约或界面展示，按 Architecture 评审、Rust/Tauri 与 Frontend 分开实施、Test 独立验收推进。回滚只撤汇总输出。自动离线保留、索引持久化与统计查询列独立后续任务。

勘误由对应文档 owner 校对，原报告和原始证据保留可追溯。若主实验出现可重现分歧，再为该分歧开一个定点逆向用例，写清输入、输出、候选模块、替代解释和能推翻假设的测试。
