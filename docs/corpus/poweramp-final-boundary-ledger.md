# 插件系统（三十九）：边界终账

## 0. 一句话结论

本轮闭合 `pak-apk Q2`，并把剩余 8 项**逐项定性**。

**结论：8 项中 6 项属硬边界/不可判断，2 项属低价值细节。**
插件系统的**架构层面逆向已完整**。

---

## 1. 本轮新闭合：`Х()` 不含 zip 逻辑

第十三篇遗留"`Х(apkPath, pkg, flag, ...)` 内部如何打开 zip"。
实测 `Х()`（`:1408-1462`，54 行）的**全部方法调用**：

| 行 | 调用 | 用途 |
| ---: | --- | --- |
| `:1411` | `TextUtils.isEmpty(pkg)` | 参数校验 |
| `:1417` | `TextUtils.isEmpty(apkPath)` | 参数校验 |
| `:1429` | `Uri.encode(pkg)` | 构造去重键 |
| `:1433/1435` | `StringBuilder.append/toString` | 拼 `apk://<pkg>` |
| `:1441` | `HashSet.contains(uri)` | **去重** |

> **没有 `ZipFile`、没有 `ZipInputStream`、没有任何 IO。**
> 真正的 zip 枚举在 `у()` 里由 **native** 完成（第十四篇）。

### 1.1 `Х()` 的完整职责

```
Х = 参数校验 + URI 构造 + 去重 + 转调 у()
```

> 它是一个**薄包装**，不含任何扫描逻辑。

### 2.1 关于 `bit4` 的新证据

查 `preference/H.smali`（177 行）：

| 检查 | 结果 |
| --- | --- |
| 数值常量 | **0 个** |
| 结构 | **纯字段容器**（19 个 fastpref 字段） |

> **`H` 只持有偏好引用，不参与位运算**。
> 因此 `0x10` 不可能在 `H` 里被设置——
> 它要么来自 `i.А()` 之外的合成路径，要么由 native 注入。
> **判定为不可从静态产物判断**。
