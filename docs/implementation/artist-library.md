# 媒体库艺术家分类实现

## 数据与成员

`artistLibrary.ts` 从现有选中存储的 `allSongs` 派生艺术家，沿用真实歌曲 key、scope、trackId。摘要新增 `libraryArtistName?: string | null`，分别表示未读取、已完成但缺失、有效原始 ARTIST。mapper、行相等比较和 PlayerShell 的水合展示覆盖均保留该字段，避免 ARTIST 缺失而 ALBUMARTIST 存在时误建同名艺术家。

当前拆分规则为 `/`，逐段 trim、去空、去重，保护完整片段 `AC/DC` 和 `+/-`，也保护它们处于合作串中的情况；`XAC/DCY` 仍按普通分隔符拆分。逗号、`&`、`feat.` 不额外拆分。Poweramp 参考资料证明了可配置拆分及例外机制，没有证明其默认分隔符；本实现采用项目已批准基线，不声称已提供其全部扫描设置。

缺失 ARTIST 归“未知艺术家”，与真实标签为“未知艺术家”的实体拥有不同 key。未完成摘要不创建未知实体。每首合作曲可以归属多位艺术家，根页选择多个艺术家播放或随机时按 song.key 去重，保留第一个真实描述符。

艺术家内专辑由 `albumEntries(artist.songs)` 生成，沿用已有专辑身份和目录后备。合辑中的其他艺术家独唱不会进入当前艺术家的专辑详情或队列。所有歌曲也包含缺失专辑名的曲目。

## 页面与导航

`AlbumLibraryPanel` 通过显式 `categoryId="artist"` 复用集合头图、控制器、卡片、索引、歌曲窗口、实体窗口、封面缓存及租约。根页使用圆形本地曲目封面和居中名称，分类图标复用已有 `media-library/feb56.svg` 麦克风资产；没有封面时显示该分类占位。设计稿中的人物照片属于动态数据示意，不作为静态艺人资料，不新增联网图片来源。

设计依据来自 Figma 节点 `8018:16827` 的高保真上下文及随附截图，session 为 `b3f93b8f-a4a3-4e6d-bd92-3d6948fe8eb7`。默认大卡片按设计使用 280px 圆形封面、15px 内边距、26px 封面与名称间距和 32px 名称；窄窗口缩小为两列。其余布局档位复用现有集合布局交互和主题变量。

PlayerShell 独立保存 `artistLocation`：根页为 null；进入艺术家默认为 `albums`，头图下、专辑之前的“所有艺术家歌曲”入口进入 `songs`；专辑卡片进入带 artistKey 和 albumKey 的 `album`。返回依次为歌曲或专辑详情 → 艺术家专辑 → 艺术家根页 → 媒体库。从播放器返回保留当前会话位置；各层 route 包含艺术家身份，搜索、选择、滚动和动画身份彼此隔离。

内层页按 Figma 节点 `8114:18993` 的高保真上下文对齐。所有艺术家歌曲入口使用125px圆形真实曲目封面，复用当前艺术家头图代表曲目、缓存和租约；入口左右40px、上下15px内边距，封面与信息间距15px。右侧两行间距4px：标题28px/36px，24px原始音乐图标与“实际数量 首歌曲”采用24px/32px及主题 `--player-inverse-primary`。音乐图标从该节点下载为 `src/assets/artist-library/24b9a.svg`，保持原始24px尺寸，没有临时资产URL。艺术家内默认大专辑卡维持240px封面，名称与作者字号直接复用媒体库专辑分类同布局档位，不再使用艺术家页面独有的32px/24px覆盖；网格横向48px、纵向22px。局部头图为320px高、左右25px等距，宽屏也完整铺开；歌曲数与总时长紧接艺术家名下方，操作按钮位于统计之后。其他分类不受这些局部头图样式影响。

艺术家根页、专辑层和歌曲层分别保存布局偏好。读取摘要、目录恢复或重扫期间保留位置及加载状态，禁止基于临时成员播放；数据稳定后当前艺术家消失则回根页，仅专辑消失则回该艺术家专辑层。离场场景 inert，不能清理新场景位置。

## 验证

- `artistLibrary.model.test.mjs` 覆盖原始标签、拆分边界、多对多归属、选择去重、专辑成员及导航身份。
- `artistLibrary.browser.test.mjs` 使用实际 PlayerShell 和模拟原生命令，覆盖默认专辑视图、所有歌曲、合辑播放边界、选择队列、播放器返回、未知实体、pending 和过时摘要取消。设置 `SPMUSIC_TEST_WIDTH` 指定窗口宽度，`SPMUSIC_TEST_SCREENSHOTS` 保存截图，`SPMUSIC_TEST_MOTION=1` 启用动效验证。
- 原专辑模型及实际 PlayerShell 浏览器回归均通过；摘要 mapper 的既有测试同步保留原始艺术家字段断言。
- 构建与 lint 通过；独立验收结果由 Test Agent 记录。

## 边界

本次未新增 Rust command、数据库、依赖、权限、标签写入或队列来源。专辑艺术家分类、用户可配置拆分设置和在线艺人图片不在本次实现范围。

## 索引叠加层

所有歌曲、播放列表、文件夹、专辑与艺术家共用 `CollectionQuickIndex`。索引及拖动预览是滚动内容区域之外的绝对定位兄弟节点，不参与内容宽度和网格列数计算。索引自身接收指针事件，预览不拦截指针；没有全屏命中层。移除了所有歌曲列表原先左右24/40px、窄屏16/28px的不对称预留，现分别为左右24px和16px；其他分类原有设计内边距保持不变。索引显隐不得改变卡片边界或虚拟窗口列数。

## 实体封面与虚拟窗口

原封面观察逻辑假设 `list.children` 与 `renderedItems` 等长、逐项对应。实体页传入的观察区域包含头图、入口和嵌套虚拟网格，不能满足该结构；虚拟窗口外艺术家滚入后新节点没有注册，因而没有缩略图请求。原先按歌曲 key 只保存一个 DOM 节点，也不能表达同一资源在多个可见位置的需求。

`useAllSongsWindow` 现在按 HTMLElement 注册当前已挂载节点，在窗口或描述符变化时重新协调观察集，滚动时仅测量已请求资源的登记节点。每个资源 key 可以关联多个节点，IO 相交状态按节点维护，再聚合为资源需求；任一副本可见时，其他离屏副本不会撤销其请求。排序为每个资源选择实际可见、再按距离最近的节点，不在每次滚动时扫描全库 DOM。节点上的 `data-cover-key` 优先于 `data-song-key`，同一节点只登记一次。

专辑、艺术家及艺术家内专辑使用已有 `track-candidates` 描述符，分别以实体身份生成封面资源 key。候选包含真实 native trackId、sourcePath、可用状态与 artworkRevision。首曲没有封面时依次尝试后续可用曲目；缓存、过时完成校验和取消仍使用既有缩略图调度器。根卡片、头图和所有艺术家歌曲入口订阅实体资源，头图与入口共享当前艺术家候选及租约。原 `data-song-key` 与播放歌曲身份保持不变；全局专辑与按艺术家限制成员的专辑资源彼此隔离，避免互相覆盖。候选变动不能让旧请求回写新实体封面。

## 艺术家头图更多菜单

艺术家根页保留 `LibraryRootMenu`；内层头图及浮动控制器复用 `PlaylistHeroMoreMenu` 的填充圆形按钮与封面信息叠加层。共享组件只新增可选 `contextLabel` 和 `actions`，未传入时保留原播放列表七项动作及说明。艺术家按钮为42px容器和32px图标，叠加层展示当前艺术家的真实实体封面、名称、歌曲数和总时长。菜单封面沿用实体候选和缓存；弹层挂载期间保留租约及单实体观察窗口，避免从浮动控制器打开时因头图已离屏而缺失封面需求。

五项操作分别是选择文件夹、重新扫描、封面、侧栏置顶和列表选项。前两项调用已有媒体库回调并遵循忙碌/能力缺失禁用状态；侧栏置顶沿用现有 `artist` 分类置顶及取消语义，没有新增单个艺术家持久化。封面和列表选项继续展示明确的未接入说明。打开文件夹对话框时使用共享菜单的 transferring 状态撤下旧焦点陷阱，与根菜单现有交接方式一致。叠加层及根菜单各自保留正确的上下文语义，播放列表调用方默认行为保持不变。

头图更多展开层按动作内容自然增高，移除了旧592px固定高度和专用滚动条。正常视口中艺术家五项和播放列表七项可完整呈现；超过可用视口高度时，仅对话框本身使用原生滚动，不裁剪操作，也不嵌套两个滚动区域。已有键盘焦点和对话框交接保持不变。

头图及其更多菜单统一复用 `playlistDuration.ts` 中的 `formatDurationClock`：不足一小时显示 `26:36`，满一小时显示 `1:26:36`。播放列表原有 `formatPlaylistDurationLabel` 已使用此格式；艺术家、专辑和文件夹的总时长改为调用同一函数，保留原有真实秒数聚合、可用曲目范围及尚未读到时长时的加载/未知语义。单曲播放器和歌曲行格式不在这次修改范围内。

## 艺术家所有歌曲头图

`artistLocation.view === 'songs'` 按 Figma 节点 `8117:19352` 单独呈现：左上返回按钮仍显示当前艺术家名并返回该艺术家专辑层；底部标题固定为“所有艺术家歌曲”，使用16px/24px中等字重圆角标签，左右15px、上下2px内边距。标题下为原始16px音乐图标 `playlist-library/77262.svg` 与真实“N 首歌曲”，最下方保留播放、随机、搜索、选择及右侧更多。内容始终按纵列及5px间距排布，宽屏不会把计数推至右侧。

该歌曲视图头图按新设计只显示曲目数，不附加总时长；更多菜单仍显示当前艺术家真实曲目数及统一格式的总时长。头图高320px、左右25px等距铺满，主题颜色、正确返回矢量、实体封面及返回作用域保持一致。歌曲列表保留原有16px/25px响应式内边距、用户布局偏好和虚拟窗口，其他艺术家层级及全局专辑页面不受这些专属样式影响。

## 共享专辑详情

全局专辑详情和艺术家内专辑详情均以 `data-album-detail` 标记，按节点 `8134:19952` 复用同一套局部样式。320px头图左右25px等距铺满；底部信息纵向5px间距，专辑名继承标准头图字号（窄屏24px/32px、宽屏22px/28px），作者及数量/总时长使用16px/24px中等字重标签，标签均保留左右15px上下2px内边距，数量使用已有16px音乐矢量。年份来自真实标签摘要，不使用设计示例年份。全局返回专辑根，艺术家内返回当前艺术家，曲目成员及队列作用域不变。

全局专辑头图更多菜单改为复用 `PlaylistHeroMoreMenu`，显示当前专辑真实名称、成员统计和实体候选封面；五项操作沿用选文件夹、重扫、封面说明、`album` 分类侧栏置顶及列表选项说明。艺术家内专辑更多菜单仍保留已批准的艺术家上下文，统计及封面来自该艺术家成员，侧栏置顶也仍指向 `artist`。根分类菜单不受影响。

默认大行档继续复用现有 `PlaylistCard` 和布局控制器，封面135px、内边距15px、封面文字间距24px、行间距20px；该专辑详情档仅将标题、作者和格式文字局部对齐为28px/36px、22px/28px、16px/24px。用户已保存的其他档位、缩放交互、歌曲虚拟窗口和封面租约保持不变。

## 专辑真实年份

只读摘要DTO新增 `year: number | null`，由Rust与既有标签读取同源提供。前端parser兼容旧响应省略字段；0、负数、小数、非数字及超出u32范围的值仅将year归一化为null，不影响整批其余有效摘要。`libraryYear?: number | null` 沿原始标签通道保存，undefined表示尚未读取，null表示本轮缺失/失败；摘要mapper、行相等比较、view model及PlayerShell补水展示覆盖均保留该字段，正在播放曲目或系统年份不能替代它。

`albumEntries` 只对当前专辑成员的有效年份去重。有效集合恰好一个年份时，头图信息栏追加 ` | YYYY`，允许其他成员缺失；无有效年份或多个冲突年份时直接省略该项及分隔符，不显示未知或不一提示，不擅取首曲、最早或当前播放年份。艺术家内专辑依据其匹配成员独立聚合。year不参与专辑身份，年份补齐不会改变key、导航或队列scope。
