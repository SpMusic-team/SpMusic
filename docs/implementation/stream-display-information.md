## 名称与数据

`Track`、摘要和歌曲视图模型使用可选 `stream: { url, stationName? }`，地址不存入艺术家或专辑字段。名称顺序为流根注册表显式名称、当前播放列表显式名称、电台名、有效元数据或文件名、原始地址。HTTP(S) 地址形式的标题作为兜底，不压过已发现的电台名。流的专辑与艺术家为空，不虚构时长。

后端 `stationName` 经既有 Ready 事件传递；前端先验证既有请求和 selection fence，再接受名称。本会话按 URL 保留已接受的名称，缓存写入失败后读取旧列表也不会使名称退回。摘要指纹包含流标题和电台名，名称变化更新搜索、排序和当前播放展示，歌曲身份仍是原有 id 与地址。

接受名称后使用既有读取命令刷新一次。添加、删除和导入期间先标记待刷新，变更完成后执行，避免后台读取递增同一 generation 导致变更结果丢失。观察名称只合并返回列表中已有成员，不能把已删除地址加回。

## 虚拟列表

流行使用独立内容形状 31；共享卡片样式代表扩展至 32 个，普通歌曲仍使用原有 0–15 形状。只隔离内容高度测量代表，虚拟窗口调度和选择逻辑不变。

## 验证

`streams.model.test.mjs` 验证名称优先级、非字符串可选字段降级、地址保留、无伪造专辑与时长，以及流与普通歌曲的内容形状隔离。独立 Test Agent 负责十种布局、混合歌曲列表、名称事件和变更并发的浏览器回归；最终构建与 lint 由主协调 Agent 执行。
