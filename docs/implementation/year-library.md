# 年份分类页面实现

## 浏览与数据

`yearLibrary.ts` 从已选择文件夹的真实 `allSongs` 派生年份分类，并合并重复歌曲 key。有效的原始年份始终优先；已完成但缺失或无效的年份，继承完整专辑已有的最早有效年份。`undefined` 始终表示 pending，不参与推断。按用户后续要求，年份分类只展示最终具有有效年份的歌曲：pending 及继承后仍无年份的歌曲均不生成年份入口，不再提供“未知年份”。默认按年份从新到旧排列。

年份根进入年份专辑视图，同时提供“所有年份歌曲”入口。全部歌曲按上述有效年份筛选；专辑先使用完整曲库的 `albumEntries` 聚合，再按专辑年份筛选，专辑详情保留完整成员。`yearAlbums(albums, null)` 始终返回空数组。`yearEffectiveYears` 从完整专辑的最终 `album.songs` 成员建立歌曲 key 到派生年份的映射，保留专辑的细分身份及 `null` / pending 语义；仅年份展示投影排除无有效年成员。分组、统计、全年歌曲播放及按年排序均使用相同有效年规则。原始歌曲对象及 `libraryYear` 不会被改写，全库和其他分类保留所有歌曲。专辑年份沿用 SpMusic 已有的最早有效成员年份规则；本次没有新增专辑标签或后端协议。

`PlayerShell` 持有 `yearLocation`，摘要、时长及歌曲合并门控纳入年份分类。从播放器返回保留当前年份、分支及专辑。重扫、恢复、导入和摘要读取期间保持加载状态，稳定数据不再包含当前年份或专辑时逐级退回；旧未知年份位置在数据稳定后按同一逻辑回到年份根。只有无年份歌曲时显示既有空状态，不清理曲库。场景滚动位置按完整 route 保存。

## 同目录合辑修复

2026-11-03 对用户两份实际文件只读检查发现：`「吾导先路」殉道者（第五个）.flac` 的 ARTIST 为 Mentalmeisters、DATE 为 2022；`「如我所见」夜幕.mp3` 的 ARTIST 为塞壬唱片-MSR、无年份。两者均在 `E:/Music`，ALBUM 同为《明日方舟》游戏原声OST，均没有 ALBUMARTIST。原先把 ARTIST 回退为专辑身份，导致这两首歌先被拆为不同专辑，缺年份成员无法继承另一个实体的 2022。

经用户确认，修复统一的 `albumEntries` 身份源头：命名专辑缺少或空白 ALBUMARTIST 时使用专辑名和规范化直接父目录，不再以 ARTIST 拆分；有显式 ALBUMARTIST 的专辑仍按名称与规范化署名跨目录合并。两类身份互相隔离，缺少 ALBUMARTIST 的不同目录也不因同 ARTIST 间接合并。合辑副标题汇总并稳定排序原始 ARTIST；原文件、曲目标签和播放身份不变。年份模型继续复用最终专辑成员，故两首曲目归入 2022，无需另建跨实体借年规则。有效原始年保持优先，pending 不继承；专辑视图仍保留完整成员。

实际标签等价回归在修复前以 `albums.length: 2 !== 1` 失败，修复后通过，并覆盖输入乱序、重叠扫描、不同目录及显式专辑艺术家隔离。

## 组件与设计

`AlbumLibraryPanel` 使用显式年份分支，复用现有集合标题、hero、动作、歌曲卡片、侧栏、封面 store、虚拟窗口及布局手势。年份根默认采用小封面行布局：64px 封面、88px 行、16px 间距、24px 年份与14px曲数/时长统计；640px 窗口下标题为57px，分类圆84px。布局缩放仍沿用四个独立的集合偏好作用域。

年份专辑和“所有年份歌曲”两页由头图自身的 25px 水平 margin 统一控制左右边距，二者的滚动容器均清除继承的水平 padding。此前只有专辑页清除 padding，歌曲页额外叠加共享文件夹样式的 16px（宽窗 25px），使切换页面时头图变窄。本次修复局限于年份两条分支，不改变其他分类。

年份专辑页的歌曲数与时长统计条显式设置 `align-self: flex-start`，与年份标题保持左边对齐。其 copy 已切换为纵向 flex，而共享桌面头图样式仍给统计条设置 `align-self: center`，造成宽窗中统计条漂到头图中央；本次在年份专辑分支覆盖该交叉轴对齐，不改变统计条内部垂直居中、字号或其他分类。

年份、艺术家、专辑艺术家与作曲家专辑页统一复用共享头图布局的 25px 顶部外间距。原先贡献者 albums 分支将头图后的 layout 容器 `margin-top` 单独覆为 0，导致全部歌曲入口背景紧贴头图；移除该覆盖后，四类页面的入口背景顶部均与头图底部相隔 25px。间距由父容器的外边距提供，不加入按钮内部 padding，也不改变入口与下方专辑列表的距离、水平边界、歌曲页或布局档位。

除下述带图专辑行（level 3/4/5）外，头图下方两条分支按可见封面/文本而非透明卡片外框对齐：列表水平 padding 与卡片自带 padding 相加为头图的 25px 外边距，文本、普通封面和小封面布局分别补足对应差额。平铺从左开始，歌曲平铺封面不再在单元格内额外居中；保留现有列数、卡片尺寸与虚拟窗口高度计算。年份专辑页的“所有年份歌曲”入口封面复用 `--app-radius-lg` 改为圆角方形。

用户随后纠正带图专辑行的对齐基准：`FOLDER_CARD_LAYOUTS` level 3（row-wide / large，封面 165×165）、level 4（row-wide / medium，107×107）及 level 5（row-compact / small，64×64）统一以**真实可悬停按钮外缘**对齐头图外缘，替代上段对这些档位的“封面起点对齐”规则。年份及艺术家、专辑艺术家、作曲家页的 albums 带图行列表与全部歌曲入口均使用 25px 外边距，按钮内部仍保留 15px padding，因此封面位于 40px，悬停框位于 25px。选择器按 `data-folder-flow='row'` 和父层 `data-layout-flow='row'` 覆盖全部行档，避免只按 level 4 修复而漏掉大行或小行。此调整与播放列表歌曲条目相对头图的关系一致；平铺、文本及年份 songs 分支继续保持原布局，虚拟窗口高度和封面尺寸不变。带图行验收应比较按钮外框与头图左右边缘，旧的这些档位“封面等于头图起点”断言不再适用。

“所有年份歌曲”和艺术家、专辑艺术家、作曲家的全部歌曲入口统一使用真实按钮布局约束悬停/键盘 focus 框，不使用背景伪元素。入口按钮外边距匹配下方列表的水平 padding，宽度减去两侧相同外边距，内部横向 padding 匹配相应卡片；四类页面带图行均使用上述 25px 外边距和 15px 内边距。其余年份档通常为 10px 外边距加 15px 内边距，小平铺封面档为 20px 加 5px。艺术家等页面平铺外边距为 25px，窄窗平铺为 16px，小平铺封面档横向内边距为 5px；纯文本布局保持既有设置。入口使用普通专辑条目的主题圆角 `--app-radius-lg * 5 / 6` 与上下 15px 留白，保留原封面尺寸和自然内容高度，继续消费既有 ghost 按钮的悬停颜色和 focus ring。

## 分类侧栏滚动

分类切换时 `PlayerSurface` 用分类 key 更换面板，各面板的 `PlaylistLibrarySidebar` 和分类 nav 随之重新挂载；原来没有独立保存 nav 的滚动位置，导致新 nav 默认回到 0。这与主内容按路由保存的位置不同。

`useLibraryChromeTransition` 在常驻 `PlayerSurface` 会话中持有分类 nav 的位置 ref，通过稳定的 `categoryScroll.read/write` 接口供侧栏消费，分别保存 desktop 和 overlay 的位置，不按分类分桶、不写 localStorage。侧栏在 nav 滚动及点击捕获阶段同步记录，在挂载的 layout effect 恢复；带清理的 ResizeObserver 仅在 nav 从零高度恢复可见时重新恢复，覆盖窄窗切宽窗的 desktop 重现。只允许仍 present 且 nav 高度大于 0 的可见实例读写，防止退出动画或隐藏 desktop 迟到的零滚动事件污染有效位置。卸载时不写回，不增加延时，不改变 focus、键盘事件、动画 key 或主内容滚动。播放列表区域的独立滚动不在本次范围。

Figma 的年份图标、统计音符及根更多图标分别保存为 `src/assets/year-library/1fed4.svg`、`36e6f.svg`、`1e93b.svg`。通用返回、播放、随机和搜索资产复用已有精确资源；设计示例封面由真实曲目封面替代。没有临时 Figma URL 进入运行代码。颜色与圆角消费现有主题变量，窗口顶栏与底部播放控制器保留既有行为。

## 排序与播放

年份根更多弹窗仅保留“选择文件夹”“重新扫描”“列表选项”，不展示重新排序或置顶；“列表选项”继续使用既有未接入提示。根原有排序缓存保留，默认仍为年份降序。子层更多菜单及排序操作保持不变，偏好分别保存到 `spmusic.year-{root|songs|albums|album-tracks}.sort.v1`。专辑支持名称、作者、年份、歌曲数；歌曲支持名称、艺术家、专辑、年份、时长。各视图可独立选择升降序，不添加原始数据缺少的添加时间排序。排序字段与方向均校验后读取，无效或不可用存储回退到默认值。

播放和随机继续调用现有 `onPlaySong`、`onShufflePlay`，只展开当前分支及选择后的有效成员，传递原始 `scope/trackId`。年份根按派生有效年份成员展开，年份专辑视图按可见专辑的完整成员展开。搜索按钮沿用项目全局搜索页面及其实际结果队列。

年份专辑入口与歌曲页头图统一显示“所有年份歌曲”。歌曲页右侧复用 `CollectionQuickIndex`，标签为“歌曲快速查找”，索引名称来自当前排序、筛选后的 `visibleSongs` 标题。普通列表按实际歌曲 slot 定位；超过 100 首且启用窗口化时，按完整成员索引、布局列数及已测量 stride 定位到虚拟空间中的目标行，不查询尚未渲染的曲目。字母无匹配时保持当前位置，顶部入口回到滚动容器起点；数字、其他字符、指针拖动与键盘行为继续由共享组件提供。该入口只增加在年份歌曲页，不改变年份专辑或其他分类的索引。

## 验证

实现阶段已运行 `npm run build`、`npm run lint`。独立的模型与浏览器验收由 Test Agent 执行，覆盖混合年份专辑、四个排序作用域、播放候选、返回、加载/重扫与清理，并记录窄/宽窗口的设计几何证据。最终结果以测试报告和主代理仓库级检查为准。
