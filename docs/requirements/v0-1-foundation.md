# 需求分析：v0.1 播放界面

## 摘要

v0.1 的目标是建立 SpMusic 的最小可验证播放界面，而不是实现完整音乐播放器。该版本从 `docs/requirements/总需求分析.md` 中切出项目身份、播放界面、前端状态和基础验收流程，确保后续 PM Agent 可以在清晰边界内制定 Sprint 计划和任务拆分。

## 用户问题

当前项目仍处于模板应用形态，无法体现 SpMusic 的产品定位，也缺少后续开发所需的播放界面、假歌曲结构、前端状态和验收边界。如果直接从最终产品愿景进入播放列表、真实音频播放、文件读取、媒体库、网络存储或插件系统，会导致范围过大、架构决策前置和验收标准不清晰。

## 目标用户

- 需要确认 SpMusic 项目方向和版本边界的项目维护者。
- 需要基于明确需求开展计划拆分的 PM Agent。
- 需要在播放列表、真实播放和媒体库之前验证播放界面的 Frontend Agent、UI/UX Agent 和 Test Agent。

## 用户场景

- 用户启动桌面应用后直接进入播放界面，看到应用内容，而不是开屏页、品牌展示页或 Tauri / React 模板页面。
- 用户看到播放界面，界面展示当前歌曲信息和基础播放控制。
- 用户点击播放 / 暂停、上一首、下一首后，界面状态发生可预测变化。
- 用户在没有真实音频文件、文件读取和媒体库的情况下，也能验证播放界面和状态流转。

## 优先级建议

P0。

v0.1 播放界面是后续虚构播放列表管理 UI、真实播放、媒体库、真实播放列表和扩展能力进入计划前的前置条件；如果该需求未完成，目标版本的后续任务无法稳定拆分和验收。

## 版本建议

建议进入 v0.1。该版本只承接最终需求中的项目身份、播放界面和前端状态验证部分，不承接虚构播放列表管理 UI、真实音频播放、本地文件读取、媒体库、真实播放列表、网络存储、数据库或插件系统。

## 范围

- 项目身份从模板项目收敛为 SpMusic，但不要求专门的开屏页、Logo 展示页或品牌介绍页。
- 播放界面，用于展示当前歌曲信息和基础播放控制。
- 演示歌曲数据，至少包含 5 条虚构歌曲信息。
- 当前歌曲展示。
- 播放 / 暂停 / 上一首 / 下一首的前端 UI 状态切换。
- 最小 `PlayerState` 或等价前端状态结构。
- 最小 `Track` 或等价假歌曲结构。
- 空歌曲列表 Empty State。
- 基础工程验收命令和人工检查清单。
- README 或需求索引中的 v0.1 范围说明。

## 不在范围内

- 真实音频播放、音频解码、音量控制、播放进度拖动。
- 本地文件读取、文件夹选择、本地文件夹扫描、媒体库索引、元数据解析、封面和歌词。
- 数据库、缓存层、迁移系统和持久化媒体库。
- 虚构播放列表管理 UI，包括展示、创建、编辑、删除、排序虚构播放列表和管理歌单内歌曲条目。
- 播放列表真实创建、编辑、导入、导出和 `m3u8` 支持。
- 真实歌单管理，包括新建歌单、删除歌单、编辑歌单和持久化歌单内容。
- 最小 Tauri command 或 React 到 Rust 通信验证。
- FTP、SMB、WebDAV 网络存储播放。
- Last.fm、Pano Scrobbler、云同步、自定义功能区。
- 插件系统、插件市场、插件运行时和插件 API。
- 复杂主题编辑器、复杂动画系统和高级音频 DSP。

## 假设

- v0.1 以当前 Tauri + React + TypeScript 项目为基础推进。
- 演示歌曲数据只用于播放界面和状态验证，不代表真实媒体库数据结构，也不代表后续正式的内置播放队列模型。
- v0.1 不要求跨平台行为细节完全定义，只要求基础构建与本地运行链路可验证。
- PM Agent 后续会基于本文档拆分 Sprint 计划和实现任务卡。

## 依赖

- `docs/requirements/总需求分析.md`：作为最终产品愿景和长期范围来源。
- `docs/requirements.md`：作为需求索引和版本状态汇总。
- `agent-prompt/agents.json`：用于确认后续可参与 Agent 及职责边界。
- Architecture Agent：如播放器状态结构、假歌曲结构存在争议，应先给出边界建议。
- UI/UX Agent：如播放界面、交互状态和 Empty State 需要进一步细化，应单独产出 UI 规格。

## 功能需求

- FR-001：应用启动后必须直接进入播放界面，不得先显示专门的开屏页、Logo 展示页或品牌介绍页。
- FR-002：应用必须提供播放界面。
- FR-003：播放界面必须展示当前歌曲信息。
- FR-004：当前歌曲必须展示歌曲名、艺术家、专辑、时长中的至少 3 类信息。
- FR-005：播放界面必须提供播放 / 暂停、上一首、下一首控制。
- FR-006：播放 / 暂停控制必须只改变前端 UI 状态，不触发真实音频播放。
- FR-007：上一首 / 下一首必须基于演示歌曲数据切换当前歌曲。
- FR-008：演示歌曲数据必须至少包含 5 条虚构歌曲信息。
- FR-009：当前歌曲必须有可识别标记。
- FR-010：前端必须存在最小 `PlayerState` 或等价状态结构，表达当前歌曲、播放状态和演示歌曲数据。
- FR-011：前端必须存在最小 `Track` 或等价假歌曲结构，表达演示歌曲字段。
- FR-012：演示歌曲数据为空时必须展示 Empty State。

## 非功能需求

- NFR-001：v0.1 核心验证不得依赖网络。
- NFR-002：v0.1 不得引入真实音频播放依赖。
- NFR-003：v0.1 不得读取用户本地文件，不得请求文件系统扫描权限。
- NFR-004：v0.1 不得引入媒体库持久化、数据库或迁移系统。
- NFR-005：v0.1 不得为了未来能力引入复杂插件、数据层或音频引擎抽象。
- NFR-006：验收必须能通过构建命令和人工 UI 检查完成。
- NFR-007：界面文案应避免继续保留模板项目的主要可见内容。
- NFR-008：状态切换应在无真实音频文件的环境中可重复验证。
- NFR-009：项目身份要求仅用于去除模板痕迹和明确应用归属，不应被实现为额外的品牌页或启动页。

## 输入与输出

- 输入：固定演示歌曲数据、用户对播放控制按钮的点击。
- 输出：播放界面、当前歌曲信息、播放状态、当前歌曲标识、Empty State。

## 关键规则

- 演示歌曲数据仅用于 UI 和状态验证。
- v0.1 中的演示歌曲数据不等同于后续正式的内置播放队列。
- v0.1 不展示虚构播放列表管理 UI，不代表真实歌单管理、媒体库或 `m3u8` 能力已经进入范围。
- v0.1 不要求展示完整歌曲列表；至少 5 条虚构歌曲信息用于当前歌曲展示、上一首 / 下一首和空状态分支验证。
- 播放控制仅改变 UI 状态，不播放真实音频。
- v0.1 不访问音乐文件、不扫描目录、不写入数据库。
- 应用启动后的第一屏应是可用的播放界面内容，而不是单独的品牌识别页面。
- 演示歌曲数据为空时应用不能崩溃。
- 单曲演示歌曲数据下，上一首 / 下一首不得导致当前歌曲变为无效状态。
- 任何超出 v0.1 范围的能力必须交由 PM Agent 判断是否延期或另行分析。

## 边界情况

- 演示歌曲数据为空。
- 演示歌曲数据只有 1 首歌曲。
- 用户连续点击播放 / 暂停。
- 用户连续点击上一首 / 下一首。
- 当前歌曲不存在或队列数据异常。

## 异常情况

- 空歌曲列表时，播放 / 暂停、上一首、下一首不得导致界面崩溃。
- 当前歌曲索引越界时，界面不得渲染未定义字段。

## 数据或权限约束

- v0.1 不读取用户本地音乐文件。
- v0.1 不请求文件系统扫描权限。
- v0.1 不保存用户音乐数据、播放历史或播放列表。
- v0.1 不要求用户登录账号。
- v0.1 不访问在线音乐服务或第三方音乐 API。

## 验收标准

- `docs/requirements/v0-1-foundation.md` 存在，并包含范围、不在范围内、功能需求、非功能需求、边界情况、风险和验收标准。
- 应用启动后直接显示播放界面内容，而不是 Tauri / React 模板页面、开屏页、Logo 展示页或品牌介绍页。
- 应用存在播放界面。
- 播放界面展示当前歌曲信息。
- 当前歌曲展示歌曲名、艺术家、专辑、时长中的至少 3 类信息。
- 播放界面存在播放 / 暂停、上一首、下一首控制。
- 系统存在至少 5 条虚构歌曲信息用于播放界面状态验证。
- 点击播放 / 暂停后，播放状态能在 `paused` 与 `playing` 或等价状态之间切换。
- 点击上一首 / 下一首后，当前歌曲能基于演示歌曲数据切换。
- 当前歌曲有可识别标记。
- 演示歌曲数据为空的分支存在并可渲染 Empty State。
- `npm run lint` 通过。
- `npm run build` 通过。
- 真实音频播放、本地文件读取、媒体库、真实播放列表、网络存储和插件系统未进入 v0.1 实现范围。

## 开放问题

- 演示歌曲数据应放在组件内、独立 fixture 文件中，还是由 UI 状态模块提供？
- 播放控制按钮在 v0.1 中使用文字、图标还是图标加文字？
- Empty State 是否需要由 UI/UX Agent 先定义具体文案和视觉状态？

## 风险

- 模板内容残留会影响应用内容验收，但不应因此引入专门的品牌展示页。
- 总需求范围很大，容易把真实音频播放、媒体库或真实播放列表提前塞进 v0.1。
- 最小 Tauri 通信验证移出 v0.1 后，前后端通信风险会后移到 v0.3 或后续工程验证任务。
- 如果最小状态结构设计过度抽象，可能提前引入未来音频引擎或媒体库复杂度。
- 如果 UI 规格缺失，实现时可能出现播放界面范围不一致。

## 建议

建议 PM Agent 基于本文档维护 Sprint 计划和任务卡。若状态结构、假歌曲结构或播放界面布局在拆分任务前仍不清晰，建议先交由 Architecture Agent 和 UI/UX Agent 做最小边界确认。虚构播放列表管理 UI、真实音频播放、文件读取、媒体库、真实歌单管理、真实播放列表、网络存储和插件系统应保持 Deferred，等待后续版本单独分析和批准。
