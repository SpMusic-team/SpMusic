# 需求分析：v0.2 虚构播放列表管理 UI

## 摘要

v0.2 的目标是在 v0.1 播放界面完成后，使用假数据建立可运行、可验证的播放列表管理 UI 原型。该版本支持对虚构播放列表进行展示、创建、编辑、删除和排序，也支持对歌单内歌曲按默认顺序、歌曲名称、时长等规则排序，在默认排序下手动调整歌曲顺序，支持从一个播放列表选择一个或多个歌曲加入到其他一个或多个播放列表，并支持从虚构播放列表中移除选中歌曲；不读取本地文件，不实现真实音频播放，不做播放列表持久化、导入导出或 `m3u8` 支持。

## 用户问题

v0.1 只能验证播放界面，无法表达用户管理多个播放列表和从播放列表中选择歌曲的基础路径。v0.2 需要在不引入真实文件、媒体库、数据库和持久化逻辑的前提下，先验证播放列表管理 UI 的信息结构、操作入口、状态变化和边界情况。

## 目标用户

- 需要管理多个播放列表入口的普通用户。
- 需要验证播放列表 UI 信息结构和交互边界的项目维护者。
- 需要基于明确范围实现 UI-only 原型的 UI/UX Agent、Frontend Agent 和 Test Agent。

## 用户场景

- 用户打开应用后，可以看到虚构播放列表列表。
- 用户可以创建一个新的虚构播放列表，并在当前会话中看到它出现在列表中。
- 用户可以编辑虚构播放列表的基础信息，例如名称。
- 用户可以删除某个虚构播放列表，并看到列表状态变化。
- 用户可以调整虚构播放列表的显示顺序。
- 用户选择某个虚构播放列表后，可以看到该播放列表内的虚构歌曲。
- 用户可以按默认顺序、歌曲名称或时长查看歌单内歌曲。
- 用户在默认排序下可以手动调整歌单内歌曲顺序。
- 用户可以在一个播放列表中选择一个或多个歌曲。
- 用户可以把选中的歌曲按选择顺序加入到其他一个或多个播放列表。
- 用户可以选择一个或多个歌曲，并从当前播放列表中移除这些歌曲条目。
- 用户删除播放列表时，需要能理解该操作是否只删除播放列表本身；真实文件删除不进入 v0.2。
- 用户点击播放列表详情中的歌曲后，v0.1 播放界面的当前歌曲状态切换到该歌曲。

## 优先级建议

P1。

虚构播放列表管理 UI 是真实播放列表、本地音乐库和后续播放队列体验的前置验证能力，但仍然应晚于 v0.1 播放界面。建议进入 v0.2。

## 版本建议

建议进入 v0.2。该版本只承接播放列表管理 UI 原型和假数据状态验证，不承接真实播放列表持久化、文件读取、媒体库、真实音频播放、`m3u8` 或数据库能力。

## 假设

- v0.2 基于 v0.1 的播放界面和 UI-only 播放状态继续推进。
- 虚构播放列表数据只存在于前端假数据或内存状态中。
- 新增、编辑、删除和排序操作只用于当前 UI 原型验证，不要求写入文件、数据库或系统存储。
- “编辑”在 v0.2 中优先指编辑播放列表名称，不包含编辑歌曲内容。
- 歌单内歌曲的“默认排序”指虚构播放列表数据中的原始顺序或用户在当前会话中手动调整后的顺序。
- “加入到播放列表”只在当前 UI 原型状态中修改目标虚构播放列表的歌曲集合。
- 多选歌曲加入目标播放列表时，加入顺序以用户选择歌曲的顺序为准。
- “从播放列表删除歌曲”在 v0.2 中只移除虚构播放列表内的歌曲条目，不代表删除真实歌曲文件。
- 真实产品中删除播放列表或歌单时，应明确区分“仅删除歌单 / 播放列表”与“同时删除关联歌曲文件”；v0.2 只验证提示文案和交互边界，不执行文件删除。
- 播放列表中的虚构歌曲仍然使用 v0.1 或 Architecture Agent 定义的最小 `Track` 结构。

- FR-012：用户必须能删除虚构播放列表。

- FR-020：选择按时长排序时，歌曲必须按歌曲时长排序展示。

- FR-023：切换到非默认排序时，歌曲展示顺序必须由当前排序规则决定，不要求允许手动调整。
- FR-024：用户必须能在当前播放列表中选择一个或多个歌曲。
- FR-025：用户必须能将选中歌曲加入到其他一个或多个虚构播放列表。
- FR-026：选中多个歌曲加入目标播放列表时，目标播放列表中新增歌曲的相对顺序必须与用户选择顺序一致。

## 关键规则

- 虚构播放列表只用于 UI 原型和状态验证。
- v0.2 中的新增、编辑、删除和排序不写入磁盘、数据库或外部服务。
- 删除虚构播放列表不删除真实文件，也不影响任何本地音乐资源。
- 排序只影响虚构播放列表的显示顺序，不代表最终持久化排序策略。
- 歌单内歌曲排序只影响当前 UI 原型中的展示顺序或当前会话内的默认顺序，不写入真实播放列表。
- 只有默认排序模式要求支持手动调整歌单内歌曲顺序。
- 按歌曲名称和按时长排序属于规则排序，不要求在该模式下手动拖动歌曲。
- 从一个播放列表加入歌曲到其他播放列表时，源播放列表不应移除这些歌曲。
- 加入到多个目标播放列表时，每个目标播放列表都应收到同一批选中歌曲。
- 选中歌曲加入目标播放列表时，应追加到目标播放列表当前默认顺序的末尾，除非后续 UI/UX 规格另有定义。
- 如果目标播放列表已存在同一首虚构歌曲，v0.2 是否允许重复项必须有明确规则；在规则未定前应作为开放问题。
- 从播放列表详情删除歌曲时，只移除当前播放列表中的歌曲条目，不影响其他播放列表中的同一首虚构歌曲。
- 删除播放列表时，v0.2 只删除虚构播放列表本身；不删除歌曲文件，不删除其他播放列表中的歌曲条目。
- 真实文件删除属于高风险能力，必须在后续真实媒体库或真实播放列表版本中单独分析和确认。
- 播放列表详情中的歌曲点击只切换 UI 当前歌曲状态，不播放真实音频。
- 任何真实播放列表、`m3u8`、媒体库或文件系统能力必须交由 PM Agent 判断是否延期或另行分析。

## 边界情况

- 初始播放列表为空。
- 某个播放列表内歌曲为空。
- 用户新增播放列表时名称为空。
- 用户编辑播放列表名称为空。
- 用户删除当前选中的播放列表。
- 用户删除最后一个播放列表。
- 用户连续新增多个播放列表。
- 用户连续调整播放列表排序。
- 用户在空播放列表集合中尝试排序。
- 用户在空歌曲列表中切换排序方式。
- 用户在单曲歌曲列表中手动调整顺序。
- 用户在按歌曲名称或按时长排序模式下尝试手动调整歌曲顺序。
- 多首歌曲名称相同。
- 多首歌曲时长相同。
- 用户未选择歌曲时尝试加入到播放列表。
- 用户选择一个歌曲加入到一个目标播放列表。
- 用户选择多个歌曲加入到一个目标播放列表。
- 用户选择多个歌曲加入到多个目标播放列表。
- 用户尝试把歌曲加入当前源播放列表。
- 目标播放列表为空。
- 目标播放列表已存在相同歌曲。
- 用户未选择歌曲时尝试删除歌曲。
- 用户选择一个歌曲从当前播放列表删除。
- 用户选择多个歌曲从当前播放列表删除。
- 用户删除当前正在播放的歌曲条目。
- 用户删除播放列表时误以为会删除歌曲文件。

## 异常情况

- 新增或编辑名称为空时，界面必须阻止提交或显示明确提示。
- 删除当前选中播放列表后，界面不得继续引用已删除播放列表。
- 删除最后一个播放列表后，界面必须展示空播放列表 Empty State。
- 排序操作目标无效时，界面不得崩溃。
- 歌单内歌曲排序字段缺失时，界面不得崩溃。
- 非默认排序模式不支持手动调整歌曲顺序时，界面必须禁用入口或给出明确反馈。
- 未选择歌曲时，加入到播放列表操作必须禁用或显示明确提示。
- 未选择目标播放列表时，确认加入操作必须禁用或显示明确提示。
- 目标播放列表不存在或已被删除时，加入操作不得导致界面崩溃。
- 未选择歌曲时，删除歌曲操作必须禁用或显示明确提示。
- 删除当前正在播放的歌曲条目后，播放界面的当前歌曲状态不得变为无效状态。
- 删除播放列表确认提示不得暗示 v0.2 会删除真实歌曲文件。

- v0.2 不创建、修改或删除用户文件。
- v0.2 不导入或导出 `m3u8`。
- v0.2 不持久化歌单内歌曲排序结果。
- v0.2 不持久化跨播放列表加入歌曲的结果。
- v0.2 不删除真实歌曲文件。

- v0.2 不要求用户登录账号。
- v0.2 不访问在线音乐服务或第三方音乐 API。

## 验收标准

- 应用展示至少 3 个初始虚构播放列表。
- 点击或选择某个虚构播放列表后，界面展示该播放列表内的虚构歌曲信息。
- 播放列表详情中的歌曲展示歌曲名、艺术家、专辑、时长中的至少 3 类信息。
- 点击播放列表详情中的歌曲后，播放界面当前歌曲切换为该歌曲。
- 当前歌曲在播放列表详情中有可识别标记。
- 用户可以新增一个虚构播放列表，新增后列表中可见该播放列表。
- 用户可以编辑虚构播放列表名称，编辑后列表展示新名称。
- 用户可以删除虚构播放列表，删除后列表中不再展示该播放列表。
- 用户可以调整虚构播放列表顺序，调整后列表顺序发生可见变化。
- 播放列表详情提供默认排序、按歌曲名称排序和按时长排序。
- 选择默认排序后，歌曲按默认顺序展示。
- 选择按歌曲名称排序后，歌曲按歌曲名称排序展示。
- 选择按时长排序后，歌曲按歌曲时长排序展示。
- 默认排序模式下，用户可以手动调整歌单内歌曲顺序。
- 手动调整歌单内歌曲顺序后，再次选择默认排序时展示调整后的顺序。
- 非默认排序模式下，手动调整歌曲顺序入口被禁用或有明确不可用反馈。
- 用户可以在一个播放列表中选择一个或多个歌曲。
- 用户可以选择一个或多个目标播放列表，并将选中歌曲加入目标播放列表。
- 多选歌曲加入目标播放列表后，新增歌曲在目标播放列表中的相对顺序与用户选择顺序一致。
- 选择多个目标播放列表后，每个目标播放列表都加入同一组选中歌曲。
- 加入歌曲后，源播放列表仍保留被选中的歌曲。
- 未选择歌曲或未选择目标播放列表时，加入操作被禁用或显示明确提示。
- 用户可以在当前播放列表中选择一个或多个歌曲并删除。
- 删除选中歌曲后，这些歌曲不再出现在当前播放列表详情中。
- 从播放列表删除歌曲不会删除歌曲文件，也不会删除其他播放列表中的同一首虚构歌曲。
- 删除播放列表时，界面显示确认提示，并明确 v0.2 不删除歌曲文件。
- 未选择歌曲时，删除歌曲操作被禁用或显示明确提示。
- 空播放列表、空歌曲列表和无选中播放列表分支存在并可渲染 Empty State。
- 新增或编辑名称为空时，界面阻止提交或显示明确提示。
- 删除当前选中播放列表后，界面不再引用已删除播放列表。
- `npm run lint` 通过。
- `npm run build` 通过。
- v0.2 不读取用户文件，不播放真实音频，不写入持久化播放列表数据，不导入或导出 `m3u8`。

## 风险

- 如果 UI-only 管理和真实播放列表混淆，可能提前引入持久化、导入导出或 `m3u8` 范围。
- 如果排序交互不先明确，Frontend Agent 可能采用和目标体验不一致的排序方式。
- 如果播放列表排序和歌单内歌曲排序没有区分清楚，容易造成状态模型混乱。
- 如果默认排序和规则排序之间的关系不清，手动排序结果可能在切换排序方式后表现不一致。
- 如果多选歌曲的选择顺序不可见，用户可能无法预测加入目标播放列表后的顺序。
- 如果重复歌曲规则不明确，目标播放列表中可能出现用户不预期的重复项或缺失项。
- 如果删除歌单条目和删除歌曲文件的边界不清，可能造成高风险的数据丢失误解。
- 如果删除当前选中播放列表的状态规则不清，容易出现已删除对象仍被详情区引用的问题。
- 如果假数据结构过度贴近最终媒体库结构，可能提前制造不必要的数据层复杂度。

## 建议

建议 PM Agent 将 v0.2 定义为“虚构播放列表管理 UI”版本，而不是“真实播放列表”版本。进入实现前，建议 Architecture Agent 定义最小 `Playlist`、`Track`、播放列表排序字段、歌单内默认顺序字段、规则排序字段、跨播放列表加入歌曲和从播放列表移除歌曲的状态规则；UI/UX Agent 定义新增、编辑、删除、播放列表排序、歌单内歌曲排序、多选歌曲、加入到播放列表、从播放列表删除歌曲、确认和 Empty State 的交互规格。真实播放列表持久化、`m3u8`、媒体库、文件读取和真实文件删除应保持 Deferred。
