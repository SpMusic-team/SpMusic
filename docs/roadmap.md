# SpMusic 路线图

## 摘要

本路线图基于 `docs/requirements/总需求分析.md`。路线图的原则是先建立可运行地基，再逐步进入真实播放、音乐库、播放列表、网络存储、高级 UI 和扩展能力。

## 版本规划

### v0.1 项目地基

目标：摆脱模板项目状态，建立可运行、可验证、可迭代的 SpMusic 桌面应用地基。

范围：

- SpMusic 项目身份和 README。
- 静态播放器主界面。
- 假歌曲队列。
- UI-only 播放状态。
- 最小前后端通信验证。
- 基础验证命令和发布检查清单。

不包含：

- 真实音频播放。
- 媒体库。
- 数据库。
- 网络存储。
- 播放列表真实导入导出。
- 插件系统。

### v0.2 本地播放技术验证

目标：评估并实现第一条真实本地音频播放链路。

候选范围：

- 音频方案评估和架构决策。
- 单文件本地音频播放。
- 播放 / 暂停 / 停止。
- 基础音量和进度状态。
- 格式支持边界记录。

不包含：

- 完整媒体库。
- 高级 DSP。
- 独占输出。
- 网络存储播放。

### v0.3 本地音乐库地基

目标：建立本地音乐库最小闭环。

候选范围：

- 选择本地文件夹。
- 扫描音频文件。
- 基础歌曲索引。
- 按歌曲浏览。
- 缺失元数据后备展示。
- 本地数据存储方案决策。

### v0.4 音乐库浏览与播放列表

目标：让本地音乐管理进入可日常使用的基础形态。

候选范围：

- 按艺术家、专辑浏览。
- 按文件夹范围过滤。
- 基础搜索。
- 收藏 / 喜欢。
- 播放历史列表。
- 基础播放列表。
- `m3u8` 导入导出策略。

### v0.5 网络存储播放

目标：支持用户自有网络存储中的音频资源。

候选范围：

- FTP / SMB / WebDAV 来源抽象。
- 网络文件浏览或引用。
- 流式播放能力评估。
- 离线与错误状态处理。

### v0.6 UI、性能与多语言

目标：强化 SpMusic 的核心体验差异化。

候选范围：

- 明暗模式。
- 基础主题切换。
- 多语言适配基础。
- 动画和视觉性能档位。
- 触控友好的关键交互。

### 后续高级能力

目标：在基础播放器稳定后扩展高级体验。

候选范围：

- 歌词。
- 专辑封面。
- 元数据编辑器。
- 智能播放列表。
- 独占音频输出。
- 收听记录可视化。
- Last.fm / Pano Scrobbler。
- 云同步适配。
- 自定义功能区。
- 可拆分、可置顶功能区。
- 插件增强体系。

## 范围护栏

- 基础播放、音乐库、播放列表、网络存储播放不应依赖插件。
- 插件只作为增强能力，不作为核心能力前提。
- SpMusic 不做在线音乐平台、在线曲库搜索、内容推荐或版权音乐服务。
- 每个版本必须有可验证的完成定义，不能以最终愿景替代当前版本范围。
