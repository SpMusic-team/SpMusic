## 背景与范围

这是一项 P2 研究。首轮确认了 B 的核心版本、主题的 COM 前置条件和 ESLyric 空闲开销，也验证了内嵌 CUE 能枚举逻辑分轨。界面端缺同任务对照、首达与真实回访以及匹配画幅的头图，音频端缺实际输出抓样。原版值得进一步研究的能力包括大曲库快速可用、可组合查询、自动重新求值的列表、可靠的组织与恢复，以及稳定的连续播放。

DS 负责可复测实验、功能级逆向、基线核查和实施方案。产物包括独立夹具、测量脚本及可丢弃的实验原型。正式产品改动由各候选任务进入各自的实现与复核流程。专题范围保留与现象直接相关的代码、脚本、配置或 SDK 契约；插件平台、完整搜索语法兼容、批量自动改写用户文件、全链路音质排名列为后续议题。

## 执行顺序与停测条件

以下时长是首批实验的建议上限，单位为投入工时。每阶段结束记录已完成、未测和下一步，时间用尽就提交已有结果。

| 顺序 | 工作 | 建议时间 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 0 | 环境、样本、界面输入及 PCM 抓样预检 | 1–2 小时 | 两种界面均由录屏确认位置实际变化。PCM 有已知信号的正对照，或已登记阻塞。 |
| 1 | 找歌到播放、长列表首次到达和回访、头图 | 3–5 小时 | 一条同任务双样本路径、首达与回访各三对有效记录、头图同尺寸对照。缺项保留待测。 |
| 2 | 原生检索、组织与索引持久化 | 3–5 小时 | 完成最小语料设备上的查询结果、规则更新、一次增量和一次离线恢复证据。 |
| 3 | 两类续播、PCM 精度与播放稳定性 | 3–5 小时 | 抓样通过后交实际测量。抓样不可用时交触发证据与复跑卡，继续本地可观测的稳定性实验。 |
| 4 | 定点归因、实施卡和复核 | 2–3 小时 | 每条候选绑定证据与 SpMusic 基线，分别标注可实施、需补证、已覆盖。 |

**预检**先在正常前台窗口人工点击、滚动一屏，录下条目变化和输入时刻，校验录屏时间轴。首轮 E-008 的 `PrintWindow` 会返回静态缓存位图。只在真实交互已验证的桌面尝试自动输入，工具不可用就保留人工录像或交操作卡。音频用目标端点播放已知的带定位标记 PCM，并录取播放前静音、信号和停止后静音。检查录音确实来自目标端点而非麦克风，记录设备、端点格式、采样率、通道及录制格式。首次路径失败时尝试第二种可用且已获准的抓样方式，例如 Windows 共享端点的 WASAPI 环回，或已有数字回录设备。两种方式均不可用或预检到时即记录工具、实际错误、缺件、可复验步骤，继续其他阶段。

## 实验规程

### 1. 找歌、长列表与头图

1. **同任务对照。** 用含合作艺人、多值流派和同名专辑的固定曲库。初始从库首页出发，找到指定曲，将它设为下一首，自然进入该曲后保留当前播放顺序证据。记录入口、操作次数、任务总时长、误操作、键盘可达性及队列状态。功能缺失时用该播放器能达到相同结果的最短路径，记录替代动作。
2. **长列表。** 生成至少 300 条，其中多数封面带唯一编号，同一组另有故意重复和已知无图。固定排序、目标行、移动范围、布局、视窗及后台负载。第一眼报告各自默认视图，性能对照再匹配可见行数、图数和实际像素面积。若 A′ 或 B 没有等价封面面板，记录产品差异，量化比较限于可匹配场景。
3. **首达与回访。** 对每个主测状态至少三对交错运行，首达跳到该会话尚未显示的区域，准备过的落盘状态和新 profile 分开。先等目标图全齐，再离开并原样返回才计为真正回访。黑盒只能观测会话及准备动作时，缓存命中填未知。每次保存输入前至结束的录像、帧号、正确目标图集合与超时。从提交搜索或滚动松手起记录首个正确条目、可交互、50%／90%／全齐、松手空白数和错图暴露。明确判定稳定画面的帧数与统一超时值，报告中位数、范围和失败分母。计划中的无图对照单列，未知或未加载的有图项计入分母。
4. **头图与源图。** 用同含细线与小字的合成源图，保存原生无缩放截图和同一内容区域的 1:1 裁片，记录 DPI、裁剪、像素尺寸与来源。准备仅嵌入、仅目录、两者冲突和无图四例，替换其中一个源并重开验证失效。分别观察列表与播放详情，记录可辨细节和所选图。截图无法决定缓存分辨率或插值核时标记未知。

### 2. 检索、自动列表、持久化及组织

1. **查询表。** 建 12–20 条自制标签，覆盖多值艺人、同名专辑、无字段、重复引用和不同版本。事先写好应命中的逻辑曲目 ID。比较 A′ 原生检索与 B 各入口，测试字段匹配、布尔组合、缺字段、按流派联动艺人、稳定排序和非法条件。记录运算语义、入口反馈和实际结果。以创建一个保存规则的列表、编辑一条会改变命中结果的标签、重启后复查为闭环。收集规则何时求值、队列行为、排序及重启恢复。切换一个组件或设置并恢复，以区分核心查询、组件筛选和主题包装。评分可用 A′ 自带语法帮助中的 `%rating% GREATER 3` 作独立例子，播放统计在组件启用和停用时用固定时钟另测，留给后续实现。
2. **增量与离线。** 先用 300–1000 条夹具，独立根目录与多级子目录，控制初次导入、同 profile 重启、只碰 mtime、真实改一首标签、根目录离线后恢复。分别记录首条可用、搜索可用、完成收敛、已保留/更新/删除条目、路径及打开失败行为。使用带进程和路径字段的文件活动记录，区分目录枚举、属性查询、内容读取、缓存/索引读写。对照进程冷启但系统缓存未清的情况；用真实标签变化在视图或只读快照内显现来确认更新。禁止凭 `LastAccessTime` 或启动变快单独断定只重读一首。运行中数据库只按可验证的一致性方法取快照，文件差异仅作辅证。
3. **组织与恢复。** 扩展复用前述夹具，对复制出来的测试根做一次批量修改预览或按标签改名/迁移，设置一个名称冲突或不可写文件并记录部分失败。复查重复引用、原歌单顺序、评分或历史对应关系。若暂时无法做该轮操作，先产出可用的只读体检用例，区分真正失效、暂时离线、有意重复及同名不同版本。

### 3. 接缝、精度及播放稳定性

1. **最小矩阵。** 从同一个无损 PCM 生成整轨、连续切分的 A/B 两个文件，以及带两个索引点的内嵌 CUE 整轨。保存来源、编码参数、样本数、精确边界、前后定位标记和解码基准哈希。每端先捕获一条整轨正对照，再分别捕获两文件自然续播、同文件 CUE 自然续播，各三轮。固定播放顺序、音量、设备和格式，关闭会改变信号的预设、淡化、EQ 与 ReplayGain；后续变体单独开启。手动切曲和 seek 另起试验。按定位标记对齐，报告边界窗口、丢失／重复样本或静音区间、峰值不连续和测量误差。确知捕获链不会改变采样率、幅度和时钟时才做逐样本等值判断。
2. **测量边界。** 分别标注解码后 PCM、SpMusic 内部抓样、系统共享混音端回录、数字端回录和模拟回录。分别写出能归因的阶段；共享环回没有确认独占输出或 DAC 结果的能力，模拟回录用于观察噪声、瞬态和断音，精确字节比较使用可比的数字信号。保留未经处理的抓样、脚本及其输出，不用响度或零段单独推断丢样。
3. **精度和稳定。** 首轮先测同采样率和 24-bit 低位可辨信号，记录实际共享格式、声道、增益和活动 DSP。条件允许再测 44.1→48 kHz、暂停恢复、快速 seek、输出设备切换或繁忙时断音。用正常文件和受控截断文件记录播放状态、可区分的错误和自动恢复。重采样质量、ReplayGain 策略、独占模式分开做单变量实验。若抓样仍受阻，保留实际播放和设备状态、CUE 定位及 UI/诊断结果，接缝和精度标为待测并提供另一台机器的复跑步骤。
4. **可选验证。** 用同源文件比较有 Track/Album 标签、只有一组标签及无标签时的增益行为，固定端点、前置增益与其余 DSP。只在同一已知抓样点比较电平。同时核对界面报告的设备、格式与实际端点，分别记录请求值和实测值。

## 归因与 SpMusic 实施

先确认差异可观察，再锁定可能的层级。每次保留默认状态，在同一副本上仅改一项组件、配置或缓存准备动作，复跑后恢复再测。记录组件版本、配置键、SDK 契约、必要的文件或二进制偏移以及替代解释。首轮可复用 ESLyric 禁用再恢复的行为证据，主题补丁的 SHA 恢复只支持文件还原。对核心 `.text` 的归因须用原始字节差异与引用关系，段长度相同只证明长度相同。复核已确认 1,424 个差异字节，其中 898 个可归到指向中文字符串段的地址改写，其余保留待解释。涉及版本演进时区分旧版 LargeFieldsConfig 与 2.26 恢复的机制。

每张实施卡指定用户操作、当前基线 SHA 与代码路径、可衡量的差距、最小方案和替代方案、失败及恢复语义、兼容和回滚方式、所需角色及独立验收。以下是候选的先后依赖，只有拿到对应证据且基线尚缺该能力时才进入实施评审。

| 候选 | 基线核查与最小实施方向 | 验收与回滚 |
| --- | --- | --- |
| 封面可用性 | 优先复用 `useAllSongsWindow.ts`、`useLibraryArtwork.ts` 与 `audio/cover_pixels.rs`。若确认回访闪空，先验证同一曲目与同一图像版本在回访时保留已有正确封面，刷新失败仍能保留有效旧图。头图选档独立对照。 | 冻结同批夹具，对比可交互及正确图首次出现、90%/全齐、回访闪空、请求数和内存。错误图、饿死、回访退化即回退独立提交，保留基线指标。 |
| 可组合检索与动态列表 | 核查 `librarySearch.ts` 及艺人、流派模型。第一步用既有标签实现「流派 AND 艺人」本地组合过滤；第二步再保存一条规则并重算。核查当前 `sourcePath` 去重，分轨用不同逻辑曲目 ID，用户在播放列表重复加入同一曲的两条记录使用独立列表条目 ID。 | 12–20 条真值表准确命中，改单条标签后更新。保存规则阶段另验重启恢复及静态列表顺序和播放项。回滚先关闭新入口并保留旧持久化可读取。 |
| 曲库恢复与安全组织 | 核查 `library_folders.rs`、`lib.rs` 的扫描入口及 `audio/playlist.rs`。先在单根目录验证只读离线提示，保留上次可用清单及原歌单引用，恢复后重新核对。增量新索引及组织写入分别评审。 | 交一次真实标签变化、离线再上线及基线 I/O 结果。保留旧快照兼容或可逆迁移。误删、重复或引用失效时退回原读取路径。 |
| 分轨播放、PCM 或恢复 | 核查 `audio/{runtime,source,symphonia_source,cue,chapters}.rs`、前端 `audioCommands.ts` 与恢复提交差异。先选一个缺口。分轨用一份双轨 CUE 实现按逻辑 ID 选择播放时间窗并验证结束位置。PCM 可先实现可重复抓样与比对夹具，定位精度损失边界后再决定改造。 | 检查本地文件、重复条目、seek／续播／重启和错误回传，分轨以每段实际起止验证。触及 PCM 或时序时对比同端点抓样。契约不兼容或出现断音回归时回退该项，保留已通过的夹具。 |

首批证据到位后可选一项制作可复跑脚本或隔离原型，优先选封面回访或 PCM 接缝。实验原型在独立分支验证。按用途复用 `tools/thumbnail-benchmark/coverlane-README.md` 或 `tools/audio-compatibility/generate-fixtures.mjs`。先冻结语料及基线，按基线噪声设定最小收益和可接受的回归上限，再记录配对结果、改动 SHA 与回滚步骤。原型通过后把适用范围和独立验收写入正式实施卡。

对 `c20ff0c` 的自检、解码失败分类、会话保存去重、滚动暂缓、内部 `f32`、MMCSS、CUE 扫描和缩略图平滑逐项写清「提交里有 / 当前已合入 / 尚缺完整路径 / 待复验」，以实际 diff 和运行证据为准。特别检查 CUE 列表后的播放范围、错误阶段的前端契约，以及平滑改动是否存在于提交。仅在选定单项的实现卡内复用已验证改动，处理与头图分支的文件重叠。架构和契约由 Architecture 复核，用户路径由 UI/UX 核对，正式实现按 Frontend 和 Rust/Tauri 的写入范围分工，性能、音频和跨层行为由 Test 独立复验。

## 交付与验收

- 研究归因报告建议存 `docs/architecture/foobar2000-foobaka-phase-2-findings.md`，实验记录与能力边界建议存 `docs/test/foobar2000-foobaka-phase-2-comparison.md`，候选实施卡及排序建议由 PM 汇总到 `docs/tasks/foobar2000-foobaka-phase-2-candidates.md`。分别遵循文档归属，研究证据可以先以交接文本提交。
- 原始材料按 `.rea-analysis/foobaka-phase-2/<run-id>/` 保存，仓库只登记去标识的结果与相对路径。每轮记录样本、配置、语料、录屏或音频哈希，环境与动作、观测表、失败或排除原因。结果字段采用 `run_id, case_id, sample, build_id, fixture_sha256, mode, repeat, start, end, metric, unit, status, artifact`；机制结论另写证据等级（实测、公开契约、推断、未知）、替代解释、证伪方法和用户价值。
- **首批通过条件**为阶段 1 的三项界面证据、阶段 2 的查询规则与增量/离线闭环、两个可区分的续播用例及三张以证据排序的候选实施卡。若某个样本经实际检查缺少等价的封面或头图面板，附入口核查及另一侧独立观测，对应配对指标标为不适用。等价面板存在但无法输入或截图时标为受阻。定量主张必须附有效重复和原始数据。只有在相应捕获边界测到输出时，才把接缝和精度标为已验证。批量组织、额外设备和大规模曲库是扩展验收项。
- **阻塞交付**保留每个受影响用例的确切状态，标明哪一环失败、首选环境、接手动作与可接受输出。特别保留输入和抓样预检日志，未测条目保持待测。实测本身没有覆盖的结论或产品路径照实列出，不用静态推断、测试通过数字或其他分支的实现替代验收。
