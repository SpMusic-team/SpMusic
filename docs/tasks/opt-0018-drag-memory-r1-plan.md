# OPT-0018 拖动内存第一轮实现与测试方案

DS 负责复现、实现可拆分的候选、执行筛查和交回原始证据。Codex 根据结果淘汰方案、确定最后做法并负责最终实现与验收。DS 将候选留在独立工作树或实验分支，每个候选单独提交或导出补丁，保留失败结果。所有正式实验使用同一可重放 Git 基线。

## 1. 目标和边界

- **重复拖动带来的额外私有内存观测峰值严格小于 300,000,000 bytes**，约 286.10 MiB。逐个候选运行判定，任何一次有效运行超限均报告。总进程树绝对峰值另外公布。
- 有图片的目标应正确显示，停手后维持此前约 1 秒的 H 体验。允许调整拖动时的懒加载、离屏预取、驻留时间、加载批量及动效触发。在移动中维持已有有效封面和导航租约，松手及时补齐。
- 开始时以目标集成提交的完整 SHA 冻结基线。截至起草时 develop 为 682acf4，工作树另有媒体库封面接入与公平调度修改。若需基于这些修改实验，A 和所有候选使用同一份独立快照并记录补丁摘要，避免覆盖用户工作树。目标集成提交变化后重建批次。4d4477c 与 fb7913a 仅为历史对照。
- 第一轮保持 256 行图、现有头图档位、Lanczos3 和 t2 持久化兼容。布局自适应尺寸如需验证，单列候选并附画质比较。保留目录代表图选择、网络流占位、损坏回退、重扫版本与旧图过渡。

## 2. 基线与归因

历史 1799 首、2544×1431、DPR 1、level 2 的一次 BA 对中，活动峰值 A 1277.8 MiB、B 1431.6 MiB。减去各自活动前中位 959.5 和 989.9 MiB，旧口径增量约 318.3 和 441.7 MiB。B 相对 A 的绝对峰值增量中，GPU 进程 95.3 MiB，renderer 49.8 MiB，应用主进程 4.2 MiB。它支持优先排查 WebView2 图片与合成路径。GPU 进程 Private Bytes 与显卡显存是不同指标，历史单秒采样可能漏峰。

### 2.1 同批进程树测量

- 用 PID 加启动时间锚定各臂测试进程和独立 WebView2 profile。每个采样批汇总活跃专属进程的 Private Bytes，记录 app、browser、renderer、gpu-process、utility 和其他拆分。保留进程树、时间戳、扫描跨度和 CPU 原始值。各角色峰值分项取总峰值同一时刻，Working Set、JS heap、显卡计数仅作旁证。
- 默认目标采样间隔 50 ms，拓扑约每 500 ms 刷新，结果须有完整窗口和 renderer，间隔 p95 ≤160 ms、最大 ≤400 ms，扫描跨度最大 ≤400 ms。先在代表路线核对采样开销。可用 50–100 ms 范围内经前测验证的设置。临界样本用较密采样追加复核，保留两份。如果有进程新生、重启或脱离归属且可能漏峰，补录进程事件或 ETW 后再给结论。报告采样观察峰值。
- 不强制 GC，不手工清理运行中的缓存，不用禁用硬件加速当优化。错开构建和并行桌面任务，登记干扰、采样缺失和产品失败。

### 2.2 指标与防止移峰

启动后尽早采样。首屏稳定后静置 15 秒，热态预热拖动 30 秒，再静置至少 15 秒。冷态把预热设为 0，使用新缓存根。随后活动拖动，停止后继续记录至少 60 秒。两段静置各取末 10 秒的 Private Bytes 中位。

1. **主活动增量** = max(0, 活动开始至停止后 60 秒的峰值 − 活动前静置中位)。
2. **含预热增量** = max(0, 预热开始至停止后 60 秒的峰值 − 首次静置中位)。
3. 两项均须低于 300 MB。另报从启动开始的绝对峰值、两段静置绝对量、拖动活动峰值、恢复期峰值与末 10 秒中位。以候选首次静置或启动绝对峰值比 A 恶化超过 50 MB 为调查线，补做成对观察排除开销前移。停止期仍有积压或上升时延长采样，查并记录最后一次输入后的任务收敛。10 分钟跑分段报告峰值。
4. H/G/R 松手时延独立用轻量计时器。时延采集与高频内存、详细诊断分开；同场景 A/B 保持相同仪器配置。候选延后发起的工作继续计入内存窗口。

### 2.3 先跑这些用例

| 场景 | 路线与压力 | 用来区分 |
| --- | --- | --- |
| P-H-fixed | 活动播放列表，盘上图准备好，重启及新 profile，同两处落点往返 120 秒 | 相同落点下浏览器 decode、图层、URL 或租约是否累积 |
| P-H-sweep | 盘热态，固定多站正反向路线，120 秒 | 新图片不断进出视口和拖动途中读图放大 |
| P-G-sweep | 每臂新隔离缓存根，预热 0 秒，掠过新目标 120 秒 | 原生解码/中间缓冲/路径失效与像素回退 |
| P-H-600 | H 中更容易出峰的路线 600 秒 | 峰值是否仍增加、长期稳定性及恢复 |
| L-H / L-G | 所有歌曲和一个有代表图的集合页，优先文件夹层次或艺术家 | 独立 owner、集合候选和根页回归 |

包内自动内存路线覆盖活动播放列表。DS 对根页加真实入口及滚动容器适配，或用独占桌面、固定手势和同一进程树采样器输出相同 phase/gesture schema。先验证实际滚动目标、首尾坐标与采样窗口。播放列表数据不能填作根页样本。每对同输入、时间、视口、显示布局与缓存条件。移动率 ≥95%、落点误差 4 个百分点内的比例 ≥90%、动作数达到计划的 ≥90%。两臂总移动距离差 >5% 时核对并整对重做。

P-H-fixed 和 P-H-sweep 先各用 A 跑两个新进程。H 用每臂自己的准备根，预先覆盖实际路线目标，重启且新建 WebView2 profile。G 抽核未访问目标派生图在按下前缺失。诊断时抽核实际命中、生成、像素回退和时间阶段。基线未超限时复核范围、缓存、规模、视口和负载，补一趟 600 秒；仍未复现则交回证据，避免对未证实的根因直接调参。

必要诊断以聚合计数或环形缓冲记录。关联可见/必需/可选 demand、请求启动/取消/完成、驻留资源及 lease、DOM 唯一 URL 数/面积、临时 Image 个数、路径错误/像素回退、原生解码在途字节，并与进程轨迹时间对齐。正式验收禁用高密度诊断。场景准备覆盖有图、无图、大图、共用封面和一个损坏恢复样例，错误压力单列。

## 3. 实现候选，按以下顺序

### B1　拖动时少启动离屏读图

从 PlaylistPanel 的可见需求入口到 useAudioPlayer 的 admission，及媒体库 useAllSongsWindow 的窗口排序入口接入。useLibraryArtwork 只同步实际需求有关的浏览路径。第一版保留完整可见需求，暂停拖动途中新增 overscan、全源后台预取或可选高档升级；已有有效图仍显示。长跳释放已离开窗口的消费者，已进入原生的工作仍受全局名额约束。松手、pointercancel、lostpointercapture、blur、路由退出或滚动结束后，恢复并立即重算需求。固定行尺寸、温热预算、后端宽度和动效，观察有无松手后集中补发峰值。

第一版稳定有效但仍过限时，单做 B1b。高速拖动中对新图要求短暂连续可见再启动，可探索两帧或 60–100 ms。已有图照常绘制，松手绕过稳定门槛，慢拖和触控板/键盘正常更新。记录拖动沿途空白、松手空白和实际取消量，防止通过一直留空来达标。

### B2　缩短离屏驻留，单独从 A 比较

先在诊断图上读出离屏资源被哪条边持有。活跃播放列表先测试 playlistArtworkGrace 的 5 秒改约 1 秒，保持 96 MiB、并发和动效。若证据表明受保留量主导，则独立测试 96→48 MiB、固定 5 秒。根页 CACHE_LIMIT、浏览页 MAX_RESIDENT 独立验证，按已证明受益的 owner 分别改。已解码缓存、真实缺图、失败缓存分开计，释放无租约的 blob，保留 asset URL 语义、切页过渡、当前播放头图和同会话回访。应用预算与浏览器实际内存分别报告。

### B3　WebView2 临时预解码或合成

renderer/GPU 仍主导时，关联临时 Image 并行数、DOM 实际绘制图、可见面积与图层变化。先只限制共享预解码许可，从 4 或 8 小样试验，保持原生调度和 resident。队列可取消，可见优先，等名额与实际解码超时分开。取消按 dropped 清理，不触发路径熔断/像素重读。保留同一 decoded 标志及发布校验。若峰值与成批合成动效重合，再独立试画面动效触发或层使用频率，保持首屏和松手后过渡。避免以 CSS 强制降质、硬件禁用或移除解码探测换数字。

### B4　冷态原生预算，按证据启用

在 G 确认主进程峰值或大图解码在途才启动，固定前端 owner 宽度和驻留预算，单改解码并发/字节准入。低宽度 1/2 要能完成，保留可见优先、待命取消、错误收敛和写盘身份。Rust permit 报告同时影响前端宽度，实验必须隔离变量。若后续测试尺寸或新的持久化键，独立输出画质、旧缓存兼容和停手时延证据。

### 筛查与组合

B1、B2 各从同一 A 出发，先跑 H-sweep 一对 BA 和一对 AB。有效者补 H-fixed。只有单一顺序改善时先补样。再选最多两个有效变量做组合并重测交互。先做能回答问题的低成本对照，暂不为所有候选铺正式矩阵。每轮控制在 DS 能交付的 3 小时内，时间紧优先基线和 B1/B2，回报哪些其他实验尚未执行。

## 4. 入围与最终验收

- **内存**。入围后每个 P-H-fixed、P-H-sweep、P-G-sweep 至少 2 AB + 2 BA；P-H-600 至少 1 AB + 1 BA。两种媒体库路由各至少 1 AB + 1 BA，含实际冷/暖对照。所有有效候选运行均通过两项 <300 MB。10 分钟内继续明显增长或停手后积压，须给原因和追加样本。
- **H/G**。DS 先给入围项 H/G 各 20 对，10 AB、10 BA，便于沿用包内统计。受 3 小时限制可先交齐 10 对原始数据作探索，由 Codex 根据选择后的版本补完 20 对。H 配对退化中位 ≤max(50 ms, A 中位的 5%)，单侧 95% 上界 ≤max(100 ms, A 中位的 10%)。同原机器、路线、语料和布局可重现时，H 候选中位还应 ≤1100 ms。其他设备注明绝对值，用同机非劣线。G 配对退化中位 ≤max(30 ms, A 中位的 5%)，单侧 95% 上界 ≤max(50 ms, A 中位的 10%)。使用 10,000 次按 pair bootstrap、Mulberry32 种子 20261109 与 nearest-rank。包内旧时延报告中 H 的提速判据属于上一任务，本轮按此处 H 非劣阈值定结论。
- **R 与拖动体验**。按 H/G 来源分别统计同会话离开再回。配对退化中位 ≤16.7 ms、跨运行 p95 增量 ≤33.4 ms，并报单侧上界。高速可短时暂停新增读取，单列沿途空白和松手后的空白。慢拖正常更新画面。
- **正确性**。松手冻结可见集合，身份相符且连续两帧可见才算全齐。真零照录，正确落点下错图、缺图或 20 秒超时记产品失败。覆盖快拖、慢拖、反向、拖停、窗口外松手/取消、换页、切歌、重新进入、重启、坏缓存回退、源重扫、无封面、大图和低宽度。实测播放列表、全部歌曲、文件夹及分类代表图，不把系统从未请求的行填为已完。
- **工程检查**。跑前端构建、源码 lint、scheduler/path lane/owner 和浏览器覆盖。改 Rust 则再跑 cargo check 和 Rust 库测试，验证磁盘文件互通。验证高密度图布局和纯文本布局。旧套件若被历史归档或导航阻塞，附失败记录和等价定向证据。
