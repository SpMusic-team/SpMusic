| 已知事实 | 来源与边界 | 对本轮的约束 |

| 多站往返正式 20 对中，回程补齐合计中位 387.5→25 ms，去程无明确差异 | [往返报告](../test/opt-0018-ab-multistop-formal-2026-11-09.md)，本机、单曲库、固定档位 | 回访必须保留；不能声称首次到达已经改善 |

| owner 上限 2→4 的探索未改善，观察到的请求在途峰值仍为 2 | [并发实验](../test/opt-0018-concurrency-experiment-2026-11-09.md) | 不重复盲改常量；仍须记录真实队列、资格和空闲原因 |
| 历史 `.m3u8` 场景请求归属 `useAudioPlayer` | 同上，41 条归属记录 | 只对该场景成立；当前“全部歌曲/浏览/播放中”分别核对 owner |
| 重启后捕获的 23 条目标请求命中 JPEG，未观察到重新生成 | [持久化报告](../test/opt-0018-disk-cache-persistence-2026-11-09.md)，目标总数 78，记录不全 | 23/23 不能写成 78/78；未记录的生成耗时是未知，不是 0 |

以下历史推论**不作为本轮既定根因**：

1. “peak in-flight 为 2，所以队列从来没有超过 2 个作业”。峰值、请求间隔和请求耗时无法代替待执行队列记录；去重、资格过滤、优先级、被占用的其他层槽位等都可能影响发出速度。
2. “首次到达只能优化 `scaleUs`”。已写盘和需现场生成是两种状态；前端需求晚到、排队、源定位、原生准入、读取、浏览器解码、React 发布和渐入都尚可能贡献等待。
3. “磁盘层没有浪费”或“所有目标都没有重复生成”。现有记录只覆盖部分目标，不能把未观察到的事件当成不存在。
4. “回访优势必然来自某一缓存层”。历史正式体验实验没有完成这一归因；应按当前事件验证。

旧 [ds 验证手册](../test/opt-0018-ds-verification-runbook.md) 的证据保全、故障测试和统计原则仍可复用；其旧版本状态、特定脚本参数和历史路径必须重新核对。

## 3. ds 的执行纪律与能力边界

### 3.1 每次只执行一个阶段

每阶段先写 5 行：输入是否齐全、当前固定版本、准备执行的命令/动作、预期产物、失败信号。完成后更新 `progress.md`，至少包含：

```text
当前阶段：
本阶段状态：未开始 / 进行中 / 通过 / 不通过 / 能力阻塞
已冻结版本、产物和协议：
亲自执行的命令、动作及证据路径：
事实：
假设与待反证项：
失败或缺失字段：
下一步唯一动作：
本轮已改文件及 Owner：
```

上下文不足或换聊天时先读这份账本及 `protocol.md`，不要凭记忆重建结果。不能用“已完成”替代日志。新能力未确认前不尝试依赖它的步骤。同一工具阻塞最多尝试两种有依据的修正，或投入 30 分钟，以先到者为限；之后交付具体缺口，继续独立工作。这不是正常编译/正式实验的总运行时限。

### 3.2 能力分层

| 能力 | 最小证明 | 缺失后的输出 |
| --- | --- | --- |
| 仓库阅读和编辑 | 能读取当前文件并保存差异 | 无文件能力则仅交付任务清单，不声称已改代码 |
| 命令执行 | 实际获得 Node/npm/Cargo 版本及退出码 | 完成可执行部分；缺失命令完整记录 |
| Release 构建 | 成功产生可定位、可 hash 的 Tauri exe | 不使用 Vite 页代替原生速度验收 |
| 原生实例控制 | 明确专属 PID、实际 exe、WebView2 及前台窗口 | 只做代码/自动化，原生计时标未验证 |
| CDP/桌面操作 | 能对同一实例真实拖动并读取目标状态 | 截图可辅助说明，不能靠截图猜毫秒或恢复次数 |
| 隔离缓存 | 证明实际 config/data/cache 及 WebView profile 路径 | 无法确认则不启动故障注入、不删除文件 |
| 原生分段 | 相关入口和命中早返回都有可关联记录 | 只报告已测边界，不填 0，不作后端内部归因 |
| 角色委派 | 实际存在架构、实现、独立 Test 执行者 | 可提交自查材料；没有独立审查就写“待独立审查”，不伪称由另一 Agent 验证 |

仓库要求的架构审查不能用自己换一个角色标题代替。没有多 Agent 工具时，可以继续只读诊断和整理具体修复提案；触发架构审查的实现，交由具备能力的协调者安排。用户若另行明确调整执行方式，记录新授权，仍如实区分自查与独立验证。

### A4. 隔离与构建绑定

1. 测试使用独立源码副本/工作树、独立应用 config/data/cache 及 WebView profile，不操作用户安装版。
2. 现有 `coverlane-isolation.patch.mjs` 提供构建期 `AppPaths` 与选文件入口隔离。仅在专属副本使用，先检查锚点是否仍匹配；保存 `apply` 差异，再运行其 `verify`。两臂隔离补丁必须相同。不要在主工作树应用。
3. 该隔离版本才认识 `THUMB_UI_ROOT`/`THUMB_UI_PLAYLIST`。给普通产物设置变量不等于隔离成功。实际启动后检查落盘位置，路径须在现有 `$CACHE` 权限范围内，不扩大 asset scope。
4. 标准原生构建入口为 `npm run tauri -- build --no-bundle`。执行前核对当前 CLI 帮助及配置，记录 Release 模式、完整命令、环境、日志、源码差异和 exe 实际位置；本方案不假定产物在某固定 D 盘目录。
5. 使用 `Get-FileHash -Algorithm SHA256 -LiteralPath <实际exe>` 记录产物，启动后再核对主进程的实际执行文件 hash。记录 `dist` 文件清单/hash、lockfile hash、构建参数及所有参与构建的未跟踪文件，避免“源码是新、exe 是旧”。
6. 正式性能构建禁用详细诊断埋点；若保留最小观测，A/B 必须一致且通过扰动检查。缺少构建绑定即停止性能比较。

## 5. 阶段 B：定义场景，先验证测量器

### B1. 先分清三种缓存状态

“本会话首次到达”只描述访问历史，**不等于操作系统冷缓存**。本轮不清 OS 文件缓存，不禁用杀毒软件，不宣称控制了物理磁盘冷态。

| 代号 | 定义 | 制备与证据 |
| --- | --- | --- |
| H：已落盘首次到达 | 目标缩略图/索引已存在，新进程尚未展示目标区域 | 在独立准备会话用正常路径生成目标，等待写入结束并记录索引/JPEG 清单与 hash；关闭进程。为 A/B 使用等价独立根，重启后目标未先进入视口；记录是否后台预取及真实命中 |
| G：需生成首次到达 | 测量动作前目标派生图未存在，动作导致现场生成 | 为每臂/每轮使用新的隔离根；固定同样的入库/打开动作；动作前检查目标文件和索引、启动至动作间请求。正常后台预热若已生成，标成实际混合状态，不能硬称全 G |
| R：同会话回访 | 本次会话目标已显示齐全，离开后按同样路线返回 | 从 H/G 完成状态进入，确认每个目标成功显示，再返回起点、等待固定时长、同路线拖回；记录内存/DOM 是否复用，不强制清内存 |

H/G 分别建立可复算的准备流程。若索引包含绝对路径、版本或 source 身份，不能盲复制目录；要验证复制后的每个目标仍能命中，否则各臂各自用等价准备流程。缓存状态以实际逐目标事件为准，不能只凭目录非空判断。

若 G 无法避开既有后台预热，先报告“正常启动策略下混合缓存的首次到达”及命中/未命中分布；纯 G 只作为另列诊断。不要关闭生产预热后把所得数字冒充正常体验。将缺失派生图的目标子集单列，不能从固定目标集合删掉其余目标。

### B2. 冻结最小动作矩阵

主场景沿用历史问题的真实入口、全屏小卡片档位及大幅拖动。先核对该机是否能复现历史 2560×1440/DPR 1；不能时记录新条件并重新建立基线，不直接比较历史绝对毫秒。

第一轮诊断只做 H/G/R、一个主入口、一个高密度档位、一个固定远端落点。历史 `.m3u8`/120 首语料可用于校验工具或复现旧测试。历史往返测试的可滚范围只有 1053 px，而全屏专项的列表视口高约 1400 px。这个量级的四列档场景无法保证起点和终点完整分离。主测试优先选能通过下述检查的长歌单，可先用数百首带独立封面的语料试跑，再按实际视口和预取范围加长。记录实际条目数、独立封面数和布局几何。

#### B2a. 主场景必须覆盖整屏未加载目标

1. 用全新测试会话从固定起点打开列表，选择距离起点数个视口的落点。先用几何验证起点与落点可见条目集合无交集，再用事件验证落点超出打开后实际触及的可见区和预取区。单靠滚动距离或曲目数不能通过。用准备会话冻结落点条目及封面身份，测量会话不先滚到落点取样。
2. 从打开列表前开始采集。拖动前，逐个确认落点条目本会话未进入视口，所有有封面的目标均无已加载或就绪的显示资源。用封面身份检查其他条目带来的复用，同时单列已发起但未完成的需求、预取和请求。纯场景要求拖动前这些计数也为 0。H 可以已有磁盘文件，G 另需确认派生图尚未生成。事件缺失时标为未知。任一臂在预检中无法证实整屏条件，就换语料或落点重新预检。
3. 正式 A/B 使用预检冻结的落点、路线和目标集合，记录指针按下时及松手时分别有多少目标已发起请求、加载或显示。快速拖动过程中可能提前加载部分目标。保留这些轮次和结果，不能因某一臂在拖动中加载得更快而排除它。需要观察“松手时也一张未加载”时，另外固定一条更快的真实远跳路线做专项诊断，逐目标记录松手前是否已加载。只有所有有封面目标都满足，才报告实际覆盖到该场景。程序直接跳转可辅助定位，结果单列。
4. 在 `protocol.md` 冻结语料、目标集合和判定规则。预检未通过时，120 首或其他短列表的结果只报告为混合视口，正式验收中的整屏首次到达标为待验证。

固定到 `protocol.md`：

- 应用入口、是否播放中/浏览中、owner、列表排序、筛选、当前歌曲、dock 状态。
- 窗口内尺寸、列表裁剪区域、DPR、zoom、系统缩放、卡片/封面尺寸、实际列行数。
- 起点、终点、实际 `scrollTop/maxScrollTop`、thumb 几何、拖动步数及间隔。历史 14×16 ms 仅作候选，先确认当前命中真实滚动条。
- 打开列表后至开始动作的固定等待；不要因某臂加载慢临时等更久。若准备条件未满足，按预登记规则中止该轮。
- 指针按下、移动、松手的真实时间；脚本必须在输入前安装观察器。正式场景不以直接赋值 `scrollTop` 替代真实拖动。
- 每站停留和截止点：本轮建议松手后 20 秒固定截止；不得临时延长。拖动期间已完成的目标松手等待记 0。
- 超时、产品错误、后台干扰、工具故障的处理规则，以及固定样本数。

### B3. 冻结分母和完成口径

1. 语料先产生稳定匿名条目 ID、独立封面身份和 `has-cover/no-cover/unknown` 标签。不能从“页面已有 img”的集合倒推目标，否则缺图会逃出分母。标签取得过程在准备阶段完成，不在被测会话预先加载目标。
2. 松手时冻结与真实列表视口相交、未被 dock/遮挡完全覆盖的条目集合。两臂几何/排序相同应得到同集合；不一致先排查工具或实际布局差异，不能偷偷取交集。
3. 成功封面定义为：正确条目对应当前资源，图片已解码且 `complete && naturalWidth > 0`，有效可见面积大于 0，最终展示层 `opacity >= 0.99`，连续两帧成立。这个值称**可见完成代理**，不是显卡实际 paint 时间。抽样截图核对；出现错图即产品失败。
4. 原生 `load`、`decode` 完成、发布、淡入结束分别记录。历史动画约 200 ms 只是线索，执行时查当前 CSS/逻辑；不要移除动画换取表面收益。
5. `no-cover` 占位正确可单列为成功状态，但不计为真实封面补齐；`unknown` 不能自动视为无图。报告完整分类分母。`has-cover` 分母为 0 时，封面补齐时间/比例标为 `not-applicable`，不能记 0 ms 或 100%；存在 `unknown` 时，只能称“已确认 has-cover 子集完成”，不能声称全目标封面齐全，正式接受前需补清分类或将该场景标为证据不足。
6. 虚拟化换 DOM 时追踪同条目及本次暴露 episode，不把旧元素 load 算给新条目。冻结目标在截止前离屏/卸载未完成要保留终态及原因，不能从结果剔除。

主指标与辅助指标：

| 指标 | 计算方法 | 用途 |
| --- | --- | --- |
| 松手至全部真实封面完成 | 冻结 has-cover 集合最后一个完成代理时间减松手时间；已齐为 0 | 首次到达主指标 |
| 松手空白数/比例 | 松手时未达完成代理的 has-cover 数/has-cover 总数 | 解释起点差异，不能用每张平均耗时抹平 |
| 松手至 90%/50% 完成 | 按同一冻结集合排序；已超过该比例为 0 | 看整体与尾部，0 饱和时不能强解释 |
| 单卡可见至完成 | 本 episode 真正可见至自身完成；已提前就绪单列 | 诊断等待分布；未完成为右删失 |
| 整段存在空白的时长 | 输入开始至截止期间，视口至少一张真实封面未完成的帧间隔之和 | 防止只优化松手后而把等待挪到拖动期间 |
| 空白封面面积积分 | 各帧未完成封面的真实裁剪可见面积×帧间隔 | 可选辅助，不替代主指标；面积算法需先验真 |

帧采样间断要记录 gap；不把最后一次观测无限外推。每轮必须同时保留目标数、成功、错误、超时、取消、删失和未知数量。一次性空白/永久缺图均在固定分母内。

### B4. 3 对 A/A 只检验工具

使用同一个 A 产物模拟两臂，交替顺序，主场景 H/G 各 3 对；R 附在同一会话后测。两臂缓存制备一致。目标是发现工具偏差，不从 3 对推出性能结论。

检查：实际运行 hash、前台可见、输入前起钟、同落点/目标、缓存状态、所有事件终态、截图与完成代理一致、松手已齐为 0、未知值不变成 0、统计器从文件读取实际配对数。主动让测试辅助器处理一次超时/缺失事件，确认它保留失败而非报成功；此为工具自检，独立于性能数据。

**扰动检查：**在固定缓存状态/路线下，比较最小标量采集与详细 trace，至少 3 对；不能两者都关闭所有观测后还声称测到了完成时延。详细 trace 采用有界缓冲、标量字段、动作结束后批量导出，不逐帧遍历全库、不逐事件同步写盘、不保存 DOM/曲目对象引用。预登记容忍值为完成时间差不超过 `max(20 ms, 5%)` 且长帧无明显增加；这是本轮工具门槛，不是已测事实。超出则只用详细 trace 做结构诊断，正式 A/B 用一致最小观测。无法量化扰动，结论注明该限制。

**B 通过标准：**无产物/分母/缓存分类错误，失败保留正确，基本时序自洽，A/A 无固定臂偏差。3 对不能证明零偏差；若明显不稳，先修工具并重做这一步。测试工具变化使指标语义改变时，作废旧批次的正式资格并保存历史原始数据。

### C3. 最小事件合同：先审查再补埋点

复用现有出口优先。若需改变业务文件或跨前后端观测字段，先由 Architecture Agent 审查：这只是诊断观测，不得改变调度、返回语义、权限、恢复次数或持久化协议。以下是**所需观测信息**，不是要求公开 API 增加全部字段。

每条事件至少关联 `runId / sessionId / owner / anonymousTrackId / demandEpoch / attemptId / requestId / edge / lane / outcome`；发布额外有当前 `generation/revision/publishGeneration`，恢复有 `parentAttemptId/recoveryEpoch`，按实际契约映射，不杜撰同名字段已经存在。资源共享与消费者必须分别编号，一次 native 请求可以对应多个消费者，不能重复算作多次生成。

| 事件 | 必要字段/说明 |
| --- | --- |
| `input.start`、`input.release` | 同一页面单调时钟；真实输入和实际位置 |
| `card.visible` | 本 episode、裁剪区域、真实可见；几何预取带进入另列 |
| `demand.publish` | 需求版本、可见/预取类别、匿名条目数 |
| `owner.receive/enqueue` | 接收时刻、入队时刻、去重/拒绝/缓存命中的原因 |
| `owner.dispatch` | 活动作业数、eligible pending 数、各优先级待执行数；空闲但不派发要给固定原因码 |
| `scheduler.enqueue/start/end` | 全局等待、原生请求身份、终态；与 owner 队列区别记录 |
| `native.admit/start/end` | 准入等待和真正工作区间；取消/过期/错误不可记成功 |
| `native.cache` | 索引命中、JPEG 命中、无图命中、未命中、损坏，各命中早返回必须覆盖 |
| `native.probe/decode/resize/encode/write` | 只记录实际执行段的时长与次数；未经过标为 not-executed，缺出口标 unknown |
| `asset.request/end` | 能观察则记录读取边界/状态；观察不到不能用 IPC 返回代替 |
| `image.decode/load/error` | 对应条目和发布身份；解码完成与原生 load 分开 |
| `store.publish/react.commit/presented` | 已取得资源到发布/DOM 使用/完成代理的时间，不能把 store 写入直接当显示 |
| `cancel/stale/recovery/release` | 原因、父作业、当前版本、资源引用变化及终态 |

**跨进程时钟：**页面 `performance.now()` 与 Rust `Instant` 各自单调，不能直接相减。前端发送/返回用前端时钟算总往返，后端返回或旁路记录本地分段 duration；按 request ID 对齐。只有建立并报告带误差界的时钟映射后才能画跨进程绝对时间线。不同作业 p95 之间不能相减得到某阶段 p95；必须先逐请求算区间，再汇总。

**匿名化：**现有诊断 ID 的 salt 随录制变化，不能直接跨运行拼接。测试 fixture 使用独立稳定匿名 ID，本地保密映射连接源路径；不要导出路径、歌曲名、歌词、封面字节或用户配置。若必须跨进程关联，用本轮不透明请求标识，不能把原路径当关联键。记录 dropped/capped，丢失关键事件的 episode 不能用于精确分段，但仍保留在端到端分母。

### C4. 按单卡解释，再汇总

从每个状态选 5 个最慢且证据完整的目标，并选 5 个普通目标作对照。输出逐卡表：

```text
匿名目标 / 缓存类别 / 实际 owner / 松手时状态 /
可见→需求接收 / owner队列 / 全局队列 / 原生往返 /
后端各本地段 / 返回→发布 / 发布→load / load→最终显示 /
取消重做次数 / 未知区间 / 最终结果
```

并发段会重叠，不能把所有作业总耗时相加当成视口延迟。先找决定最后完成的关键路径，同时看 90% 与整段空白，避免只针对偶然最后一张。

`diagnosis.md` 以如下格式给每个假设定性：事实→候选解释→替代解释→可区分两者的观测/实验→结果→仍未知。至少反证一个替代解释。没有证据就保持“假设”。

### C5. 候选选择表

| 观察到的主等待 | 首选调查/候选方向 | 必须排除/保护 |
| --- | --- | --- |
| 可见很久才收到 demand，后续很快 | 检查窗口发布、过期节流、可见/预取资格、批量发布遗漏 | 不把全部行标 urgent；确保快滑/反向/关闭不会遗留任务 |
| 已 eligible 的可见作业排队，预取占槽 | 检查现有优先级与 stale 清理，修正错误排序/取消链 | 先证明占用者和顺序；不直接增并发；避免饿死必要非可见任务 |
| 热盘命中但反复源探测/重验证占主导 | 检查索引命中路径及是否重复请求/重复读取 | 源变更失效、路径安全和错误语义不能削弱；新缓存合同需审查 |
| G 生成段主导，H 很快 | 在现有质量和档位约束下评估已测最贵阶段 | 不预设缩放必然主因；图像方向、透明度、损坏图与质量需回归 |
| native 已快返，前端发布很迟 | 检查 await 链、资源共享、批处理、状态提交 | 不绕过 decode/身份/lease；不发布已过期图 |
| load 已完成，最终显示迟 | 检查重复淡入、ready 重置、遮挡和渲染等待 | 修复错误重复流程；正常动画时长保持，不能仅删动画冒充加载优化 |
| 同资源多次生成/重新请求 | 检查身份、代次、缓存键、共享请求生命周期 | 合法不同档位/源版本不能合并；失败恢复与 stale 不能被吞 |
| 没有明确主因或观测扰动过大 | 补最小必要观测/交付缺口 | 不凭感觉重构，不一次尝试多个参数 |

**C 通过标准：**至少一个可操作假设具有当前证据、可反证预测、清楚的改动边界。否则停在诊断结果，不能用“可能是调度”直接进入优化实现。

- 不扩大默认并发、驻留上限、预取范围、超时、重试，不把整个列表预热作为默认“修复”。若证据最终要求其中一项，应另写预算与审查提案，不能藏在当前候选中。

## 8. 阶段 E：5 对探索，决定是否值得正式测

本轮预设 **5 对**探索；如资源限制选 3 对，必须在看结果前登记，且仅作探索，不作接受依据。A/B 顺序交替，两臂使用同 fixture、同缓存制备、同输入，按 H/G 分开保存，R 附测。不能 A 一口气跑完后才跑 B。

探索期间只比较一个候选，不边看数据边改参数。任何代码或完成口径变化都形成新候选编号和新批次。失败候选的原始数据保留，恢复 A 后再尝试下一个，不能只保留最好的一组。

### E1. 本轮预登记门槛

以下是**本方案提出的新工程验收规则，尚未测得，不是历史 SLA**。如现场条件需调整，只能在候选结果揭晓前由协调者记录原因、冻结新版本；看过结果后不能降低门槛让它通过。

| 项 | 探索进入正式实验的门槛 |
| --- | --- |
| 指定主目标状态 H 或 G | 松手全齐配对改善中位至少 `max(50 ms, A 中位数的 10%)`，5 对至少 4 对更好；3 对探索则 3 对都更好 |
| 因果预测 | 候选预期缩短的区间确有变化；如果端到端变快但预测不成立，先解释原因，不宣布根因已证实 |
| 另一首次状态 | 不出现持续的明显退化，配对退化中位不得超过 `max(30 ms, A 中位数的 5%)` |
| R 回访 | 新增错图/失败/超时为 0；已接近 0 的场景不能靠百分比衡量，补齐退化中位不超过 16.7 ms，p95 不增加超过 33.4 ms。这里 p95 指同一 R 场景每臂“每轮松手至全齐时间”的跨运行 p95，采用 nearest-rank（排序后第 `ceil(0.95*n)` 项）；不是单卡 p95，探索 n=5 时等于该臂最大值。比较 `p95(B)-p95(A)`，同时保留每对差值 |
| 起点与整段 | 同时报告松手空白、整段空白，不能仅主指标变好而其余明显变差 |
| 正确性 | 任何新永久缺图、错图、无限恢复、源更新失效、资源提前释放均不通过 |

达不到门槛：停止该候选正式 20 对，记录“未证明收益/退化/证据不足”。若只有某状态改善，则声明局部候选，另一状态继续受保护。不要为了保住改动改成与更旧、更慢版本比较。

## 9. 阶段 F：正式比较、独立回归与资源检查

### F1. 最小正式矩阵

主入口、主档位：H 与 G **各固定 20 对**，每对 A/B，各自附带 R；去/回分开统计，不能把 R 优势抵消首次退化。先完成这个最小矩阵，再考虑次档位/多站路线。

若候选仅针对一种状态，另一状态仍需回归对照；不得只测有利状态却宣称总体改善。正式 20 对不得包含工具 pilot、基线诊断和探索。固定 10 对 A→B、10 对 B→A，脚本记录顺序和实际启动 hash；每轮重建等价独立缓存条件。

正式阶段至少增加一组原有多站往返路线的回归检查：先 5 对，同样路线和停留；无明确退化可报告有限回归证据，若要声称与历史相同强度的往返收益保留则补为独立 20 对。不要为简单根因自动展开全部入口×布局×缓存×DPI 的巨大矩阵。

### F2. 统计器的明确规则

1. 对每个场景，逐对计算 `d_i = A_i - B_i`，正数表示 B 改善。同时给 A/B 各自中位和配对差值中位；两者中位数相减不一定等于配对差值中位。
2. 对 20 个 pair 重采样计算配对差值中位的 95% bootstrap CI：10,000 次、固定种子 `20261109`，采样单位是 pair，不是单卡。使用 percentile 法：将 10,000 个重采样中位数排序，取 2.5%/97.5% 分位，分位定义统一为 nearest-rank（第 `ceil(p*N)` 项，1 基下标）。另一首次状态的退化上界按 `r_i = B_i - A_i` 独立计算配对中位的同样 bootstrap 分布，取其 95% 分位作单侧 95% 上界。保留统计脚本、伪随机算法名称/版本、种子、输入 hash 和输出；不要跨状态混池。R 的 p95 按 E1 的跨运行定义计算，不能在正式阶段改成单卡分位。
3. 给出胜/平/负、每对原始值、p50/p90/全齐、松手空白和整段空白。相等才记平；测量误差范围另报，不事后修改平局定义。
4. 产品超时、错误和错图不剔除。全齐时间无法定义时记 `null + timeout/error`，显示截止时未完成数量；不能填 20 秒当成真实完成，也不能仅在成功子集上宣称通过。若新版本出现新增产品失败，本轮不得接受。
5. 单卡离屏未完成是右删失，单列数量和暴露时长；成功样本分位数只能标为“已完成子集”。不把删失样本当成 0。
6. 工具崩溃、错 exe、落点不一致、窗口最小化等可按事先规则标 invalid，保留原始记录与理由，整对重做；不得只重做表现差的一臂。固定 20 个有效 pair，同时报告全部尝试数；超过 4 对工具无效即暂停修工具，不无限补测。
7. 后台干扰按客观事件登记，例如进程抢前台/可确认的系统任务。不能看到 B 慢就推测有干扰并删掉；同时报告含全部有效运行与预登记排除的结果。

**正式接受门槛：**主目标状态配对改善中位达到 E1 幅度，95% CI 下界大于 0，至少 16/20 对改善；另一首次状态的配对退化中位不超过 E1 限值，且其退化的单侧 95% 上界不超过 `max(50 ms, A 中位数的 10%)`；R 满足绝对回归限值；主目标整段空白配对中位不得增加超过 `max(20 ms, A 中位数的 5%)`。CI 太宽无法排除退化时写“证据不足”，不以不显著冒充等效。正确性失败优先于速度收益。

### F3. Test Agent 独立验证清单

Test 读取最终补丁和协议，自己执行必要复现/验证并检查原始数据，不只复述实现者报告。

| 方面 | 最小验证 |
| --- | --- |
| 原始问题 | A/B 同入口首次到达；H/G 真实分类；关键事件和画面一致 |
| 相邻交互 | 快速连续滚动后停下、立即反向、离开/重开面板、切歌/切列表/搜索改变集合、关闭时仍有在途请求 |
| 页面归属 | 全部歌曲、播放列表浏览及播放中，按实际 owner 覆盖；共享组件影响 hero/菜单/侧栏时也必须检查 |
| 资源与身份 | 旧 generation 结果/error 不污染新图，多消费者共享时不提前释放、不中断另一消费者 |
| 失败恢复 | 正常图、明确无图、损坏 JPEG、删除派生图、pixels 回退也失败、多个消费者近同时 error；次数按恢复身份和 requestId 对齐 |
| 数据变化 | 同源更新后的封面正确失效；无图不永久掩盖后续新图；不同档位升级失败时已有可用图按原契约保留 |
| 播放/队列 | 当前曲目封面、dock/头图、队列浏览及播放操作未因封面调度变化退化 |

故障只注入本轮隔离缓存对应文件，保存原 hash/备份并恢复。若内存命中使故障无法触达，不强称已验证；自然重挂载、受控 DOM 重读、mock 注入分开报告。侧栏 `LibraryCover` 的历史恢复证据缺口仍需说明；本轮未触及且未验证不能写已解决。

### F4. 有界资源检查

资源不以 JPEG 文件大小或 IPC 字节推断。最终 A/B 干净专属会话做至少 1 对相同脚本：预热 30 秒、静置 15 秒、持续动作 600 秒、停止输入后 30 秒。实际墙钟核验，不靠 `--memory-seconds` 参数名认定运行时长。该一对仅筛大异常，不作 CPU 改善统计结论。

以外部采样器记录专属进程树主进程/renderer/GPU/utility 的累计 CPU 秒、private bytes、working set、PID/开始时间，处理子进程新增/重启；不要混入用户其他 WebView。现有 `coverlane-memory.ps1` 的能力以当前代码为准，缺 CPU/动态进程追踪就补辅助器或明确未覆盖。

关闭详细事件数组，或使用有界采集并记录丢弃量。查看活动最后五分钟每分钟中位、停止后资源和活动作业/lease 数是否收敛。不得新增无界队列/监听器/驻留；若 B 出现 A 没有的持续增长、未归零作业或明显内存阶跃，停止接受并定位。没有硬预算时不伪造“绝无泄漏”；若性能改动本身增加驻留，必须在 D 阶段审查时先冻结明确字节预算，不能事后解释。

大曲库、慢盘、高 DPI 作为扩展项，核心结论完成后按实际影响选择；未测就明示。1000 首不等于 1000 张独立封面，延迟注入不等于真实慢盘。
