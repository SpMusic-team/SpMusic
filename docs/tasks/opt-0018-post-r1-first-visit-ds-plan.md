# 第三轮列表封面首次到达优化

## 可直接发给 DS

> 请执行本文件。以包含 R1 的当前 develop 建立原生基线，缩短用户拖到本次启动尚未加载区域后，整屏歌曲封面实际可见的等待时间。先完成环境和测量器预检，再测 H、G 和真回访 R。用慢卡证据选一个改动，在同一基线上单独比较。按阶段保存记录，能继续就继续。工具不足时完成可做部分，交接下一条可运行的命令或明确需要补的工具。只报告亲自测得的结果和明确标记的历史数据。最终交付补丁、复现方法、独立验证结果和未覆盖项，由项目负责人决定合入。

建议优先级 P2。主入口为上一轮测试的播放列表，全屏小卡片，大幅拖动滚动条。先用一个布局完成闭环。其他媒体库入口只有共用变更或需要验证适用范围时再测。

## 起点与参考值

若同时执行[头图清晰度任务](hero-cover-sharpness-ds-plan.md)，两个 DS 先登记同一基线 SHA、各自 worktree、写集和本机测速时段。列表 DS 独占本任务的能力报告和运行目录。修改共享 hook、调度器、Rust 封面模块或测试工具之前，两边按文件确定唯一写入者；没有协调渠道时先做各自的只读诊断和独立文件。原生性能采样期间另一任务暂停本机编译、测试与采样。两项都有候选后，按头图方案在隔离集成分支比较列表单独版和组合版，检查头图升级与滚动同时发生的情况。

编写时本地 develop 为 `fb9f2db29c787e33682a2b2aa82c5047d98032d3`，包含 R1 合入提交 `73c2ba2`。运行时重新冻结完整 SHA。R1 从并发 2 起步，查询后端名额达到 3 才升为 3。前端查询失败或名额不足时继续按 2 工作。两臂保留真实查询，记录运行中实际生效宽度和时间。旧报告中固定并发 2、路径版初版及 R1 的实验 exe 仅供历史比较。

在 400 首、落点 112 张的上轮正式 A/B 中，R1 候选的 H 全齐中位为 1495 ms，G 为 3248 ms。各 20 对，配对缩短中位分别为 185.5 和 1195 ms。R 的 10 对数据中退化量的单侧 95% 上界为 +48 ms，尚不能排除超过 16.7 ms 的退化。以上为合入前候选的数据。第三轮的 A、B 都需重新构建并在同批环境实测。[R1 报告](../test/opt-0018-r1-formal-ab-2026-11-10.md)

## 第一步　确认 DS 实际能做什么

在仓库根执行以下只读检查。分别记录命令、退出码与版本。保存现有用户改动，在独立工作树准备 A、B。

```powershell
git status --short --branch
git rev-parse develop
git merge-base --is-ancestor 73c2ba2 develop
Get-Command git,node,npm,cargo,rustc
node --version
npm --version
cargo --version
rg -n 'queryPlaylistDecodePermitWidth|audio_playlist_decode_permit_width' src src-tauri/src
rg --files tools/thumbnail-benchmark
```

祖先检查退出码 0 表示包含 R1。若历史被重写，核对实际查询和生效逻辑，明确选定含 R1 的 A。记录 Windows、WebView2、机器、屏幕/DPI、可用空间、语料来源及能否启动并控制原生窗口。当前机器查不到旧的 `D:\opt0018-ab` 与 `%LOCALAPPDATA%/spmusic-coverlane/first-visit-20261109-104619`。两处均是过往本地证据位置。

每阶段开始核对上一阶段的能力记录。凡工具无法使用，当场将现象追加到仓库的 [DS 工具能力报告](../test/opt-0018-post-r1-ds-capabilities.md)，即使有替代手段、未阻断或稍后恢复也保留原事件并追加状态。记录时间、执行上下文与平台、工具及版本、实际调用、原始错误（脱敏）、原因及证据或未知、重试/替代及其证据性质、影响范围、相应调整和下一步。区分未尝试与已尝试失败。每阶段收尾检查有无漏记，将报告路径放入 checkpoint 和最终交付。若 DS 无法写仓库，按该模板输出可复制的完整 Markdown，写明待补录路径，将写入失败本身也记在表内。

## 第二步　恢复最小原生测量能力

1. 阅读在库 [封面测试工具说明](../../tools/thumbnail-benchmark/coverlane-README.md)。从 common 复用专属进程启动、CDP、隔离根检查和清单，从 fixtures 复用匿名身份与固定集合，从 page/stress 复用可见性与逐帧采集。阅读入口源码核对参数、支持的输入事件和结束条件。原有 open/scroll 用例覆盖的动作与本轮真实拖动不同。
2. 优先复用合法可读的长歌单。缺失旧私有语料时，在专属目录生成可播放的短音频、可区分的内嵌封面和对应 m3u8，记录生成方法、种子、顺序和摘要。先验证首尾音频能由应用正常探测、封面身份稳定且能落盘，再扩到约 400 首或足够形成完全独立落点的长度。记录独立封面数、原图尺寸/格式和不同封面复用情况。新语料的数字只比较同批 A/B。
3. 在专属工作树按工具说明对两个版本施加相同隔离补丁，核对补丁及摘要。选择 LOCALAPPDATA 下新建的实验根，为每次运行分配独立应用数据和 WebView profile。先在新根确认读写、asset JPEG 成功和路径归属。检查默认用户缓存不参与实验。按仓库锁文件准备依赖，运行 `npm run build`、`npx tauri build --no-bundle`，核验启动的是记录过 SHA-256 的 exe 和内嵌前端。初始 A/A 可共用同一个 A exe。
4. 若缺正式拖动脚本，在实验目录写最小驱动。通过专属 CDP 找到真实列表，测出滚动条滑块及轨道几何，安装观察器后依次发送按下、沿轨道移动、松开。在页面时钟记录事件与每帧实际 scrollTop。确认滚动条确实移动、窗口前台、起终视口不相交。保存匿名固定落点和抽样画面。给驱动留可复制的命令、工作目录和参数示例。
5. 首次只跑一次 H、G、R，确认每次有原生请求/缓存证据、目标身份和最终状态。若缺逐目标命中记录，先在隔离诊断构建补最小观测；缺记录写 unknown。资格判断所需观测如对时间有扰动，先验证同输入的缓存制备，再用轻量采集跑正式计时。比较两类构建的行为与覆盖，分别保留摘要。工具就绪后按旧协议 §B4 做 3 对 A/A，检查同臂噪声、顺序偏差、完整性。发现错目标或串缓存先修工具再复跑。

## 第三步　冻结动作和终点

| 场景 | 制备方法 | 运行时核验 |
| --- | --- | --- |
| H 已落盘，本次启动首次到达 | 准备会话按正常链路生成目标 JPEG 和索引，关闭后用同一隔离数据重启应用。A/B 各自准备等价根。 | 拖动前目标未展示、未持有或请求相关前端资源，落点命中已有派生图。记录源重验证和实际生成数。 |
| G 需要现场生成，本次启动首次到达 | 使用新的实验根打开同一歌单，按固定间隔发起拖动，保留正常后台策略。 | 动作前检查派生图和索引，动作中按封面身份核生成情况。预热已覆盖的目标标明；无法得到纯 G 时调整落点，仍不满足就单报混合场景。 |
| R 同会话真回访 | H/G 中等整屏全部显示，离开、固定停留，再拖回同一组目标。 | 记录离开时已齐数、回程目标集合、资源复用和回程单独耗时。 |

固定入口、排序、窗口/DPI、视图档、起终点、拖动步数/时长、启动至按下间隔和 20 秒截止。尽量复现 112 张落点，可用同机不同尺寸重新立基线，记录实际张数。准备会话先按条目身份冻结目标与有图标签。测量会话从打开前采集，核对拖前整屏未访问且未提前加载，松手按可见几何核对冻结集合。拖动中已显示的目标保留并计入。

主指标为松手到最后一张正确封面完成可见的毫秒数。采样要求图片解码成功、可见裁剪面积大于零、展示层 opacity ≥ 0.99 连续两帧，抽样画面对照。松手时已齐记 0。每轮另存按下至结束期间的视口空白时长、松手未齐数、50%/90% 到齐时间、掉帧间隔、失败/未知/卸载数。有图、明确无图、未知按固定集合分别报告。无法全齐保留失败和截止时缺图数。完整规则见[上一轮协议 §B](./opt-0018-first-visit-ds-execution-plan.md)。

## 第四步　在 R1 的真实关键路径上选一个实验

H、G 各取至少三次短诊断，另做真回访。记录进入视口、提出需求、owner 入队/占槽、调度器发出命令、Rust 缓存判定、读索引/源探测/解码/缩放/编码/写盘、收到路径、预解码、发布、实际图片 load、达到可见终点。给作业标注匿名源身份、资源档位、owner/generation、请求 ID、优先级、实际槽宽和占用者。不同进程只比较同一时钟内的耗时，靠请求 ID 关联。一次运行挑最后完成的 10 张及几张早完成卡，对照松手时各自等在哪一步。区分可重叠的工作、取消重做和未观测区间。

| 从慢卡需观察到的事实 | 可验证的单项候选 | 预测及反证 |
| --- | --- | --- |
| H 命中派生图，但同一来源在一次展示内多次做等价校验或读取 | 在已有请求生命周期内合并已证实的重复工作 | H 同源操作次数和该阶段延迟一起下降。检查更新源文件、删图、坏图恢复；若次数已为一次，转查等槽或展示尾部。 |
| H 或 G 可见目标已入队，前面被过期/离屏作业长期占用 | 修正具体 owner 的代次清理或现有优先级分配时机 | 被过期作业阻挡时间下降。反向拖回、换列表和连续滚动时核对丢图、错误发布、重复请求及预取饥饿。 |
| G 重复出现未命中生成，慢卡长时间缩放且直接延迟其后批次 | 先离线比较等规格缩放实现，固定输入、方向、尺寸、滤镜与质量，再让有胜算的一个实现进入端到端实验 | 对比输出尺寸、像素及极端长宽/透明/方向案例，记录单卡分布。G 应缩短，H 生成计数应维持为零。需要新依赖、改尺寸或画质时单列产品/架构取舍。 |
| 返回路径很快，但迟迟未发布，或同身份反复进入渐入 | 定位失效重挂载、重复重置或批量提交遗漏，修正已证明的具体事件 | 对应事件次数/区间及用户可见等待同步下降，保留正常首次渐入和坏图回退。 |

旧版 G 诊断的 Lanczos3 约 25–27 ms、编码约 2 ms 来自固定并发 2 的短样本，可用于选观测点。只有在新基线确认它影响松手至补齐时才选择缩放。若采样只表明排队长，继续查谁在占槽、持有多久、后端实际名额及设备压力。申请更宽并发、整库预热、扩大驻留、变更持久化格式等提案须先说明资源预算和适用条件。[历史细分数据](../test/opt-0018-job-diagnosis-v2-2026-11-09.md)

输出一页候选卡，写明一个主场景、慢卡样例、主因和备选解释、预期缩短的区间、能推翻它的结果、涉及文件、写入人、回退点。依 AGENTS.md 先完成触发的架构审查，再由对应实现 Agent 写代码。保留 R1 查询失败/低名额行为、取消和错误语义、坏图恢复与 URL 所有权。无可区分的假设时补观测，出现性能退化时保留负结果。

## 第五步　探索、正式对照与交付

1. 看候选结果前固定主场景、样本数、顺序、门槛、环境和统计脚本。本轮沿用旧协议 §E1/F2，统一用 A−B 表示节省。探索用 5 对，至少 4 对更快，主指标配对中位改善至少 max(50 ms, A 中位的 10%)，且候选预测的阶段确实改善。另一首次场景退化中位不超过 max(30 ms, A 中位的 5%)。不达标记录原因并撤回候选；下一假设用新编号和新批次。
2. 最终候选用相同轻量采集构建与 A 成对比较。H/G 各 20 对，各场景 10 对 AB、10 对 BA；附带同会话 R 并按来源分别报告。探索、工具试跑、历史样本不计入。对同一 pair 的耗时取差，再计算中位数。按 pair 做 10,000 次 bootstrap、固定种子 20261109，给 95% 区间、胜平负和逐对数据。主场景至少 16/20 更快，达到探索幅度且区间下界大于 0。另一首次场景同时满足探索退化限及其单侧 95% 退化上界 ≤ max(50 ms, A 中位的 10%)。
3. 主场景整段空白时长退化中位 ≤ max(20 ms, A 中位的 5%)。R 的配对退化中位 ≤16.7 ms，跨运行 p95 增幅 ≤33.4 ms，同时报告配对退化中位单侧 95% 上界；该上界若超过 16.7 ms，只能报告尚不能排除小幅退化。宽区间或资源不够跑完时列出已完成对数和剩余批次。异常运行、失败及排除规则按旧协议 §F2 处理。
4. Test 独立复算原始数据并检查快速反向、换歌单、离开/重开、切歌、正确封面、无图、损坏派生图回落、源文件更新、查询晚到/失败。按修改范围运行封面目标测试、`npm run lint`、`npm run build`、Rust 的 `cargo check --manifest-path src-tauri/Cargo.toml --lib --locked` 和 `cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`。至少做同脚本一对 10 分钟滚动，记录专属进程 CPU、private bytes、停止后在途作业收敛情况。输出每项实测、模拟、未测及原因。[命令和资源检查细则 §D4、F3–F4](./opt-0018-first-visit-ds-execution-plan.md)
5. 每个阶段结束在实验根更新一份 checkpoint，保存下面字段。正式报告给出能复现的脚本、命令、匿名输入摘要、逐轮 CSV/事件、失败样本和候选补丁。Test 撰写测试报告，验收后 Documentation 更新集成记录。仅在实验范围清理专属进程及临时资源。交付差异供审查。

```text
阶段 / 已完成条件 / 尚缺条件
A、B 源码 SHA / 未提交补丁摘要 / exe SHA256 / 实际运行路径
场景 / 实际目标数 / 命中、生成、未知数 / 实际并发宽度
语料、协议、脚本及结果路径和摘要 / 已完成的 pair ID
当前证据 / 待证假设 / 工具或产品失败及原始错误
下一条可运行的命令、工作目录、输入和预期输出 / 接手角色
```

恢复时核对 checkpoint 中的源码、exe、语料和协议。相同批次只补完整缺失对；任何一项变动另起批次。结果可标为达到门槛、仅个别场景改善、未证明收益、退化或证据不足。最终结论写明成立的设备、入口、布局和缓存状态。
