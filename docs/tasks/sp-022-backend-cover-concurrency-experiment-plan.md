## 背景与依据

目标问题是首次浏览未覆盖区域时，列表封面需要等待。现有资料的证据权重如下：

| 来源 | 可采用的结论 | 不可外推的部分 |
| --- | --- | --- |
| 基线 0N | 未覆盖区域真正可见至加载 p50 约 969 ms、p95 约 1,645 ms；已覆盖区域约 25 ms | 缓存状态不同，不能合并成统一延迟基线 |
| 基线 0Q | 同批冷缩略图输入的吞吐在请求并发 2 后饱和，优先调查 Rust 串行工作 | 直连代理绕过真实 UI，不能作为用户体验验收 |
| 基线 0R | 全局锁覆盖完整像素管线；该批冷路径解码约占门内 96%；取消后阻塞任务仍可能执行而 guard 已释放 | 锁内占比来自指定素材，不等于所有端到端等待的 96%；内存估算和收益推断仍待验证 |

0P 的“墙钟约等于最慢一路，所以完整管线真正并行、前端加槽可获约 50% 收益”已被 0Q 纠正，本方案不再据此立项。0R 提出的约 1.8 倍上限也是待验证推断，不是实验承诺。

## 目标

- 先确认后端并发、内存、取消和去重契约能否安全放宽，再定义最小 N=1/N=2 候选。
- 在前端视觉作业上限固定为 2 的条件下，区分安全修正的影响与增加后端准入的收益。
- 用独立代理测量、真实列表 UI 和长期资源证据决定采用、回退或继续定位。

## 非目标

- 初始计划编写阶段未运行测试、修改业务代码、构建或启动应用；当前安全基础阶段的代码、构建和隔离测试按上述授权执行，应用启动仍后置。
- 后续本实验不增加前端槽位，不同时改变预取、档位、几何、Object URL 所有权或交互呈现。
- 不迁移缓存键、存储或传输协议，不调整缓存容量，不引入依赖、权限、数据库、服务或音频引擎能力。
- 不做分片锁、大范围管线重构或整库预解码，不以隐藏占位、强制刷新、任意延时或重试掩盖延迟。

## 涉及模块、输入与输出

涉及模块为 Rust 列表封面准入与 `spawn_blocking` 生命周期、同键在途工作、现有缩略图 writer 与 session 检查。播放器大图 coordinator 保持独立；前端调度与命令契约作为回归边界。

输入：SP-022 任务卡、基线 0N/0Q/0R、当前工作树及其差异、现行架构文档与实现差异、可合法使用的匿名封面素材清单、可证明隔离的测试环境。

## 阶段与依赖

### 阶段 1：聚焦只读复核并固定设计

Architecture Agent 与 Rust/Tauri Agent 在 0R 结论基础上复核，不重复泛泛排查：

1. 确认所有列表入口、锁边界、共享 writer、客户端代次及播放器隔离，并列出依赖原串行保护的状态。
2. 定义有界准入 N 的确切保护区、FIFO 公平性、等待队列边界；permit 必须跟随实际阻塞工作存活，调用方取消不能提前释放仍在用的资源额度。
3. 固定同键单飞的键、注册/移除时机、结果共享、失败清理和 owner/waiter 取消语义；每个等待者仍须独立遵守自己的 session/代次，不共享其他请求的 stale 结论。
4. 给出明确的在途内存预算和执行机制，覆盖压缩输入、解码、缩放、输出、去重注册表及排队持有数据；仅有“最多 N 个”或前端 96 MiB 资源池不能证明 Rust 内存有界。0R 的 0.31–0.69 GiB 单请求估算需校验，不能直接用本机中位数作为安全上限。
5. 明确原有各处 `ensure_current`、受限路径、输入/尺寸限制、SPXR v1、缓存键、writer 队列上限、错误码和 `STALE_REQUEST` 语义的保持条件，并制定异常、取消、退出的释放证据；检查点数量以当前源码及 Test 纠错结论为准，不沿用旧基线的数量表述。

阶段出口：Architecture 给出可实施/需收窄/暂不可实施结论；Rust/Tauri 给出精确文件清单、必要安全修正和测量缺口。若 N=2 与内存上限无法同时成立，先记录障碍，不能直接加槽绕过。需要突破非目标时，由 PM 另立范围，不自动扩大本实验。

### 阶段 2：形成最小候选并冻结比较对象

当前用户已要求推进安全基础，由 PM 按架构结论定界最小候选：后端有界准入、必要 singleflight/内存控制、取消安全生命周期，N 先限 1 与 2；前端固定 2。`Cargo.toml` 仅用于明确实验 feature 等本轮必要配置，不增加依赖。需要超出当前明确写入清单时，先由主协调收敛原因和单 Owner 清单，再实施。

| 比较对象 | 定义 | 用途 |
| --- | --- | --- |
| A0：原始现状 | 冻结执行前工作树、差异、构建和缓存条件，保留既有取消行为 | 复现既有性能与失败；不能作为未来安全回退实现 |
| A：安全 N=1 | 必要安全修正与 B 完全相同，后端准入 N=1 | 安全控制组；A0↔A 单列安全修正及基础重构的影响 |
| B：候选 N=2 | 同一实现、同一边界与资源预算规则，仅 N 改为 2 | A↔B 测量增加后端并发的收益与代价 |

若预算不足让 B 达到两个在途任务，必须在结果中呈现实际并发，不能只凭常量为 2 声称测过并行。A0 与 A 不得称为“逐位等价”；取消与去重行为修正可能改变语义。源码与运行身份按测试计划记录，不将不同构建、缓存状态或安全修正混成一个 A/B。

阶段出口：Rust/Tauri 提供实现自查、必要构建与针对性验证证据；Architecture 对实现边界复核，随后交独立 Test。该安全基础出口现已通过，最终独立报告已核对；仅代表可以准备下一层实验，不得直接跳到 UI 或长期资源验收。

### 阶段 3：独立验证，逐层推进

Test Agent 按 [独立测试计划](../test/sp-022-backend-cover-concurrency-test-plan.md) 执行，细节以该文件为准：

1. 先验证隔离目录、缓存层级、样本和构建身份；不能证明隔离则停止缓存重置和动态注入。
2. 优先验证准入上界、同键单飞、取消/stale/错误清理、退出与预算压力等安全行为。
3. 在固定素材、固定缓存起点的交错配对中比较 A/B 冷吞吐，另列 A0/A 与热态回归；代理结果只决定是否进入 UI 验证。
4. 使用真实 Release WebView2 列表验证同卡首次可见至加载、完成率、帧与长任务，同时观察播放器、快返、切列表及失败分支。
5. 按长期资源协议验证 Rust、Renderer/GPU、受管 Object URL 与磁盘写盘资源是否有平台并回落；不能以短测替代长跑。

仅操作测试专用根目录与派生缓存副本，不搬移、清空、重命名用户应用缓存，不改用户媒体。设置环境变量不能单独证明 Tauri 应用目录隔离；隔离路径和实际读写位置必须有证据。样本使用匿名标识，禁止把私人绝对路径带入公开报告。

### 阶段 4：采用、停止与回退

测试计划中的吞吐/UI/资源数值均为本实验建议阈值，待未来正式执行前由 PM 固定版本和判定口径；不是现有产品 SLA，也不改变 SP-022 未验收的状态。硬性契约、安全上界和完成率证据不以平均吞吐收益抵消。

| 条件 | 决策 |
| --- | --- |
| 阶段 1 安全设计不成立或隔离无法证明 | 停留在设计/环境阶段，记录缺口，不运行动态实验 |
| 取消后真实在途量超上界、预算越界、同键重复失控、stale 跨代提交或原有契约回归 | 立即停止 B，保存证据，退回安全 N=1；修复后重新验证 |
| 代理吞吐未达到固定收益阈值，或结果受漂移/缓存污染影响 | 不采纳 B；前者回到分段定位，后者补有效对照，不转向前端加槽 |
| 代理有收益，真实 UI 无稳定改善或帧/完成率退化 | 不宣称体验优化完成，保留安全 N=1，定位剩余队列/发布成本 |
| 短测通过，但长跑资源不收敛或数据不足 | 不采纳 B 为最终配置；保留证据和待验证项 |
| 契约、代理、真实 UI 与长跑均达固定门槛 | PM 据独立报告决定采用 N=2，记录适用素材/环境与残余风险 |

回退指恢复**安全 N=1 的准入配置**，保留已验证的取消安全等必要修正；不因取消 B 重引入 A0 的提前释放缺陷。如安全基础本身未通过，则隔离实验候选，不能宣称安全 N=1 已可交付。任何临时探针须有界、默认关闭，并在最终交付前撤除或另行明确其保留范围。

只有后端通过且证据显示前端 2 槽再次成为瓶颈，才另立前端 2↔3 实验；不包含在本任务内。

## 验收标准

初始计划阶段完成条件：任务字段完整、比较对象明确、先后依赖与停止/回退决策明确；独立测试计划覆盖相应证据，引用可追溯；该阶段无业务修改或执行结果声明。

安全基础阶段完成条件：Architecture 的安全契约与实际实现一致；Rust/Tauri 自查、主协调最终仓库检查及 Test 独立安全证据齐备；安全缺口逐项有通过证据或明确剩余项；默认 N=1、N=2 feature 与前端固定 2 可核对；未启动应用、未触碰用户缓存。主协调已汇总阶段通过证据并核对最终独立报告；不能把历史 P2 报告当作本轮性能验收。

未来实验完成条件：所有阶段都有负责人、构建/样本/缓存身份和出口结论；独立报告可复算安全与收益判定；未满足项标记未验证；PM 记录采用或拒绝 B 的依据。拒绝候选可以完成实验结论，不代表 SP-022 整体性能目标完成。

## 风险与缺陷专项

- 复现：按 0N 首次浏览未覆盖区观察延迟，按 0Q 冷缩略图直连输入观察吞吐饱和；未来在隔离环境重建，旧数值只作历史参考。
- 因果链：首次浏览缓存未命中 → 列表请求经过全局串行管线 → 服务吞吐限制与前端排队 → 可见封面延迟；其他端到端成本仍存在，不能预定唯一根因。
- 取消风险链：调用方取消 → async guard 提前释放 → blocking 工作仍存活 → 实际并发/内存上界失守。完成条件须观察工作结束前 permit 仍被占用，取消后最终释放且新任务不饿死。
- 同键与预算风险：不同曲目可能共享原图，放宽后会重复解码；内存需覆盖实际同时持有缓冲，writer 命中/写入/淘汰与退出均需验证。
- 原始路径、相邻路径和失败分支：冷首次、热重访、同键/异键、取消/stale、跨列表、播放器大图、坏图/过大输入、写盘失败、关闭退出；详细步骤见测试计划。
- 性能证据：逐轮吞吐、端到端分位数及有效分母、真实在途峰值、内存与 URL 平台/回落、失败/取消终态齐全；缺失项不能用成功均值代替。
- 临时缓解：本方案没有临时缓解承诺。N=1 是实验控制与回退配置；保留原性能限制时，Owner 仍为 Rust/Tauri Agent，跟踪任务为本卡与 SP-022，不标记“问题已修复”。
