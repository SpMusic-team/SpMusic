# 任务：缩略图清理、基线与分阶段优化

## 背景、目标与范围

播放列表滚动封面加载经过前端排队、完整曲目 hydrate、后端缩略图读取与转换、二进制返回及浏览器解码。此前调查指出重复读取、冷路径图片计算以及串行请求链可能影响耗时；历史代理实验不能替代当前代码和真实 UI 的测量。

本轮按用户明确授权执行：先清理无用探针，检查全仓库改动并提交推送，固定该版本为基线 B0；随后依次处理 IO、后端原图转缩略图、前端获取三个环节，每阶段独立验证与提交。优先级 P1，依据是已批准的核心播放列表性能修复。

非目标：音频引擎替换、媒体库或数据库建设、在线服务、无关样式迁移、依赖升级及大规模公共模块重构。不预设每个候选必然有收益。

本任务的实现与测量交付已完成：完成探针清理、固定已推送基线、三个环节的顺序改动及独立对照。完成结论仅覆盖本次用户请求和下述场景，不代表 SP-022 整体发布验收、所有回归全绿或三个环节分别都已提速。最终报告/工具提交、分支推送与工作树洁净核验由主协调在交付收口时记录，本文不提前声称这些最后 Git 操作已执行。

## 输入与输出

输入包括用户授权、当前工作树、既有 SP-022 调查和测试报告，以及本轮 Architecture Agent 的契约结论。已存在但未提交的改动应逐项审查，不以恢复工作树的方式丢弃。

输出包括可追溯的 B0 提交、三个阶段的独立提交及阶段版本号、必要回归覆盖、同条件比较报告和最终干净的 Git 状态。性能原始数据保留在分配的测试产物位置，构建产物、临时日志和用户音乐文件不入库。

## 当前决策与证据边界（2026-10-21）

- B1 与 B1b 均完成 83 张固定素材的五对代理。冷源定位的配对耗时降低中位分别为 8.29% 与 7.86%；完整定位→像素管线没有稳定净收益证明。定长读取未证明解决首次缓存内容校验开销，不把小块读取假设当已证根因。
- 重复热访问诊断表明新文件第一次内容核验明显慢于随后访问，但该诊断不是正式交错配对，也没有分离 OS 或防病毒过滤器，不能泛称所有热访问慢五倍，不能据此宣布完整热管线提升。准确数字以 Test Agent 的[对照报告](../test/sp-022-thumbnail-optimization-comparison.md)为准。
- 阶段二 2× 中间尺寸候选因棋盘高频测试出现可见网纹而拒绝；B2 改为至少保留 4× 目标尺寸再做 Lanczos3，播放器策略与 N=1 不变。冻结版本 208 项非忽略回归已独立通过；所选质量图允许作为保守候选，不代表逐像素等价或全部 48 图审阅。
- B0↔B2 五对中，128px 冷转换配对耗时降低中位 38.61%（5/5 更快）；256px 冷为 -0.57%（2/5），512px 首次升级为 -2.51%（1/5），完整 256px 冷管线为 +3.70%（4/5），热管线为 -3.87%（0/5）。B1b↔B2 隔离转换增量的五对再次支持 128px 冷改善 36.75%（5/5）。代理结论限于 128px 冷转换，保留高档位和热态退化信号；真实 UI 改善另按下节完整测量报告。
- 3a 的证据链是 metadata loading 时 grid 尚未挂载，内容窗口监听 effect 提前返回，ready 后没有补装 scroll listener；新位置缩略图可到 ready，但内容仍未挂载。修复已在 `f3f1cc4` 独立提交，200 卡 loading→ready→滚动的旧版失败/新版通过反证成立。3b 在 `333bad4` 改为视觉队列消费轻量封面命令，保留独立元数据通道；未把 ready 状态当作原生图片 load，也未把两类收益混为同一指标。
- 真实 UI 对照直接使用用户给定的 `E:\Music` 与 `E:\temp` 路径；测试副本禁用原生文件选择器，数据与缓存隔离。首开缺口与列表重开后的速度分开报告，不通过文件选择窗口寻找已知文件。
- 构建、即时复制测试程序及身份/测试清单校验必须占用同一独占窗口；不能只依赖 cargo 锁，以免共享 target 后续构建覆盖待复制文件。正式计时不与其他构建或 UI 回归并行。

## 最终真实 UI 对照与限定验收

使用 `E:\temp` 中实际播放列表对应的 1797 条曲目，在相同 level 0、2560×1439、DPR 1 下完成五组 B0/B2/B3 对照。Test Agent 独立核对身份、目标集合及完成口径：每臂首次访问区域均为 **700/700 原生图片实际 load、0 失败**；每臂回访 **350/350 已经就绪**。这里的“首次访问”指本轮应用会话中的新区域，不等于已控制 OS 冷缓存。

| 对照 | p50 配对耗时降低中位 | p50 更快组数 | p95 配对耗时降低中位 | p95 更快组数 |
| --- | ---: | ---: | ---: | ---: |
| B0→B2 | 5.58% | 5/5 | 7.34% | 5/5 |
| B2→B3 | 3.73% | 4/5 | 4.72% | 5/5 |
| B0→B3 | **10.34%** | **4/5** | **10.77%** | **5/5** |

各运行 p50 的跨组中位数为 B0/B2/B3 **1372.8/1290.6/1258.8 ms**，p95 对应 **2581.0/2412.3/2278.7 ms**。这些是各臂分位数的中位数，与逐组先计算改善比例再取中位数不是同一统计量，不能由两个中位数相除替代上表。

首开显示另有一组 B0/B3 反证：首屏两臂均 21/21 完成；随后新增可见目标 140 个，在相同观测期限内 B0 为 **0/140**、B3 为 **140/140**。此单组结果连同 200 卡受控回归支持监听生命周期修复，不用于声称首开 p50/p95 提升百分比，也不把 B0 未完成目标当作已加载样本。

主协调最终 Rust 回归为 **208 passed / 0 failed / 2 ignored**。前端核心封面、元数据分离及监听生命周期验证通过；外围 Management/Motion 用例仍有未全绿的残余项，准确明细见 Test Agent 的对照报告。本任务不把核心通过扩写为全仓库所有回归通过，也不据此批准 SP-022 整体发布。

限定结论为：本轮实现与测量交付完成，所测真实列表场景相较 B0 的完整可见加载延迟改善约 10%，首开监听缺口获修复。IO 独立整体收益、高档位与热态代理收益未获同等证明；其他布局/DPR、全部主题/格式、长期资源与正式发布仍不在此结论之内。

## 观测、因果链与比较口径

已知代码调查发现热命中前仍可能读取原图与哈希、获取封面可能读取完整曲目、前端同一槽位串行执行多步；它们各自对当前等待时间的贡献仍需本轮测量。不能把历史冷路径占比或旧并发候选吞吐当作当前版本结果。

测试需固定提交、构建模式、机器、输入集合、封面大小与格式、目标像素档位、请求顺序、并发度和滚动脚本。分别记录冷缓存、热缓存、首次访问、重访和快速滚动；每个条件重复运行，报告样本数、p50/p95、总完成时间及波动。冷缓存清理只针对已核实的应用测试缓存位置。

主要用户指标为可见到自身图片 load 的耗时和完成率；分段记录前端排队、hydrate 或封面定位、后端准入、IO/哈希/缓存、解码/缩放/打包、IPC、前端转换/解码。同步观察滚动帧和内存。若只能完成后端代理或合成输入测试，明确覆盖范围，不推导真实 UI 改善。

对耗时指标统一使用 `(B0 - 阶段值) / B0 × 100%` 计算累计变化，并与上一阶段报告增量变化。吞吐使用独立公式并标明单位。对差异接近波动、条件不一致或缺少端到端证据的结果，标记“未证明提升”。没有收益或出现退化时如实记录，调整或撤下该候选，不用增加并发、延时、重试或丢弃需求掩盖问题。

## 边界、回归与风险

架构审查必须明确前后端类型和 command 契约、文件权限校验、内容身份与失效策略、缓存容量、去重、准入、错误返回及取消清理。缓存键不能仅凭未验证的文件名或时间戳假定内容未变；并发优化不能无界放大解码内存。

回归覆盖原始下拉加载、返回已访问区域、同封面多曲目、目标档位升级、快速切换列表、源文件替换、无封面、损坏封面和请求失败；检查无陈旧结果覆盖、槽位泄漏、Object URL 泄漏或成功率下降。运行适用的前端构建与 lint、Rust 检查及针对性测试，完成独立 Test Agent 验证后由主 Agent 收口。

风险包括本地冷热缓存难以完全隔离、异步缓存写入影响重复测量及测量本身扰动。报告保留环境限制、高档位/热态退化及外围管理/动效回归残余；不能以构建成功代替性能验收，不能把未覆盖场景写为通过。本轮按根因优化交付，不把临时缓解标记为完成。
