# 任务：停滚后可见封面加载优化与回滚验证

## 背景、目标与范围

用户认为上一轮约 10% 的图片 load 改善仍明显慢于目标视频，明确授权直接修改、测试，没有明显改进则回滚。实际视频中桌面网格停驻后出现逐行补图；目标视频手机单列在高速滚动时也会缺图，停驻后封面较集中出现。两段视频的屏内图片数量、尺寸和缓存状态不同，只用来定义体验方向，不能直接作为同负载速度基准。

本轮目标是减少同一 SpMusic 布局下从停滚到屏内大部分真实封面可见的等待，尤其避免可复用缩略图被冷计算阻塞。优先级 **P1**：已获用户批准的核心播放列表体验修复。

非目标：改变用户布局以减少图片数、缩短动画掩盖等待、默认提高解码并发、降低最终清晰度、引入数据库或依赖、改动媒体文件及正式应用缓存、修复无关媒体库功能。

## 基线与回滚边界

- 本轮基线为 `f063f70ba943214421892d768d1eaa098f0a6c00`，执行分支为 `codex/playlist-visible-latency`。此前快速索引、全部歌曲布局和上一轮缩略图改动均属于基线，必须保留。
- 冻结基线及各候选的源码、匹配前端资源、Release 程序身份。基线不能使用上一轮 B0/B3 的旧程序替代。
- 若没有达到下述明显改进门槛，或正确性、质量、资源出现不可接受退化，只回滚本轮业务改动；保留本任务卡、测试证据和未保留原因。不对基线及之前版本做破坏性重置，也不覆盖他人在本轮新增的改动。

## 验收与测量口径

1. 使用 `E:\Music` 与 `E:\temp` 中已知真实播放列表路径，测试副本禁用原生选择器，应用数据与缓存隔离。正式工具默认 **level 1、11 列、2560×1439、DPR 1**，记录实际列表摘要、布局、窗口、可见目标、程序/资源身份并核验两臂一致；不能用更稀疏布局替代密集网格负载。
2. 分开测量派生缓存冷、派生磁盘热但前端未驻留、前端内存重访：冷态使用独立缓存；磁盘热态通过新进程/新 profile 重复使用本臂缓存，不跨臂复用；内存重访在同一会话返回旧位置。没有控制 OS 冷缓存时明确说明。首次加载与回访分别统计，已就绪目标不能伪造为新的 0ms load。
3. 主指标为每次停滚后 **90% 屏内有封面目标首次可见的等待时间（T90）**。冻结真实裁剪后的目标集合，区分无封面、不可用、错误及超时。可见信号为实际图片完整、有效 opacity ≥0.99 后的 rAF 代理，不是 ready 状态、单独原生 load 或物理屏幕 paint 证明。首次预览可见与最终质量就绪分别统计；最终质量按基线同一卡片的实际 natural edge 核验，不能通过永久停留 128px 通过验收。
4. 正式计时前已冻结“明显改进”门槛：同条件五对交错测试，每运行四个停点 T90 的 nearest-rank p95（四点时等于最大值）为比较量，配对降低比例的中位数 **至少 20%**，且 **至少 4/5 对更快**。不得看到结果后降低门槛或换主指标。
5. 额外冻结最终质量的时序守门：最终质量 T90 的每运行 p95 相对基线，配对退化比例中位数不得超过 **10%**；最终尺寸及完成数量必须全量达标。即使首次预览改善 ≥20%，最终清晰图显著推迟也必须回滚。
6. 所有模式及返回位置保持完整目标分母，**problems=0、censored=0**，最终完成率不低于基线，不能只对成功样本算分位数。首屏、新位置、快滑停驻、反向重访及面板重开均需覆盖；冷与热分别判定，不用热态收益替代冷态结论。
7. 核心 lint/build、Rust 回归、封面/元数据解耦、取消/过期、分辨率升级、URL 释放及失败恢复通过。既存失败需与本轮新增失败区分，不能声称全仓库回归全绿。
8. 正式计时前已冻结资源守门：Rust 采样 private 峰值跨运行中位数的增量不超过 **max(16 MiB，基线的 15%)**；Renderer/GPU 各自采样 private 峰值中位数增幅均不超过 **15%**；帧时间 p95 增幅不超过 **10%**，长帧数量不得系统性增加。另检查在途/驻留预算，有限采样不作为长期无泄漏证明。

## 缺陷专项与风险

复现方式：实际播放列表进入密集封面网格，快速跳至未驻留位置后停滚，观察整屏占位与逐行补图；对基线与候选重复同一滚动序列。录像不能证明当时运行版本和缓存状态，实际程序身份须由本轮测试确认。

已知代码证据包括前端两槽覆盖源读取到浏览器 decode 的整条作业、后端唯一许可位于原图读取/哈希及派生缓存检查之前。待验证假设是热请求被冷任务阻挡，以及可见高档转换拖延首次成屏；具体贡献必须由 A/B 和完整 UI 对照确认，不能据代码结构直接宣布根因已消除。

需要保持的因果链与边界为：视口需求变化 → 有界队列/许可准入 → 源校验与缓存/转换 → Promise 与过期检查 → BMP/图片解码 → 状态发布和可见卡片。跨层命令、空封面、错误、路径安全及生命周期契约沿用架构审查结果。

- A 风险：冷 miss 增加一次读取；等待冷许可时不得积压大块原图；不能信任文件名或仅凭 mtime 绕过内容/路径校验。新增预查可能持有约 16 MiB 原图，且既有损坏派生文件读取上限约 36 MiB，二者可能重叠；不声称整个 IO 峰值仅 16 MiB。测试命中绕过冷队、损坏缓存、源变化、取消与共享任务结果。
- B 风险：预览后升级增加总计算，重排可能饿死升级或后台任务；旧图及消费者 URL 所有权不能提前释放。测试快速换视口、已有清晰图不降档、升级失败保留旧图和所有可见项最终恢复目标尺寸。
- 禁止通过吞错、扩大超时、无界并发/重试、减少目标、隐藏占位、强制刷新或删断言制造改善。若只是局部临时缓解，明确适用边界与剩余风险，不宣称完整达到目标视频。
