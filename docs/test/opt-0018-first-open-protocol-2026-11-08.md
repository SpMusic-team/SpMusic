# 场景 B「首次打开来源」正式测试协议（预登记）

> 在正式批次开始**之前**固定，不可事后修改。
> 本协议与场景 A（「新应用缓存启动、准备后打开列表」）的既有 A/B 结果**完全独立**，不混合、不拼接。

## 1. 场景定义

| 项 | 定义 |
| --- | --- |
| 场景名 | **B. 首次打开来源** |
| 与场景 A 的区别 | 场景 A 在未计时的准备阶段已激活来源、生成目标缩略图；场景 B **在第一次激活来源之前**开始记录，包含扫描、元数据、首次缩略图生成的全部等待 |
| 缓存 | 每次运行使用**全新应用缓存根**（运行前删除）+ **全新 WebView2 profile** |
| 禁止 | 准备阶段不得预先打开来源、不得生成任何目标缩略图 |

| 项 | 值 |
| --- | --- |

| 可见判定 | 与正式 A/B 完全相同：`complete && naturalWidth > 0 && opacity >= 0.99` |

## 3. 计时口径

- `t0` = **点击「打开音频」（首次激活来源）之前**，在页面内、同一执行上下文读取。
- 所有时间**相对 t0**；不报绝对 `performance.now()` 值。
- 就绪时间由**页面内逐帧采样**得出，不用外部轮询结束时间。
- 结束条件：固定 8 个 cohort 全部满足可见判定。
- 首次激活后进入播放器界面，需要再点「播放列表」才到列表；**该点击在测量窗口内**，属于首次打开的必经路径。

## 4. 有效性门槛（任一不满足即判 invalid，不得计入统计）

1. `cacheEmptyBeforeAction`：动作前缩略图与封面缓存文件数为 **0**
2. `sourceNotOpenBeforeAction`：动作前 `[data-playlist-track-id]` 数量为 **0**
3. `thumbnailsProducedByThisRun`：动作后确实生成了缩略图（证明是本次产生）
4. `clockCalibrated`：页面内自括 IPC 时钟标定成功
5. `cohortReached`：最终 8 个 cohort 全部达到可见判定
6. `noCoverWorkBeforeAction`：不存在 `sentMs < -5` 的封面请求（证明工作未被提前完成）

**已提前生成目标缩略图的运行不得冒充冷加载**，一律作废并记录。

## 5. 样本与顺序

- **20 对**，每对含一次基线运行与一次候选运行。
- 顺序按对奇偶交替：奇数对 A→B，偶数对 B→A。**执行顺序由脚本决定并实际记录**，不依赖文档声明。
- 每对运行之间不共享任何缓存或 profile。

## 6. 失败与超时处理

- 任何运行超时（结束条件 60 秒未达成）、报错或门槛不通过，**保留原始记录**，计入失败率，**不以重试掩盖**。
- 允许为恢复环境而重跑整批，但**旧批次完整保留**，不挑选拼接。

## 7. 预登记判定门槛

| 场景 | 指标 | 门槛 |
| --- | --- | --- |
| 首次打开来源 | 从 t0 到 8 张全部可见 | 配对差值中位数 **≥20 ms 且 ≥10%**，且 bootstrap 95% CI 下界 > 0 |

判定三态：**改善 / 无明显改善 / 退化**。CI 跨 0 或点估计未达门槛 → 判「无明显改善」。不利方向同时超过门槛且 CI 上界 < 0 → 判「退化」。

## 8. 整机负载

- 全程采样：CPU%、可用内存、磁盘活动，1 秒请求间隔。
- **实际采样间隔按样本数与跨度如实报告**，不假定每秒一个。
- 外部干扰仅在客观证据下标记；「未记录」不等于「已证明无干扰」。

## 9. 本轮不主张

- 不主张通用产品性能，仅本机、本曲库、本场景。
- 20 对样本不支持尾延迟结论。
- **不与场景 A 的结果混合**；两种场景可能得出不同结论，将分别回答。
- 不修改产品代码、不调整调度与并发。
