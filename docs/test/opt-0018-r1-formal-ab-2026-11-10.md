# OPT-0018 自适应封面并发正式对照

R1 在测试机上缩短了首次拖到新区域后整屏封面补齐的等待。已落盘和现场生成各 20 对，候选均更快。真回访的配对中位也有所改善，但样本不足以排除超过原门槛的小幅退化。

## 测试范围和产物

- 本机原生 Tauri / WebView2、400 首歌单、全屏小卡片、落点 112 张封面。H 表示磁盘已有缩略图，G 表示需要现场生成。每对固定目标集合，交替运行 A/B 顺序。
- 两臂都从 `735168a` 构建，使用相同的隔离补丁及轻量采集。A 为固定并发 2，B 为独立查询后端名额的 R1 实验候选。B 此时仍含诊断覆盖代码。
- A 的 SHA-256 为 `83D57C1DB5B2DA704376F4493DB0C1FD1EE52F514FF9440DCEABFF5A98436A7E`。B 的 SHA-256 为 `9AAB48CA92CFD3EEB87B22DEFBB78D143CBF6092D8B4EB8FBA5DC7B7D663E830`。
- H、G 和回访批次截至 2026-11-10 00:25，`73c2ba2` 于同日 00:29:40 提交，均为 Asia/Shanghai。测试运行在各自的独立工作树和固定原生 exe 上。Vite 开发服务器的文件监听错误发生在另一套浏览器测试环境。

## 可见补齐时间

差值为每对 `B − A` 的中位数，负值表示候选缩短等待。各臂中位数和配对差中位数分别计算。

独立复核逐轮核对了 100 份运行记录，全部补齐 112 个目标，各对目标集合一致。区间以配对为单位做 10,000 次 bootstrap，固定种子 `20261109`，使用 percentile 法。真回访要求同会话、同一批目标、离开前全部显示。配对差的单侧 95% 上界为 **+48 ms**，因此结论为「未观察到回访退化，证据不足以通过原 16.7 ms 门槛」。A/A 的波动用于描述测量精度。

## 合入版与兼容行为

`73c2ba2` 经架构复核后合入本地 develop。最终实现移除了实验覆盖和详细埋点。列表并发初始为 2，后端实际名额至少为 3 时升到 3，并立即检查队列。名额不足、未知或查询失败时保持 2。

新命令为独立的只读查询 `audio_playlist_decode_permit_width`。既有 `audio_begin_playlist_cover_window` 保留数字返回值。旧前端仍沿用原命令，新前端遇到不支持查询的后端时按并发 2 处理。此前返回值改为对象所带来的兼容风险属于已放弃的方案。

合入版的独立回归用例覆盖查询晚到时立即启动第三张，以及查询失败后按原宽度继续。前端构建、lint、相关测试与 Rust 检查通过，Rust 库测试 401 项通过、0 项失败、10 项忽略。上述速度数据属于合入前候选。最终提交的原生测速、真实低核设备、原生切歌单和长时间滚动资源表现仍待验证。发布说明应按后端实际名额说明适用范围。
