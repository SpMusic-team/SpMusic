# 播放列表封面后端有界并发测试计划

## 1. 状态、目的与边界

**当前仅获授权编写计划；没有执行测试、性能采集、构建、故障注入或启动应用，没有修改产品代码。** 本文与 [实验计划](../tasks/sp-022-backend-cover-concurrency-experiment-plan.md) 配套，不批准候选实现、诊断能力或测试运行。未来由 PM 明确批准范围、Architecture 确认契约、Rust/Tauri 提交实现与证据包后，再按闸门逐步执行。

优先判断“后端有界并发能否减少首次浏览未覆盖区域的等待，同时守住正确性与资源上界”。前端视觉槽固定为 **2**，不合并 hydrate/pixel，不调整档位、缓存键、SPXR v1、调度优先级、播放器大图通道或现有错误语义。前端 2↔3 属后续独立问题，不纳入本轮。

测试顺序是：静态契约复核 → 安全修正与 N=1 基线 → N=2 正确性 → 后端代理 → 真实 UI → 长期资源 → 诊断撤除后的普通 Release。任一必要闸门未通过，不进入下一阶段。

## 2. 已知证据与待反证假设

来源为 [SP-022 计划](../tasks/sp-022-playlist-scroll-performance-plan.md) 与 [基线报告 0N～0R](sp-022-playlist-performance-baseline.md)。这里只引用既有记录，尚未独立重测。

| 输入 | 可采用的结论 | 不能据此声称 |
| --- | --- | --- |
| 0N：未覆盖位置 n=91，可见至自身 load p50≈969 ms、p95≈1,645 ms | 缓存/初始化覆盖状态足以改变延迟量级，必须分层报告 | 这不是严格磁盘冷；单次历史分位数不是本轮 A 的基线或 SLA |
| 0P：并发墙钟接近最慢请求 | 请求生命周期发生重叠 | 不能证明锁内 CPU 工作并行；“加槽约 +50%”已被 0Q/0R 否定 |
| 0Q：60 首，c=2/3/4 约 30.3/28.7/29.8 首/秒 | 该构建、样本和环境中未观察到继续加前端槽的收益 | 一次曲线不是所有设备或素材的普遍吞吐上限，也不能独立证明具体锁是原因 |
| 0R：门覆盖整条阻塞管线；83 张代理的 decode 桶占约 96% | 优先复核后端准入与解码；只移动读/哈希的收益可能有限 | decode 桶未进一步拆分时不能视为纯解码器 CPU；约 1.8× 只是待验证假设 |
| 0R：取消 async future 会释放局部 guard，而阻塞闭包可能仍运行 | 必须观测闭包内真实活动量并修正 permit 所有权 | N=1 加上取消修正、单飞与预算后并非与旧版逐位等价 |

待验证因果链：多张不同键冷请求 → 全局准入串行解码 → 后端等待传播到前端两槽队列 → 首次可见补图慢。预测 B 相比 A 的不同键实际解码活动可达到 2、准入等待与批次墙钟下降，真实 UI 延迟同步下降且完成率、帧与资源不退化。

至少反证以下替代假设：差异来自缓存层级不一致；OS 文件缓存/整机负载漂移；后台 writer/淘汰扫描而非解码；hydrate/IPC 派发/React 发布仍占主导；同键重复解码制造虚假的吞吐变化。若只有代理改善而 UI 未改善，只能报告后端代理收益。

## 3. 分组与归因

| 组别 | 内容 | 用途 |
| --- | --- | --- |
| A0 原始版 | 冻结当前原始实现及源代码/构建身份 | 重建原始症状与取消越界；已知缺陷不能作为候选版通过标准 |
| A 安全基线 | 有界准入 N=1，permit 随真实工作存活，同键 single-flight、相同显式内存预算及清理机制 | 先证明安全修正，再作为并发实验基线 |
| B 候选版 | 与 A 相同，仅编译期准入 N=2 | 隔离 N=2 本身的收益和资源代价 |

A/B 的预算大小、锁边界、诊断代码、构建选项、前端文件、错误处理和写盘策略完全相同；变更只允许 N 常量。若 B 需要额外安全修正，必须同步回 A 并重新建立配对数据，不继续沿用旧 A。

分两条比较：A0↔A 量化安全机制的代价及行为差异；A↔B 量化并发参数的净变化。A0↔B 只作总效果补充，不能把所有变化归因于加并发。保留 N=1 的回退构建及 A0 身份；N=1 是安全回退，不是完整源码回滚。

每个主性能场景至少 **5 对**，预先固定顺序为 AB / BA / AB / BA / AB；A0↔A 对应交错 A0A / AA0 / A0A / AA0 / A0A。每个 arm 使用独立新测试根与 profile；热轮也由该 arm 自己预热，不能承接前一组的缓存。记录逐对差值和比例，报告中位数、范围、方向一致性；不把同一轮中的每张图当作独立实验轮。异常轮保留原始记录并注明原因，补跑完整配对，禁止只删慢轮。

## 5. 数据、缓存与环境协议

### 5.1 隔离

为每个 campaign/pair/arm 建立全新专用目录，分别承载 AppPaths 数据、封面输入副本、派生缩略图、WebView profile、日志和 build target。路径由执行前登记的绝对测试根约束；创建前确认不存在，规范化后确认全部自管写入路径位于该根内，别名/链接越界必须拒绝。应用启动前配置 fail-closed，实际落点无法确认则停止，不以“启动后再检查”补救。

只读复制获准输入或已冻结合成夹具到测试根，记录复制前后摘要；原媒体、原图缓存、用户配置和现用 profile 不作写入对象。**不复用 0Q 对用户 thumbnails 改名/清空的方法，不删除或改名用户缓存。** 不调用 picker、歌词写回等无关写操作，不停止用户现用应用；资源干扰无法控制时安排独立运行环境并记录限制。

冷轮以新目录获得空派生缓存，不需要任何递归删除。清理若另获授权，只清理已验证在专用测试根内的目录，保留原始证据。按需要复用历史 G1 的隔离经验，但历史通过不等于本轮配置已通过；也不声称 AppPaths 隔离能覆盖所有 OS/注册表写入。

### 5.2 冷热状态必须逐层标记

| 状态 | 精确定义与检查 |
| --- | --- |
| C：派生缓存冷、首次需求 | 全新进程/profile；输入副本预置；目标键在磁盘 thumbnails 与 pending writer 中均不存在；前端无对应已就绪资源；请求前无目标键初始化/预取解码。记录实际 miss/命中来源 |
| W：磁盘热、前端冷 | 在同一独立根预生成目标档位，writer 排空且验证有效文件后关闭预热进程；新进程/profile加载相同文件，目标请求实际为磁盘命中，无前端驻留 |
| R：同会话驻留重访 | 同进程同列表/布局，确认目标卡已成功就绪后离开再返回；区分资源池命中、已挂载图片和新请求 |
| U：混合或未知 | 任何前置覆盖或缓存来源不明的请求；单独统计，不能混入 C 证明冷路径收益 |

“应用重启”“新位置”“同图第二次更快”都不足以证明 C。OS 文件缓存默认**未知或温态**，不清全机文件缓存、不使用内存压力驱逐；C 只声明指定应用层冷，不称 OS 冷。初始化已覆盖的卡按 W/R/U 实际来源分类，A/B 中不能一方先覆盖、一方未覆盖。

UI 的首启自然行为和严格 C 是两个场景：自然首启保持原调度，所有 episode 入账并记录覆盖比例；严格 C 使用预先冻结的目标集合，若初始化触及任一目标键，整对该场景作无效证据并保留记录，不事后挑出较慢样本。无法在不改调度的前提下得到严格 C，则只报告自然首启分层结果，并把严格冷端到端列为缺口。

### 5.3 样本与用途

| 样本 | 用途及约束 |
| --- | --- |
| 固定 60 首（历史下标 1500–1559） | 重建 0Q 的完整 hydrate→256px 像素代理。先冻结匿名清单、输入摘要、顺序、有效封面数与唯一完整键数；历史 60 首生成 53 个文件不是通用成功分母。列表顺序变化时不能重新按当前下标抓另一批曲目 |
| 固定 83 张原图，256 档 | 后端单请求成本/阶段与历史桥接；历史 digest 为 `5b1fb04c10bb06040f3f52446d3549e0e78e6835ad3b0d80cce076966264ecd8`。现有手动 benchmark 逐次调用 blocking 路径，不能单独证明 coordinator 的 N=2 生效 |
| 合成夹具 | 同键多消费者、不同键、大图、坏图、边界和可控竞态；固定种子/字节摘要，不靠真实音乐偶然触发 |
| 真实 UI 曲库 | 冻结实际数量、匿名集合和顺序；100、1,000、现有约 1,819 首；10,000 若无获准且适用素材明确未覆盖，不复制少量同图重复记录冒充真实多样性 |

现有 83 张 harness 按媒体绝对路径哈希排序，复制到不同根可能改变选样；必须先冻结原图内容集合后在新 harness 消费同一集合，或实证 digest 一致。无法保持时建立新 A0/A/B 基线，不与历史绝对耗时作归因比较。60 首清单缺失时也应标记历史复现缺口，不能暗称同批。

记录 CPU、逻辑核、RAM/空闲 RAM、磁盘、OS、WebView2、刷新率、电源、窗口/client 尺寸、DPR、实际物理列数、布局与后台负载；不把 `data-layout-columns` 当实际列数。主要协议保持 2560×1439、DPR 1、level 0；随后覆盖其他现有布局、最大支持窗口和高 DPR。高 DPR 使用实际系统缩放并记录真实 WebView DPR，CDP 模拟只能单列为代理。历史只有一台机器，不外推硬件普遍结论。

## 6. 观测与证据规范

### 6.1 后端真实工作账本

按匿名 request/flight/worker 编号串联：请求登记、会话复检、准入等待开始/结束、内存预算等待/保留/释放、spawn 提交、**闭包真正进入/退出**、受限读取、哈希、缓存查询及命中来源、decode、方向校正/resize、打包、最终复检、写入队列接受/跳过/失败、响应终态。若细分算法阶段需要改代码，另行授权；未细分的桶用实际覆盖范围命名。

分别记录 `active_request`、`waiting_admission`、`active_blocking_worker`、`active_decode`、`reserved_bytes`、`singleflight_waiters`；准入 N 限制哪个集合必须在契约中写明，不能用 async task 的 active 冒充真实 CPU/内存活动。active 在闭包内部增减，退出 guard 覆盖正常、错误和受控 panic；取消响应不能提前把活动量减为零。准入后等待 blocking pool 的时长单列，不并入解码。

同飞输出共享方式和每 waiter 临时副本都计入预算；读入原图若发生在准入前，其并发缓冲也必须有上界。预算覆盖编码输入、解码及中间峰值、输出、共享响应持有者，writer/pending 和前端预算单列，避免漏计或重复计。R 的 0.31～0.69 GiB 是风险估算，不能把压缩文件约 2 MB 当像素峰值上界。

### 6.2 UI 与 IPC 口径

用每次跳转一次快照、只观察已挂载卡片的 IntersectionObserver、容器 capture 的 load/error，避免逐帧全量几何扫描。可见区域取列表与窗口交集并排除 dock 实际遮挡。按“同一 DOM 卡片实例 + episode + generation”关联本卡自身图片，不以共享 URL 其他卡的 load、Rust 返回或 `decode()` resolve 代替本卡终态。

同时报告 `jump→own load` 与 `visible→own load`；`load` 只代表加载完成，不声称像素已完成屏幕合成，最终显示另有 DOM/尺寸/状态抽查。终态包括：可见前已就绪、可见后自身 load、坏图/无图/受限错误、离开视口右删失、观察截止未完成。所有分母和终态闭合，禁止丢弃未完成者后只报告快速成功分位数。

页内 `invoke` 直连 **包含真实 Tauri IPC 往返**，绕过的是列表队列、BMP、React 和图片生命周期。Rust 直接调用 lib 的 83 张代理则不包含 IPC。CDP 自定义 IPC 的 POST/网络生命周期不等于 Rust handler，也不能单凭 CDP 相位归因 postMessage 派发。跨进程时钟只比较各自区间；需跨层关联时用匿名序号，不直接相减两个未校准时钟。

诊断默认关闭、纯本地、事件上限 16,384/轮、单次事件窗口不超过 5 分钟，丢失/截断计数显式输出；长跑用有界聚合和分窗证据，不无限保存逐事件。先独立交错比较诊断开/关各 5 轮的墙钟、帧、完成率和资源；扰动超出轮间波动或关键关联不完整，先改量测方案，不进入收益裁决。

### 6.3 脱敏原始格式

每轮保留唯一、不可覆盖的 manifest、事件 JSONL、资源 CSV、汇总 JSON 与命令退出码；名称用 campaign/pair/arm/regime 编号。manifest 含构建/源码摘要、采集器版本摘要、环境、协议、输入集合摘要、排序、组别、N、预算、实际目录隔离检查结果（仅通过类别，不导出真实路径）及计数。

事件白名单示例：`{"pair":1,"arm":"B","request":4,"flight":2,"episode":3,"generation":2,"t_ms":12.4,"phase":"decode_begin","cache":"miss","active_decode":2,"reserved_bytes":83886080}`。只导出会话内随机/顺序编号、相对时间、有限类别、数量与字节数；不导出曲名、路径、trackId、UUID、Object URL、原图哈希逐项映射或像素。私有输入映射留在受控本地，不进入仓库；共享证据只给集合摘要与匿名编号。

采集结束先 stop，再 dump；记录 dropped/truncated、未闭合 span、唯一关联率及每类终态。原始证据先持久化并校验摘要，分析另存，不以新轮覆盖旧轮。Test Agent 用独立计算过程从原始记录复算，而非直接接收实现者汇总。

## 7. 正确性与故障矩阵

下表均为**未来计划，未执行**。使用可控 barrier/通知固定事件顺序，不以任意 sleep 触发竞态；每种相关交错至少 5 次确定性复现，再做受控压力补充。

| 编号 | 构造与操作顺序 | 必须观察到的结果 |
| --- | --- | --- |
| C01 不同键上限 | ≥N+2 个不同键，barrier 持有首批闭包，再逐个释放 | A 真实活动≤1，B≤2；在资源允许且双请求就绪时 B 可达到2；阻塞池排队与真正解码不混算 |
| C02 同键单飞 | 相同实际内容、档位及版本，来自不同 track/client 的 ≥4 个并发请求；阻止首任务完成 | 一个完整解码/flight，响应一致且完整；仅一笔持久化或明确 AlreadyPresent；后续请求不会在 writer 落盘空隙再次解码 |
| C03 键边界 | 同内容不同路径；同路径内容改变；同图128/256/512分别请求 | 相同完整键才合并；变化后的内容与档位不得错误复用；源读取/校验不被路径去重绕过 |
| C04 等待者取消 | 同飞首发与多个 waiter；取消一个 waiter、取消首发、取消全部消费者，分别在等待准入前后 | 一个 waiter 取消不得取消其他有效 waiter；首发取消不能遗留永不完成的 flight；全取消按批准契约结束/继续有界工作，不把旧结果提交 UI |
| C05 排队取消 | 占满准入，取消队首/中间等待者，再释放准入 | 已取消任务不进入工作；permit/预算无泄漏，后续有效请求继续；队列不被墓碑永久卡住 |
| C06 执行中取消 | 闭包进入并暂停，取消外层 future，再提交新请求，最后释放闭包 | permit/预算仍随真实工作保留；即使响应已取消真实活动不超N；无提早释放、双释放 |
| C07 迟到与generation | 排队前、取得准入后、解码后分别更新 generation；旧结果先/后于新结果完成 | 保持既有复检语义；旧响应不能发布新列表/写入不允许的队列；同飞共享像素不共享每消费者会话有效性；`STALE_REQUEST` 沿既有有限恢复链最终闭合 |
| C08 FIFO 与饥饿 | 固定登记顺序的不同键争用门，同时加入取消、同键 waiter、预算不足者 | 对契约定义的准入资格集合维持 FIFO；同飞 waiter 不被误算成独立 decode 队位；无大任务/小任务永久饥饿；明确预算队列与准入队列的顺序及无死锁 |
| C09 列表/播放器隔离 | 列表饱和时切歌、播放器大图换图、另一列表 client 更新generation | 播放器独立 coordinator 未被合并；client互不 supersede；无旧图/串图；记录切歌延迟及播放连续性 |
| C10 坏图与安全边界 | 空文件、截断、无效编码、超16MiB、尺寸/像素/解码预算临界上下、非法档位/路径/链接/非普通文件 | 既有准确错误码/限制有效，不 panic、不越界读；失败释放 flight/permit/预算；后续有效请求可完成 |
| C11 持久化故障 | 在测试根注入写权限不足、写满/短写、发布/清理失败、损坏缓存、半成品、淘汰与读取竞争 | 写盘失败不计 written；已解码当前响应依既有契约成功；缓存损坏回源；原图不变；队列计数闭合且错误可见 |
| C12 writer/磁盘有界 | 测试根逼近容量/文件数阈值、暂停 writer、提交不同键和同键 | writer 128项/32MiB等已冻结双限有效，活动项计入；满载按既有规则跳过持久化而不无限等待，临时文件与磁盘淘汰可收敛 |
| C13 关闭与恢复 | 有排队、执行、同飞waiter、pending写入时关闭，再以同测试根重启 | 不接收新任务、有限退出、无悬挂waiter；半成品不命中；重启清理受限且后续有效图可恢复 |
| C14 前端相邻路径 | 快速跨越/反向停下、面板开关/卸载重开、列表替换、搜索、布局/DPR变化、连续升级失败 | 无空白永久化、旧代次回写、双重revoke、仍在使用URL误撤；有效稳定视口最终全部显示，原图回退链有效 |

历史 G2 C2 的 STALE 最终显示、G1 坏 BMP 的旧 URL 回退仍有未闭环证据，应纳入 C07/C14 补证，不能默认为已通过。0G 的受管 URL 与在途像素缺口也须补齐；历史 GPU 私有内存在12秒冷却后仍约增加80.6MiB，单个短时快照不足以证明回落，第8节的长跑与第10节资源判据分别裁决。

错误类本身是故障用例的预期输出；若出现矩阵之外的错误、计数不闭合、错误码漂移或资源越界，立即暂停当前阶段并退回 Owner。磁盘写满等系统级失败无法安全注入时用受控注入覆盖并明确真实系统条件未覆盖，不能称完整通过。

## 8. 性能实验步骤

### P0：静态契约与设施审查

核对第4节与 C01～C14 的可观测点，取得 Architecture 结论和 PM 范围批准。优先核对 permit 随闭包存活、same-key waiters 的独立取消、预算覆盖准入前读缓冲、generation 与播放器独立边界。设施不存在时先报告缺口，不以这份计划授权开发或试跑。

### P1：原始版与安全基线

在隔离合成数据上先复现 A0 的取消越界，再要求 A 通过对应反证；A0 缺陷只在隔离且可控情况下采集，不为复现而对用户实例施压。A0↔A 做5对成本比较及冷/热正确性，报告新增机制的开销。A 未通过安全与资源准入，不进入 B 性能比较。

### P2：60首完整管线与83张分段代理

60首主比较固定客户端并发 c=2，A↔B 在 C/W 下各5对，逐请求先 hydrate 再256档 pixels，记录批次墙钟、请求数/有效响应/唯一键、响应字节、每阶段和每键重复解码、writer最终排空时间。吞吐以成功有效响应/墙钟定义，同时给唯一键生成吞吐；不把共享封面的60首/53键混用分母。

补充诊断可用 c=1/2/3/4，每一 c 都独立5对并冻结顺序，保持前端实际 UI 槽数2。c>2只用于后端受控反证，不授权前端加槽；不能只跑1→2→3→4一趟后裁决。单c=1可检验机制本身开销、c=2检验目标工作负载、c>2观察瓶颈转移。

83张分段代理分别在 C/W 下5对，保留单线程 blocking 代理用于每张服务成本；验证并发上限和收益必须另走实际 coordinator 的有界并发入口。已有 benchmark 本身不会自动因 N 变化而并行。报告准入/阻塞池等待与执行、decode/resize/pack、cache lookup、writer排空，sum CPU工作与墙钟分开，避免把两路时间总和当批次耗时。

### P3：真实 Release WebView2

主场景 A↔B 每种状态各5对；按第5节隔离，启动、打开同一曲库、打开面板、固定2秒初始化后，依次跳15%/35%/55%/75%/95%，每处停6秒，末尾单列10秒终态核查。位置和时间是复现协议，不是产品 SLA；6秒未就绪不能在分位统计中消失，10秒仍未完成直接阻塞正确性。

同时测自然首启、严格 C（设施允许时）、W首次浏览、R热往返、快跨越反向停下。主表按预先分层给每轮有效图分母、已就绪率、冷/热混合比、自身load p50/p95/p99、完成曲线、右删失和错误。稳定视口与快滚分开：快滚离开导致删失不等于失败，但后续停下必须完成。

逐轮记录 rAF间隔分布、长帧计数/分钟、长任务、卡片挂载数、Rust/Renderer/GPU资源、前端队列和活动峰值。真实刷新率若320Hz，以约3.125ms为参考周期；16.7ms仅作停顿阈值，不直接称掉帧率。扩大到100/1,000/约1,819首、其他布局、最大支持窗口及高DPR时仍固定输入/窗口协议并配对；10,000素材不足单列缺口。

### P4：资源与长期稳态

短轮峰值与长跑分开。长跑提议 A/B 各5对独立会话，每arm连续60分钟、固定范围往返并包含快滚/反向/面板重开；每秒采样各进程内存、CPU、句柄及聚合计数，每5分钟归档一个有界事件窗口。完成后关闭面板空闲5分钟，再做播放器切歌与列表重开检查。

至少测常规素材、重复封面、多不同键大图及预算边界；大图压力先在合成夹具确认内存保护再进入UI。保留Rust private bytes/working set、Renderer/GPU进程占用、系统可用内存、准入/预算峰值、writer计数、受管URL数量/字节、磁盘文件/字节和未完成任务随时间序列。共享GPU进程无法可靠归属时报告总量和基线扰动；关键资源无法测量则为证据不足，不拿96MiB前端账本替代GPU占用。

## 10. 验收门槛与决策规则

### 10.1 不可放宽的正确性门槛

- 候选版闭包真实活动始终≤N，预算记账始终≤批准硬限；同键一个在途解码，其他有效waiter不被某一消费者取消；无死锁、泄漏、越界路径或generation误提交。
- 稳定视口所有有效封面最终显示；无图/坏图/受限错误单列且语义正确，10秒协议终点仍缺有效图则阻塞。逐卡自身load与最终显示证据都具备，计数闭合；无法解释的空白、错误和缺图不算性能通过。
- 原有SPXR/档位/缓存键/路径边界/播放器独立性/writer双限有效；关闭后任务、flight、permit、预算与受管URL按所有权清理。
- 必要证据未关联、丢失、事件截断或关键资源未覆盖，结论为证据不足；诊断不得用隐藏错误、任意延时、放宽超时或无限重试换通过。

### 10.2 数值提议，待 PM 与 Architecture 确认

**以下不是既有 SLA，不代表用户已批准。** 为使未来裁决可执行，建议预先确认这些值；未确认不得宣称正式验收完成。

| 维度 | 提议判据 |
| --- | --- |
| 冷代理收益 | A↔B c=2的批次墙钟配对中位数降低≥20%，至少4/5对同向，幅度大于A重复轮波动；只达到代理门槛仍不能验收UI |
| UI收益 | C或严格分层的未覆盖首次需求，逐轮p50配对中位数降低≥20%、p95降低≥15%，至少4/5对改善；p99和完成率不能出现持续退化 |
| 热态与A0→A开销 | W/R及安全修正成本单列；延迟配对中位数退化超过5%或5ms中的较大者即需解释/复审，不用冷收益抵消热回归 |
| 帧 | 相同刷新率/协议下rAF p95配对中位数恶化≤5%或1ms中的较大者；>50ms长帧计数/分钟不出现≥4/5对增加且中位增加>1次/分钟；任何新增明显冻结另列缺陷 |
| 在途硬预算 | Architecture交付数值`M_inflight`及保守算法/实测依据，测试全程reserved≤M_inflight；没有值或覆盖范围不完整则阻塞实现准入。A/B用同一M，不能为B临时增大预算制造收益 |
| 进程峰值与安全停止 | PM按设备确认Rust/Renderer/GPU各自绝对峰值限额，以及最低系统可用内存`F_min`；缺值阻塞大图压力/长跑。候选实测峰值不得超过批准限额，触及`F_min`立即停止 |
| 稳态平台 | 每个进程以第11～20分钟均值为基线，与第51～60分钟均值相比增加≤max(32MiB,10%)；最后30分钟每5分钟均值的拟合斜率≤1MiB/分钟；任一连续三窗口单调上升同时超界即暂停 |
| 回落与账本 | 面板关闭空闲5分钟后，应用拥有的活动request/flight/decode/预算归零；writer按批准退出/排空契约闭合；仅播放器仍用的URL可存活，其他受管URL引用应归零；进程总内存相对匹配A空闲基线增加≤max(32MiB,10%)。GPU不能回到启动值时必须同时满足绝对限额与稳态判据，解释allocator高水位并由PM裁定 |

约1.8×不作为最低通过值或承诺；真实收益不足、方向不稳定或低于波动时报告“未证实”。固定峰值、`F_min`和在途预算必须在执行配置表填入具体字节数、Owner、依据和确认日期，不能以“无明显增长”替代。统计判据与绝对限额应在看B结果前冻结，不根据结果反向调门槛。
