# UI 规格：播放界面

## 摘要

本规格定义 SpMusic v0.1 播放界面的信息结构、视觉方向、组件映射、交互状态和验收标准。用户提供的界面图作为视觉目标：尽量实现大封面、右侧演示歌词、底部控制条和完整图标按钮的视觉效果；功能层面仍只承诺假歌曲、UI-only 进度、演示频谱和基础播放控制。

![播放界面原型](assets/player-shell-prototype.png)

## 原型还原决策

- `SP-008` 应尽量还原原型图的布局比例、背景层次、圆角、阴影、按钮位置、字号和字重。
- 左侧封面图不要求使用真实专辑封面文件，可由前端演示图、渐变图或占位图模拟。
- 整体背景必须由当前封面视觉派生：使用封面图填充页面背景，再叠加均匀模糊层，目标模糊度为 `160px`，并覆盖半透明蒙版保证文字可读。切换当前假歌曲时，背景应跟随当前封面演示图更新。
- 窗口顶部返回 / 收起、全屏、最小化、最大化、关闭等按钮需要在前端界面内模拟展示。v0.1 可先实现视觉和可访问名称；若需要真实窗口控制，应由 Frontend Agent 与 Rust/Tauri Agent 另行确认能力边界。
- 歌曲标题和艺术家信息按原型放在右上方胶囊标签中，胶囊使用主题色浅色背景和阴影。
- 右侧歌词区使用跟随当前假歌曲切换的假歌词数据，固定展示中英双语歌词。
- 当前时刻歌词行需要高亮：字体更大、字重更高、颜色为黑色；非当前行使用弱化灰色。
- 歌词需要自动滚动视觉效果，滚动只基于 UI-only 进度和假歌词时间点，不读取真实歌词文件，不同步真实音频。
- 点赞、踩、更多、随机、循环、桌面字幕、音量、列表等按钮可以照搬原型视觉；按钮都需要 hover、focus、pressed 或 selected 等视觉反馈。
- 点赞和踩必须互斥高亮。随机和循环允许视觉选中态，并尽量在本版本影响 UI-only 切歌逻辑。
- 更多按钮点击后应向上打开叠加层；叠加层只展示演示操作，不引入真实媒体库、文件、插件或在线能力。
- 进度条允许拖动，拖动只改变 UI-only 进度。
- 播放中进度自动增长；到达当前歌曲末尾后自动切换到当前假歌曲序列的下一首。
- 上一首 / 下一首切歌后不保留播放状态，切歌完成后回到 `paused`。
- 时间格式固定为 `mm:ss`，例如 `04:31` / `06:38`。
- 窄屏时底部控制条继续横向压缩，歌词区隐藏，封面仍保持优先级。
- 封面左下点赞 / 踩按钮和右下更多按钮覆盖在封面上。
- 主播放 / 暂停按钮使用主题色圆形大按钮；其它控制按钮按照设计稿使用浅蓝线性图标风格。
- 允许为视觉效果新增前端演示字段，例如 `lyrics`、`coverArt`、`liked`、`disliked`、`shuffleVisualOn`、`repeatVisualOn`，但这些字段只属于 v0.1 前端演示状态。
- 完整播放列表管理 UI 不做；底部列表按钮完全不打开列表面板。

## 输入与约束

- `SP-003` 要求产出播放界面、可见状态、控制区和空歌曲列表状态的 UI 规格。
- `v0.1` 只支持前端内存状态，不读取本地音频文件，不触发真实播放。
- 播放状态只使用 `paused` / `playing`。随机、循环、音量、桌面字幕、点赞、更多菜单等可以作为视觉按钮出现；随机和循环可影响 UI-only 切歌策略，但不得新增真实音频行为。
- `Track` 当前字段为 `id`、`title`、`artist`、`album`、`durationSeconds`。如需呈现歌词视觉，可使用前端假歌词数据或展示常量，不代表真实歌词能力、歌词文件读取或歌词同步。
- 已接入 shadcn/ui，当前配置使用 `base-nova`、`lucide` 图标、`@/components/ui` 别名。已存在 `Button`、`Badge`、`Card`、`Empty`、`Tooltip`、`Separator` 等组件。
- 用户截图中的点赞、踩、更多菜单、随机、循环、音量、桌面字幕和歌词展示允许进入视觉实现；除基础播放、UI-only 进度、赞踩互斥、随机 / 循环 UI-only 策略和更多叠加层外，其余按钮只做视觉态、禁用态或轻量点击反馈，不接入真实能力。

## 目标

- 启动后首屏直接呈现播放界面，不出现模板页、开屏页或营销页。
- 让用户一眼识别当前歌曲、播放状态、播放进度和基础控制。
- 将现有工程验证型界面收敛为更接近桌面播放器的沉浸式布局。
- 为 Frontend Agent 提供可实现的布局、组件、状态和文案规则。
- 为 Test Agent 提供可客观检查的验收点。

## 不在范围内

- 不设计真实音频播放、真实音量调节、进度拖动同步真实音频、缓冲或音频错误恢复；可以实现与原型一致的音量等图标视觉。
- 不设计真实歌词、歌词滚动同步、歌词翻译、歌词文件读取或歌词同步；可以使用假歌词数据完成右侧歌词视觉。
- 不设计真实封面抓取、媒体库、播放列表管理、播放队列页面、HLS 或完整 `m3u8` 管理能力；本地 `.m3u8` 仅作为临时队列输入例外。
- 不设计点赞、收藏、评分、随机、循环、桌面字幕、均衡器、更多菜单、在线服务或插件入口的真实功能；可以照搬原型中的按钮作为视觉控件。
- 不新增主题导入、主题编辑器、完整国际化框架或用户自定义动效系统。

## 用户场景

- 用户打开应用后，看到一个完整播放器界面，能确认这是 SpMusic，而不是模板项目。
- 用户查看当前歌曲信息，至少能看到歌曲名、艺术家、专辑、时长中的 3 类信息。
- 用户点击播放 / 暂停，界面在 `paused` 与 `playing` 之间切换。
- 用户点击上一首 / 下一首，当前歌曲基于假歌曲数据切换，进度回到 `0`。
- 用户在空歌曲列表分支中看到稳定 Empty State，控制按钮不可用且界面不崩溃。

| 应用容器 | 承载首屏播放界面 | 背景、主内容、底部控制条 | 无直接交互 | 首屏不显示模板内容 |
| 动态背景层 | 还原原型的柔和氛围 | 当前封面填充背景、`160px` 模糊、半透明蒙版 | 随当前假歌曲切换 | 背景随当前歌曲视觉变化，文字仍可读 |
| 模拟窗口控制区 | 补足 Tauri 原生按钮不确定性 | 返回 / 收起、全屏、最小化、最大化、关闭图标 | v0.1 可先做视觉反馈 | 顶部存在模拟窗口按钮且不遮挡内容 |
| 当前歌曲视觉区 | 建立播放器主视觉 | 演示封面或抽象封面、产品标识、当前状态 | 不提供封面编辑或抓取入口 | 有稳定视觉区域，缺少封面数据时不空白 |
| 当前歌曲信息区 | 展示当前曲目信息 | 歌曲名、艺术家、专辑、时长、播放状态 Badge | 状态随当前歌曲和播放状态变化 | 展示至少 3 类当前歌曲信息 |
| 演示歌词区 | 还原截图中的歌词视觉 | 假歌词、当前高亮行、中文翻译演示文本 | 不读取文件、不同步真实音频，可随假数据切歌更新 | 不出现“已支持真实歌词”的文案 |
| 演示频谱区 | 表达 UI-only 音频视觉化 | 固定演示频谱条或等价动效 | `playing` 时可增强动效，`paused` 时静止或弱化 | 不依赖真实音频分析 |
| 底部控制条 | 提供播放器视觉和基础播放控制 | 进度、已播 / 总时长、随机、上一首、播放 / 暂停、下一首、循环、桌面字幕、音量、列表等图标 | 基础控制可切换 UI 状态；扩展按钮只做视觉反馈或禁用 | 原型中的按钮可见，但不产生未批准业务能力 |
| Empty State | 处理空歌曲列表 | 空状态标题、说明、禁用控制 | 不提供导入文件按钮 | 空列表分支可渲染且不崩溃 |

## 视觉层级与布局

- 桌面宽屏（大于等于 `1180px`）：主内容使用左右两列。左侧为大封面视觉区，右侧为当前歌曲信息、演示歌词和演示频谱；底部控制条固定在内容下方，不覆盖主内容。
- 普通桌面窗口（`820px` 到 `1179px`）：封面和信息区仍保持左右布局，但压缩横向间距；控制条保持单行，时间文本和进度条优先保留。
- 窄屏窗口（小于 `820px`）：主内容改为单列，封面在上，歌曲信息和演示歌词在下，控制条允许换行但按钮组居中。
- 最小可用宽度为 `320px`。长歌曲名、专辑名和艺术家名必须换行或截断，不得挤出容器。
- 视觉优先级为：当前歌曲名 > 播放 / 暂停按钮 > 进度 > 艺术家 / 专辑 / 时长 > 演示频谱 > 状态说明。
- 封面视觉区可以使用渐变、图标和产品标识作为演示封面，但不得展示文件路径、真实封面抓取状态或在线图片加载状态。
- 底部控制条采用浅色面板，边框和阴影应克制。普通卡片圆角不超过 `8px`；圆形图标按钮和进度滑块手柄可使用胶囊圆角。
- 配色建议：中性浅背景、白色或近白控制面、青绿色主强调色、蓝色播放状态强调、暖色暂停提示。避免整页只由单一青绿色或蓝色构成。
- 字号建议：歌曲名 `32px` 到 `42px`，区域标题 `16px` 到 `20px`，正文和状态文本 `14px` 到 `16px`，按钮可访问名称不依赖可见文字。

| 上一首 / 下一首 | `Button` `size="icon"` 或等价尺寸 | 可用 / 禁用 | `appCopy.controls` | 使用 lucide `SkipBack` / `SkipForward` |
| 播放 / 暂停 | `Button` | `paused` / `playing` / 禁用 | `appCopy.controls` | 使用 `aria-pressed` 表达切换状态 |
| 随机 / 循环 / 桌面字幕 / 音量 / 列表 / 更多 | `Button` + `Tooltip` | 视觉态 / 选中态 / 禁用态 / 轻量反馈 | `appCopy.controls` | 随机和循环可影响 UI-only 切歌策略；桌面字幕是系统级字幕开关语义，未接系统 API 时显示为不可用 |
| 封面反馈按钮 | `Button` + `Tooltip` | 视觉态 / 禁用态 / 轻量反馈 | `appCopy.controls` | 点赞、踩、更多可作为视觉控件，不写入数据 |
| 进度条 | 原生 `input[type=range]` 或现有样式轨道 | 可用 / 禁用 | `appCopy.progress` | v0.1 表达 UI-only 进度；若改用 shadcn `Slider` 需 Frontend Agent 判断是否新增组件 |
| 演示歌词 | 原生 `section` + 文本列表 | 普通行 / 当前行 | 假歌词数据或 `appCopy.demoLyrics` | 不读取歌词文件，不同步真实音频 |
| 更多叠加层 | `Popover` / `DropdownMenu` / 自定义浮层 | 关闭 / 打开 | `appCopy.moreMenu` | 从更多按钮向上展开，只放演示操作 |
| 演示频谱 | 原生 `div` + CSS token | `paused` / `playing` / 空频谱 | `appCopy.spectrum` | 不映射真实音频分析 |
| 空状态 | `Empty` 或现有空状态结构 | 空歌曲 / 空频谱 | `appCopy.nowPlaying`、`appCopy.queue` | 不出现“导入音乐”按钮 |
| 提示说明 | `Tooltip` | 控件悬停 / 聚焦 | `appCopy.controls` | 图标按钮应有可访问名称 |

## 前端演示数据建议

v0.1 可以在前端实现层新增仅用于视觉还原的演示字段。字段应放在 demo fixture 或 UI 状态中，不得伪装成真实媒体库、真实歌词或真实封面来源。

```ts
type DemoLyricLine = {
  id: string
  timeSeconds: number
  original: string
  translation: string
}

type PlayerVisualState = {
  likedTrackId: string | null
  dislikedTrackId: string | null
  shuffleVisualOn: boolean
  repeatVisualOn: boolean
  moreOverlayOpen: boolean
}

type DemoTrackVisual = {
  trackId: string
  coverSeed: string
  lyrics: DemoLyricLine[]
}
```

- `coverSeed` 可用于生成封面占位图、背景渐变或演示图路径；不得表示真实文件路径。
- `lyrics` 仅用于右侧演示歌词视觉；不得表示真实歌词文件、网络歌词或已同步歌词能力。
- `likedTrackId` 与 `dislikedTrackId` 必须互斥。
- `shuffleVisualOn` 与 `repeatVisualOn` 可以影响 UI-only 切歌策略，不影响真实音频。
- `moreOverlayOpen` 只控制演示叠加层显示。

## 交互状态矩阵

| 状态 | 触发条件 | 可见反馈 | 可操作项 | 禁用项 | 验收方式 |
| --- | --- | --- | --- | --- | --- |
| `paused` | 初始状态或用户点击暂停 | 播放按钮显示播放图标，状态 Badge 显示“已暂停” | 播放、上一首、下一首 | 无，除非歌曲列表为空 | 点击播放后切到 `playing` |
| `playing` | 有当前歌曲时点击播放 | 播放按钮显示暂停图标，状态 Badge 显示“播放中”，频谱可增强 | 暂停、上一首、下一首 | 无 | 点击暂停后切到 `paused` |
| `trackChanged` | 点击上一首或下一首 | 当前歌曲信息变化，进度归零 | 播放 / 暂停、上一首、下一首 | 无 | 当前歌曲 ID 基于假数据切换 |
| `trackChangedByControl` | 用户点击上一首 / 下一首 | 当前歌曲、封面背景、胶囊标签、演示歌词一起变化，播放状态回到 `paused` | 播放 / 暂停、上一首、下一首 | 无 | 切歌后不保持 `playing` |
| `progressCapped` | UI-only 进度达到或超过时长 | 进度显示在总时长上限内 | 播放 / 暂停、上一首、下一首 | 进度不得超过最大值 | 进度文本不超过总时长 |
| `progressDragged` | 用户拖动进度条 | 已播放时间、进度手柄和当前歌词高亮随拖动位置更新 | 进度条、播放控制 | 空歌曲或时长为 0 时禁用 | 拖动不触发真实音频 |
| `autoAdvance` | `playing` 且 UI-only 进度到达当前歌曲总时长 | 自动切换到当前假歌曲序列下一首，进度归零 | 播放 / 暂停、上一首、下一首 | 无 | 到末尾后当前歌曲 ID 变化 |
| `lyricsScrolled` | UI-only 进度跨过假歌词时间点 | 演示歌词自动滚动，当前行变大、变黑、加粗 | 播放控制、进度条 | 空歌词时歌词区隐藏或显示后备 | 当前高亮行与 UI-only 进度一致 |
| `likeSelected` | 点击赞按钮 | 赞按钮高亮，踩按钮取消高亮 | 赞、踩 | 空歌曲时可禁用 | 赞/踩互斥 |
| `dislikeSelected` | 点击踩按钮 | 踩按钮高亮，赞按钮取消高亮 | 赞、踩 | 空歌曲时可禁用 | 赞/踩互斥 |
| `shuffleVisualOn` | 点击随机按钮 | 随机按钮进入选中态；下一首尽量按非当前歌曲选择 | 随机、上一首、下一首 | 空歌曲或单曲时可禁用或保持视觉态 | 连续点击可切换选中态 |
| `repeatVisualOn` | 点击循环按钮 | 循环按钮进入选中态；歌曲结束时优先循环当前歌曲 | 循环、播放 / 暂停 | 空歌曲时可禁用 | 连续点击可切换选中态 |
| `moreOverlayOpen` | 点击更多按钮 | 更多叠加层从按钮上方向上展开 | 更多按钮、叠加层内演示项 | 空歌曲时可禁用 | 叠加层不包含导入、扫描、插件等入口 |
| `listButtonPressed` | 点击底部列表按钮 | 仅按钮视觉反馈，不打开列表面板 | 列表按钮 | 可保持启用视觉态 | 不出现完整播放列表管理 UI |
| `emptyTracks` | `tracks.length === 0` | 显示 Empty State，状态保持暂停 | 无主要播放操作 | 播放、上一首、下一首、进度 | 空列表不崩溃，不渲染 undefined |
| `singleTrack` | `tracks.length === 1` | 上一首 / 下一首后仍为同一首 | 播放 / 暂停、上一首、下一首 | 无 | 连续切歌当前 ID 仍有效 |
| `invalidCurrentTrack` | `currentTrackId` 不存在于 `tracks` | 回退到第一首或 Empty State | 同正常状态 | 取决于是否有歌曲 | 不渲染 undefined 字段 |
| `emptySpectrum` | `spectrumBars.length === 0` | 频谱区显示后备说明或静态占位 | 播放控制仍可用 | 无 | 频谱区域不导致布局坍塌 |

## 详细交互规则

- 手动上一首 / 下一首：基于当前假歌曲序列切换歌曲，切换后 `progressSeconds` 归零，`playbackStatus` 回到 `paused`，封面背景、胶囊标题、演示歌词和频谱状态同步刷新。
- 自动下一首：当 `playbackStatus === 'playing'` 且 UI-only 进度到达当前歌曲时长时，自动切换到下一首，`progressSeconds` 归零；自动切歌可继续保持 `playing`，形成播放中的连续视觉效果。
- 普通下一首：未开启随机或循环时，下一首从当前索引向后取一首，末尾循环到第一首。
- 普通上一首：从当前索引向前取一首，开头循环到最后一首。
- 随机选中态：点击随机按钮切换 `shuffleVisualOn`。开启后，下一首优先从当前假歌曲以外的歌曲中选择；单曲列表下不改变当前歌曲。
- 循环选中态：点击循环按钮切换 `repeatVisualOn`。开启后，自动播放到末尾时优先回到当前歌曲开头；手动上一首 / 下一首仍执行切歌。
- 随机与循环同时开启时，循环优先作用于自动播放末尾，随机优先作用于用户点击下一首。
- 进度拖动：用户拖动进度条时立即更新 UI-only 已播放时间、进度手柄位置和演示歌词高亮行；拖动不改变真实音频，因为 v0.1 没有真实音频。
- 演示歌词：每首假歌曲可配置独立 `lyrics` 数组，每行包含英文、中文和 UI-only 时间点。播放或拖动进度时，根据最近且不大于当前进度的时间点确定当前行。
- 歌词滚动：当前行始终尽量保持在歌词区中部；切歌后歌词回到该歌曲第一行或当前进度对应行。
- 点赞 / 踩：两个按钮互斥。点击赞后赞高亮、踩取消；点击踩后踩高亮、赞取消；再次点击当前高亮按钮可取消高亮。
- 更多按钮：点击后从封面右下角按钮上方向上展开叠加层。叠加层只能展示演示项，例如“演示信息”“复制歌曲名”，不得出现导入、扫描、真实菜单管理或插件入口。
- 桌面字幕、音量、列表按钮：需要 Tooltip 和视觉反馈。桌面字幕按钮表示未来电脑系统级字幕显示开关，不控制右侧歌词译文；v0.1 未接入系统 API 时按钮保持禁用，Tooltip / 可访问名称使用 `桌面字幕暂未接入`，不改变真实系统状态；列表按钮点击后不打开面板。
- 模拟窗口按钮：顶部按钮需要 hover、focus 和 pressed 视觉状态。v0.1 如果无法接入真实窗口控制，可仅实现视觉反馈，并用 Tooltip 标明按钮名称。
- 窄屏响应：歌词区隐藏时，播放控制、封面和胶囊歌曲信息仍可见；底部控制条横向压缩，不改为垂直堆叠。

## 空、加载、错误和禁用状态

- 空歌曲列表：显示标题“暂无演示歌曲”和说明“当前没有可用于界面验证的歌曲数据”。不得显示“选择文件”“导入音乐”“扫描文件夹”等未批准入口。
- 当前歌曲缺失：如果歌曲列表非空，界面回退到第一首；如果歌曲列表为空，显示 Empty State。
- 空歌词数据：歌词区显示稳定后备文案或隐藏，不得显示“歌词加载失败”这类真实歌词错误。
- 空频谱：显示静态后备区域或“暂无演示频谱”，不得显示真实音频错误。
- 加载状态：v0.1 不设计伪加载状态，因为数据来自本地固定假数据。
- 错误状态：v0.1 不设计真实音频或文件读取错误；异常数据只通过 Empty State 或安全回退处理。
- 禁用状态：歌曲列表为空时禁用播放 / 暂停、上一首、下一首和进度条；禁用控件保持可见但有 `disabled` 和可感知的视觉弱化。
- 完整列表管理：底部列表按钮不打开面板；点击后最多显示 pressed 视觉反馈或 Tooltip。
- 更多叠加层：空歌曲时可禁用更多按钮；有歌曲时叠加层只显示演示项。

## 可访问性要求

- 页面使用一个 `main`，并用可见标题或 `aria-labelledby` 标识。
- 当前歌曲信息变化区域使用 `aria-live="polite"`，避免频繁打断读屏。
- 播放 / 暂停按钮使用 `aria-pressed`；图标按钮必须提供 `aria-label`。
- 模拟窗口按钮、封面赞踩按钮、更多按钮、随机、循环、桌面字幕、音量和列表按钮都必须有可访问名称和 Tooltip。
- 焦点顺序为：当前歌曲区域、进度条、上一首、播放 / 暂停、下一首、频谱或状态区。若存在演示歌曲列表，列表项在控制区之后。
- 键盘用户可通过 `Tab` 到达所有可操作控件，并通过 `Enter` 或 `Space` 触发按钮。
- 可点击目标最小尺寸为 `44px`。底部控制条在窄屏下不得让按钮相互重叠。
- 文本对比度：正文至少满足 4.5:1，大号歌曲名至少满足 3:1；禁用态也要能辨认。
- `prefers-reduced-motion: reduce` 下，频谱动效应静止或移除过渡。
- `prefers-reduced-motion: reduce` 下，歌词自动滚动应切换为无动画定位或仅更新高亮行。

## 文案

- 产品身份：`SpMusic`。
- 页面标题：`SpMusic 播放界面`。
- 当前歌曲区标签：`正在播放`。
- 播放状态：`已暂停`、`播放中`。业务状态仍使用 `paused` / `playing`。
- 控制按钮可访问名称：`上一首`、`播放`、`暂停`、`下一首`。
- 进度标签：`播放进度`、`已播放`、`总时长`。

- 演示歌词区可见标签建议为`歌词`，但说明和代码命名应使用`演示歌词`或`demoLyrics`，避免暗示真实歌词能力。
- 模拟窗口按钮可访问名称：`返回`、`收起`、`全屏`、`最小化`、`最大化`、`关闭`。

- 空歌曲标题：`暂无演示歌曲`；说明为`当前没有可用于界面验证的歌曲数据。`
- 文案应集中在 `copy`、`texts` 或 `messages` 对象中，v0.1 不要求完整 i18n 框架。
- 可使用“歌词”“音量”“随机”“循环”等短标签作为图标可访问名称，但必须避免“已支持真实歌词”“正在调节系统音量”“已收藏”等会暗示真实功能完成的结果文案。

## 风险与开放问题

- 用户确认 v0.1 未批准能力可以不完全支持，但视觉效果要尽量实现；实现时必须区分“视觉按钮”和“真实功能”。
- Frontend Agent 可以照搬截图中的所有按钮，但除基础播放控制外，按钮不得写入未批准业务状态、请求权限或接入真实音频能力。
- 右侧区域可以命名为演示歌词区，并使用假歌词数据；文案和代码注释必须避免暗示已支持真实歌词文件、真实歌词同步或歌词翻译能力。底部 `CC` / 桌面字幕按钮不得复用为歌词译文显示开关。
- 完整列表管理 UI 先不做；底部列表图标可作为视觉按钮，不能打开真实播放列表管理界面。
- 如果需要把进度条替换为 shadcn `Slider` 或 `Progress`，应由 Frontend Agent 判断是否新增组件，并保持不引入真实音频进度语义。
